## Application data model: one data shape needs one mechanism, not one mechanism for all data — hash-identified operation-based CRDTs for editable state, single-writer signed logs for feeds, content-addressed immutable objects for media, and Operational Transformation excluded entirely

The application data model states how a person's edit to a shared object, a person's append to their own feed, and a person's upload of a photo or video each reach every other replica and converge to one agreed value, without any replica waiting for a server or a quorum vote before accepting the local edit. Three shapes of data appear in every candidate application (a post being corrected is editable state with more than one possible writer over time; a user's timeline is a feed only that user ever appends to; an uploaded photo is written once and never edited again), and the corpus's evidence separates cleanly along exactly that boundary: no single mechanism among the four candidates handles all three shapes at its measured or proven cost, and each of the three shapes has one candidate whose requirements match it and two whose requirements do not.

### Selection

Three mechanisms compose, one per data shape, and Operational Transformation is excluded in every topology this design permits. Editable, potentially multi-writer state (a post's text, a profile field, a folder tree) is represented as a hash-identified, Byzantine-tolerant operation-based CRDT, following the construction of `KLEPPMANN-ARXIV-20` and `KLEPPMANN-PAPOC-22`. A feed — any sequence only one identity ever appends to (a user's post history, an activity stream) — is represented as a signed append-only log, following `KERMARREC-DICG-20`'s Secure Scuttlebutt (SSB) model. Immutable media (an uploaded photo, video, or document, never edited after upload) is represented as a content-addressed immutable object in a Merkle DAG, following `BENET-ARXIV-14`'s IPFS model. These three are not substitutes for each other and the composition between them is mechanical, not architectural: the mutable "name" that lets a stable identifier resolve to the current head of a CRDT's operation DAG, or to the newest object in an evolving media collection, is itself one signed log entry per publish — the same primitive selected for feeds, reused as the pointer mechanism between the other two.

Against plain state-based CRDTs for editable state (rejecting them as the general case, while retaining Merkle Search Trees as a conditional secondary choice, addressed below): state-based and operation-based CRDTs are proved equally expressive — either can emulate the other [`SHAPIRO-SSS-11`, Theorems 3–4] — so the choice is a transport-cost tradeoff, not an expressiveness one. Operation-based transmission carries only the delta an edit produced, not the whole object; for the tree-move instance this is measured directly against a leader-based alternative on identical hardware, giving up to 100,000× lower write latency for a geographically remote replica in exchange for 4×–23× lower peak throughput than the leader [`KLEPPMANN-TPDS-22`] — a bound the state-based style's own founding papers report no comparable measurement for [`SHAPIRO-SSS-11`, `SHAPIRO-EATCS-11`]. Merkle Search Trees, the corpus's one measured state-based instance at scale, only wins on bandwidth and dissemination at light update rates (0.1 events/round); at 1 event/round it loses to plain vector-clock gossip on entropy and delivery delay, and a related hash-prefix variant fails to terminate outright at 2000 nodes [`AUVOLAT-SRDS-19`] — so state-based propagation is selected only for large, low-mutation-rate collections (an index over an already-settled dataset), not for the general editable-object case.

Against Operational Transformation: OT is excluded from the general (peer-to-peer, no permanent relay) case because its only simplification to one provable condition, TP1, is available exclusively under a single central server relaying every transformed operation [`SUN-CSCW-98`] — a permanent centralized relay is precisely the capture point this architecture is built to avoid (§1 of the brief). Outside that topology, OT requires both TP1 and TP2 proved for every operator pair in the application's data model, and the founding survey states plainly that "no method exists to verify" this and that "some seemingly correct transformation functions do not" satisfy it [`SUN-CSCW-98`] — a per-data-type correctness burden with no general proof technique, where the selected CRDT construction's corresponding burden (proving operations commute, or proving a merge is an inflation) has already been discharged once for the counter, last-writer-wins register, multi-value register, and observed-remove set, each with an implementation proved to match its own worst-case metadata-overhead lower bound [`BURCKHARDT-POPL-14`], for maps, sets, registers, and nested JSON documents generally [`KLEPPMANN-TPDS-17`], for ordered lists and text via RGA [`ATTIYA-PODC-16`, proved to satisfy the strong list specification], and for hierarchical trees via the move operation [`KLEPPMANN-TPDS-22`, mechanically checked in Isabelle/HOL with no unproved assumption]. The metadata-cost argument sometimes made for OT over CRDTs does not survive the corpus's own lower bound: `ATTIYA-PODC-16` proves any protocol in the "push-based" class — which the paper states explicitly includes deployed eventually-consistent write-propagating protocols generally, OT included — carries Ω(D) metadata overhead in the number of deletions, the identical floor RGA's proved O(D log k) nearly meets. OT supplies no advantage CRDTs lack and adds an unresolved, per-data-type proof obligation CRDTs do not.

Against plain (non-Byzantine) operation-based CRDTs, for the specific choice of identifier scheme: sequence-number or vector-clock identifiers let one faulty replica equivocate — emit two distinct updates carrying the identical declared identifier to two different correct replicas — which is demonstrated concretely (Figure 1) to defeat version-vector-based reconciliation [`KLEPPMANN-PAPOC-22`]. Deriving each operation's identifier from its own content hash removes this failure because a faulty replica cannot alter the identifier without changing the hash, at a measured cost — 96.7% one-round-trip reconciliation, ~1 kB overhead — that the plain vector-clock construction's own founding papers report no comparable figure for [`KLEPPMANN-ARXIV-20`; `SHAPIRO-SSS-11`, `SHAPIRO-EATCS-11`]. The one recorded cost of this substitution is storage: hash-based identifiers are larger than short sequence numbers, a cost the paper states can be reduced by recomputing hashes on demand rather than storing them all, without measuring that reduction [`KLEPPMANN-PAPOC-22`].

Against using a signed append-only log as the mechanism for editable multi-writer state directly (rather than only for feeds): a log by itself supplies no merge operation — SSB's reconciliation resolves exactly which entries one store is missing from another, not what a shared mutable field's value should become when two owners have each proposed a different one [`KERMARREC-DICG-20`]. Using a signed log to carry a CRDT's own operations is not a competing choice at all; it is the operation-based CRDT's own transport requirement (reliable, hash-linked delivery of signed operations) under another name, so the two candidates are complementary rather than substitutable for this shape of data.

Against using content-addressed immutable objects for editable state directly: every "edit" under this mechanism is an entirely new object under a new hash, since objects are immutable by construction, and the mechanism supplies no algorithm at all for reconciling two concurrently-proposed new roots for the same logical document [`BENET-ARXIV-14`] — precisely the missing piece a CRDT's proved commutativity or inflation property supplies. Its own mutable-pointer layer (IPNS) is constructed as a signed record published to a routing table, the identical single-writer signed-pointer pattern selected for feeds [`BENET-ARXIV-14`], not a distinct mechanism.

Against using signed logs or content-addressed objects for each other's shape: media benefits specifically from content addressing's automatic cross-user deduplication — two participants uploading byte-identical media collapse to one stored object under this scheme, a property no per-writer signed log gives, since every entry in an SSB-style log is scoped to one owner's key regardless of content [`BENET-ARXIV-14` vs. `KERMARREC-DICG-20`]. Conversely, a feed gains nothing from content-addressed immutability specifically, because a feed's ordering and single-writer-authorship guarantees are exactly what a hash-chained signed log already supplies at lower mechanism cost — a plain per-entry hash link plus one signature check, not a whole Merkle-DAG object model with a separately layered naming scheme [`KERMARREC-DICG-20` vs. `BENET-ARXIV-14`].

### Byzantine tolerance

Classical Byzantine fault-tolerant (BFT) state machine replication bounds the fraction of faulty replicas a protocol tolerates — typically requiring 3f+1 replicas to tolerate f faulty ones, reducible to 2f+1 under synchrony and digital signatures [figures cited in `KLEPPMANN-ARXIV-20` from the prior literature it surveys]. That bound presupposes a fixed, known replica count an adversary cannot inflate. An open peer-to-peer network with no admission authority cannot supply that precondition: `DOUCEUR-IPTPS-02` proves that without a logically centralized identity issuer, a single faulty participant commanding resources ρ times a minimally-capable participant's resources presents ρ distinct identities to any validator demanding proof of resources, and, absent synchronized validation rounds, presents an unbounded number of identities regardless of resource ratio (Lemma 2) — so a bounded-adversary-fraction assumption has no basis to hold, and `KLEPPMANN-PAPOC-22` cites exactly this result as its own stated reason for rejecting quorum-based BFT protocols for this setting.

The selected hash-identified CRDT construction removes the bounded-fraction requirement rather than tightening it: `KLEPPMANN-ARXIV-20`'s central theorem states a fault-tolerant Byzantine Eventually Consistent (BEC) algorithm exists for a set of operations if and only if those operations are invariant-confluent (I-confluent) — concurrent executions, each individually preserving an invariant, still preserve it when merged in either order — a condition that holds independent of how many replicas are faulty. Every commuting-operation or inflation-based CRDT selected above for editable state is, by the corresponding SEC (Strong Eventual Consistency) proof, exactly this kind of I-confluent construction [`SHAPIRO-SSS-11`], so the Byzantine variant tolerates an unbounded fraction of faulty replicas for the same operations the non-Byzantine variant already handles, measured at 96.7% one-round-trip reconciliation cost in the 4-replica prototype [`KLEPPMANN-ARXIV-20`]. The limit is exact, not approximate: the same theorem proves no fault-tolerant BEC algorithm exists for an invariant that is not I-confluent under arbitrary Byzantine faults, demonstrated concretely on a cryptocurrency balance, where two concurrent debits from one account can jointly violate a non-negative-balance invariant even though each alone would not [`KLEPPMANN-ARXIV-20`] — so any operation this design needs to enforce a cross-replica invariant outside pure commuting/inflating updates (a global uniqueness constraint on a handle, an exactly-once counter) needs a separate, explicitly bounded-adversary consensus sub-mechanism for that specific operation, which this selection does not supply and no entry in this corpus's Domain D measures for an unbounded-Byzantine setting.

For feeds and media, Byzantine tolerance is a structural consequence of the mechanism rather than a separately proved property. A signed log's single-writer-per-key construction means a faulty writer can corrupt only its own log, never another's, and other participants simply choose whether to continue following it [`KERMARREC-DICG-20`]; a content-addressed object is self-verifying by its own hash, so a faulty peer serving the wrong bytes is detected on receipt, not merely outvoted by a quorum [`BENET-ARXIV-14`]. Neither of these properties is separately measured in the corpus; both follow directly from the stated construction.

### Secondary indexes and range queries over content-addressed data

No entry in this corpus measures a secondary index (for example, "every post by principal X" or "every entry with tag Y") or a range query built directly over a CRDT-object store or a content-addressed immutable-object store at multi-writer, adversarial, internet scale. What exists is three unconnected pieces.

First, content-addressed ordered trees that support range access with a real measured cost: prolly trees, a content-addressed key-value structure supporting both Merkle verification and B-tree-style ordered range access, measure 24%–45% faster tree creation and roughly 3× faster large-scale insertion than two real deployed prolly-tree implementations (Dolthub, Canvas/okra), at 10,000,000–17,000,000 entries, on one benchmarked machine [`RAWAT-DLT-24`]. Second, range-based set reconciliation protocols that assume a range-queryable local index already exists and reconcile over ranges of it, rather than building that index: Willow's three-dimensional reconciliation splits a mismatched range recursively until fingerprints agree, in a logarithmic number of rounds by construction, but reports no measured round count, message count, or bandwidth figure on any concrete topology, and states outright that the requisite local index over (subspace, path, timestamp) triples supporting efficient range splitting by entry count is a precondition the specification assumes, not one it supplies [`WILLOW-SPEC-23`]. A concrete backend for exactly this kind of reconciliation is measured: an aggregate-augmented B+-tree realization is 4.69×–13.98× faster to reconcile than a naive auxiliary-tree baseline across six synthetic workload families, on one machine, single-threaded, with concurrent-transaction and crash-recovery behavior explicitly out of scope [`AMPARORE-ARXIV-26`]. Third, the correctness property both range-reconciliation approaches require of their backing structure — that clamping an arbitrary subrange of two structurally different, same-content trees always yields an identical clamped subtree ("clamping-invariant") — is proved in this corpus only for treaps and is proved to fail for prolly trees specifically: "Prolly-trees are not clamping-invariant," because chunk boundaries are set by a rolling hash over a window of consecutive items, and clamping changes which items fall inside that window [`MEYER-TR-24`]. Merkle Search Trees are listed among the structures the same paper asserts, but does not prove, are clamping-invariant [`MEYER-TR-24`], and Merkle Search Trees' own founding paper independently states that using them as a secondary index over data distributed via a distributed hash table is proposed but explicitly unevaluated: "the feasibility of such an approach when many updates occur at many nodes has not yet been evaluated" [`AUVOLAT-SRDS-19`].

The corpus therefore records this incompatibility, not merely an absence of measurement: the one content-addressed range-supporting structure with real deployed-scale performance numbers (prolly trees) is proved unusable, as-is, with the one reconciliation protocol built specifically for three-dimensional range queries over content-addressed entries (Willow/RBSR), because the former is proved not to have the property the latter's own correctness proof requires [`MEYER-TR-24` vs. `RAWAT-DLT-24`]. Building a secondary index over the CRDT and content-addressed stores selected above therefore needs one of: a clamping-invariant backing structure (a treap, proved; or one of the other twelve structures `MEYER-TR-24` lists but does not prove) accepting whatever performance cost that substitution carries relative to prolly trees' measured numbers, an adaptation of prolly-tree chunking that restores clamping-invariance, or an index built and reconciled by a mechanism outside the range-based family entirely — none of which is proved, measured, or ruled out by any entry in this corpus. This is also where a further, uncosted consequence attaches, belonging to the privacy-tiers component rather than to this selection: once a range query returns which stored entries matched, that return channel alone — independent of any encryption on the matched content — is sufficient for a statistical-learning attack to reconstruct the approximate order and value of the underlying records, demonstrated at 500 range queries recovering record order to within 2% of a 10^6-value domain, and separately at 100 range queries predicting a majority of a real 248,000-record salary dataset to within 10,000 currency units [`GRUBBS-SP-19`]. Any secondary index built on the structures above needs the privacy-tiers component to account for this leakage explicitly; this selection does not resolve it.

### What this selection requires from the rest of the system

- The transport component supplies, for the hash-identified CRDT construction, pairwise reconciliation of head-hash sets between any two replicas, and durable per-remote-peer storage of the head set from the last successful reconciliation [`KLEPPMANN-ARXIV-20`]; it need not supply causal-broadcast ordering, since the DAG's own predecessor hashes carry causal order.
- The identity component supplies, per replica, a distinct signing key pair, with every other replica's public key discoverable, since the Byzantine-tolerant construction discards any message with an invalid signature [`KLEPPMANN-ARXIV-20`]; per feed writer, one persistent signing key whose corresponding public key serves as the log's identifier [`KERMARREC-DICG-20`].
- The network/overlay component keeps correct replicas connected as one component in the network graph; the selected Byzantine-tolerant construction's own guarantee is void for any pair of correct replicas an adversary can fully separate, and the source paper states ensuring this "an open question" it does not resolve [`KLEPPMANN-ARXIV-20`].
- Whichever component enforces cross-replica invariants outside plain commuting or inflating operations (uniqueness, exact counts) supplies a separately bounded-adversary consensus mechanism for exactly those operations; the selected construction proves it cannot supply this for non-I-confluent invariants under unbounded Byzantine faults [`KLEPPMANN-ARXIV-20`].
- The storage/retention component supplies an explicit pinning or retention decision for every content-addressed media object; the selected mechanism supplies no default persistence policy of its own, and an unpinned object surviving only in transient caches has no durability guarantee [`BENET-ARXIV-14`].
- The content-location/routing component keeps answering, for both content-addressed objects and the mutable name pointing at the current CRDT-DAG head or feed frontier, which peers currently hold and will serve the requested hash; both the object-retrieval path and the name-resolution path degrade together with routing, even though the underlying immutable objects remain independently held [`BENET-ARXIV-14`].
- Every CRDT type this design introduces beyond the four the corpus has verified generally (maps/sets/registers/JSON documents, ordered lists/text, hierarchical trees, plus the graph type sketched but not resolved [`SHAPIRO-SSS-11`]) needs its own commutativity or inflation proof before deployment; the hash-identified construction's `before(u)`-restricted validity rule is conjectured, not proved, to extend to arbitrary CRDT validity conditions beyond bare identifier uniqueness [`KLEPPMANN-PAPOC-22`].

### What it costs and where it fails

The hash-identified Byzantine-tolerant CRDT construction costs 96.7% one-round-trip reconciliation and ~1 kB network overhead per reconciliation in a 4-replica, single-process, in-memory prototype with no actually-faulty replicas present [`KLEPPMANN-ARXIV-20`] — CPU and memory use were not measured, and the paper's own statement that behavior would not fundamentally change with faulty replicas present is an unmeasured belief the paper itself flags as such, not a reported result [`KLEPPMANN-ARXIV-20`]. It fails outright — no fault-tolerant algorithm exists, proved, not merely unmeasured — for any invariant that is not invariant-confluent under arbitrary Byzantine faults [`KLEPPMANN-ARXIV-20`]. It fails to make progress between two correct replicas an adversary has fully separated on the network graph [`KLEPPMANN-ARXIV-20`]. Storage grows without bound: every node retains the complete update DAG, and no garbage-collection mechanism compatible with an unbounded, unknown effective replica set is proved or measured anywhere in this corpus's Domain D — the one stability-based GC scheme this corpus records requires a known, bounded replica set with no undetected permanent crash [`SHAPIRO-EATCS-11`], a precondition the selected construction's whole point is to avoid needing.

For feeds, the signed-log mechanism's central limitation is scale under the open (unrestricted) replication policy: per-store memory grows proportional to the total activity of every participant ever recorded, and the paper's own stated fix — restricting replication to a transitively-followed interest graph — leaks the follower graph to anyone observing the update exchange, which the source paper states makes the mechanism unsuitable for a participant whose safety depends on hiding whom they follow [`KERMARREC-DICG-20`].

For media, the content-addressed mechanism's central limitation is that persistence is opt-in and unenforced: an object nobody chooses to pin survives only as long as some node's transient cache happens to retain it, with "no other persistence layer" supplying a default [`BENET-ARXIV-14`].

For secondary indexing, the corpus's own measured range-reconciliation speedup (4.69×–13.98×, `AMPARORE-ARXIV-26`) and the corpus's own measured content-addressed range-index speedup (24%–45% and ~3×, `RAWAT-DLT-24`) cannot currently be composed, because the structure carrying the second measurement is proved to lack the property the first measurement's protocol requires [`MEYER-TR-24`], and returning any range-query match set at all — independent of this composition question — is proved sufficient, on its own, to reconstruct approximate record order and value from encrypted content [`GRUBBS-SP-19`].

### What the corpus does not settle

The hash-identified Byzantine-tolerant CRDT construction's own convergence proof for specific data types beyond bare identifier uniqueness (RGA-style lists needing deletion-reference validity, WOOT/YATA-style insertion-predecessor validity) is stated by its own author as an open conjecture: "I leave a detailed proof of this conjecture... for future work" [`KLEPPMANN-PAPOC-22`]. No entry in this corpus supplies that proof for any specific type.

No entry measures Byzantine causal broadcast performance beyond a 4-replica, single-process, non-adversarial laboratory prototype [`KLEPPMANN-ARXIV-20`]; how reconciliation cost, DAG storage growth, or head-comparison round count behaves with millions of writers and a genuinely adversarial, churning replica population is unmeasured anywhere in the corpus.

No entry measures long-run storage growth of retained operation history at the multi-year timescale a real social application would run at. The one field report in this corpus states plainly that a CRDT's complete change history "created measured performance and memory/disk problems in real use" in one internally-built prototype, but gives no figure — no byte count, no growth rate, no time-to-problem [`KLEPPMANN-ONWARD-19`]. Whether the selected hash-identified construction's ~100-byte-per-frontier summary [`KLEPPMANN-PAPOC-22`] postpones or merely relocates this problem is not addressed by any entry.

No entry benchmarks a secondary index or range query built directly over any of the three selected mechanisms — a hash-identified CRDT store, a signed-log store, or a content-addressed immutable-object store — at any scale; the closest available pieces (prolly trees, Willow, the RSOS/AELMDB backend) neither target this combination directly nor compose with each other without an unproved or explicitly absent adaptation, as detailed above [`RAWAT-DLT-24`, `WILLOW-SPEC-23`, `AMPARORE-ARXIV-26`, `MEYER-TR-24`].

Garbage collection compatible with an unbounded, adversarial, unknown-membership replica set — as opposed to the known-bounded-membership stability model this corpus's non-Byzantine CRDT literature assumes [`SHAPIRO-EATCS-11`] — is not proposed, proved, or measured by any entry in this corpus.
