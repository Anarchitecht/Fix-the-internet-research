## Reputation: A participant assessing a stranger computes a bounded network-flow value from itself, as source, to that stranger, over a trust-linkage graph whose edges cost something real to form

A participant deciding how much to trust a stranger — whether to accept a message from them, complete a transaction with them, or count their vote — needs a number computed without a central operator holding every participant's history, and without waiting for the whole network to agree on one shared score. Every candidate below answers this from a different starting point: a value computed from the assessing participant's own position in a graph of linkages (`LEVIEN-USS-98`, `TRAN-NSDI-09`, `POST-NSDI-11`, `MISLOVE-NSDI-08`, `VISWANATH-EUROSYS-12`, `NASRULIN-BRAINS-22`), a value diffused outward from a labeled seed set along the same kind of graph (`GYONGYI-VLDB-04`, `FURUTANI-TIFS-23`, `ZIEGLER-ISF-05`), a single value every participant in the network converges to agreeing on (`KAMVAR-WWW-03`), or a value built by summing what other participants directly report about their own past transactions with the stranger (`ISMAIL-BLED-02`, `XIONG-TKDE-04`, `SRIVATSA-WWW-05`).

### Selection

The selected mechanism is the capacity-bounded, own-position network flow family: SumUp's ticket-distributed max-flow approximation (`TRAN-NSDI-09`), Bazaar's max-flow risk network (`POST-NSDI-11`), and Ostra's credit-network variant (`MISLOVE-NSDI-08`), made tractable at scale by Canal's landmark-routing approximation (`VISWANATH-EUROSYS-12`), resting on Levien's proof that a max-flow construction of this kind is the provably tightest achievable trust metric in its class (`LEVIEN-USS-98`). A participant assessing a stranger computes the maximum flow, or an approximation of it, from itself as source to that stranger as sink, over a graph whose edges represent linkages that cost something real to form; the resulting value bounds how much the participant should risk on, or accept from, that stranger.

Against the four attacks this component must address: discarding a poorly rated identity gains nothing structurally, because Bazaar starts every new or reborn identity with zero flow to every existing participant until a real vouching link or an escrowed deposit creates one (`POST-NSDI-11`), which is exactly the only equilibrium Friedman and Resnick prove cannot be beaten once identity change is free and any positive error rate exists — a strategy that extends trust only to linked history and treats every newcomer, indistinguishable from a repeat offender, at the same distrustful floor (`FRIEDMAN-JEMS-01`: no equilibrium exceeds V(PYD) = 1 − α/(2−α) − O(ε) − O(1/M) under those conditions). Coordinated mutual rating gains nothing structurally either, because Ostra's credit-conservation invariant holds the sum of every link balance in the system at exactly 0 after every operation (`MISLOVE-NSDI-08`: "the sum of all credit balances is 0"), so a set of colluding identities rating each other well only redistributes credit among themselves and cannot manufacture capacity toward a stranger outside the group — Bazaar's cut-capacity bound carries the identical property: colluders "can only defraud together for the total of what they could defraud separately" (`POST-NSDI-11`). Self-rating through controlled identities is bounded by the same cut-capacity argument: SumUp measures the resulting attack capacity at ≈1 fraudulent vote per attack edge, independent of how many Sybil identities sit behind that edge, against SybilLimit's ≈30 accepted Sybils per attack edge on the identical graph and edge count despite both carrying the same asymptotic O(log n) bound (`TRAN-NSDI-09`); Levien's proof establishes this is not an accident of one construction — no trust metric in this class can be forced below d nodes for a node-compromise attack or β·d/2 for an edge-only attack, the proven-optimal bound for the class (`LEVIEN-USS-98`). Rating a competitor falsely low is bounded, not eliminated: a false negative report reduces only the reporting participant's own link to the target, so damaging a competitor requires the attacker to already hold real prior transaction volume with that specific competitor — Bazaar's own stated reasoning is that this raises the attack's cost relative to unbounded feedback-based systems, since the attacker must first accumulate non-fraudulent transaction history before it can inflict any damage (`POST-NSDI-11`), bounding a slanderer's damage to its own accumulated legitimate link weight against the one victim, without preventing a single false report entirely.

Against EigenTrust (global eigenvector): rejected. EigenTrust requires a pre-existing, out-of-band-designated set of pre-trusted peers whose trustworthiness is assumed rather than derived, and the paper states network designers or founders fill this role but gives no verification procedure for it (`KAMVAR-WWW-03`) — a small committee whose membership decides the whole network's convergence is a durable control point, at odds with a design whose stated goal is that no company can capture the network. Measured degradation is by network fraction, not by attack edge: a malicious collective exceeding 40% can influence global trust value assignment during computation under the majority-vote secure scheme (`KAMVAR-WWW-03`), which has no counterpart bound in the selected mechanism, whose bound scales with the attacker's own cut capacity regardless of what fraction of the network it represents. EigenTrust's own text states self-rating via unbounded identities is countered only by an entry-cost mechanism external to EigenTrust itself (`KAMVAR-WWW-03`); the selected mechanism converts whatever entry cost exists elsewhere into the sharpest measured bound in this corpus (`TRAN-NSDI-09`). EigenTrust also converges to one value every peer agrees on, not a value computed from the assessing participant's own position, the opposite of what this component's task definition requires.

Against TrustRank and the unified SybilRank / CIA / SybilWalk / SybilSCAR / SybilBelief / SybilHeat family (energy propagation from a labeled seed set): rejected for assessing one stranger, though this family remains a documented option for bulk classification of an entire population against a labeled seed set — a different task. Every member requires the caller to already hold a pre-labeled trustworthy set, and most require a pre-labeled untrustworthy set too, materialized over the full graph before any query runs (`FURUTANI-TIFS-23`); TrustRank's own seed set came from one human evaluator manually checking 1,250 candidate sites (`GYONGYI-VLDB-04`), and the two production deployments of this family measured in this corpus both required the operator to hold the complete social graph plus human-verified seeds distributed by analysts (`CAO-NSDI-12`, `BOSHMAF-NDSS-15`) — the same operator-capture point this design rules out. The selected mechanism needs no labeled seed set at all: it needs only a graph of costly linkages and the assessor's own position in it.

Against Appleseed (personalized spreading-activation, energy propagation from the assessor's own seed): rejected on a directly documented distortion the selected mechanism does not carry. Appleseed inherits the "eager trusters" penalty from unweighted spreading activation — a participant who legitimately vouches for many honest strangers has each individual vouch diluted — a limitation the same source states Appleseed shares with EigenTrust and PageRank, and states Advogato's capacity-based design does not exhibit (`ZIEGLER-ISF-05`, Table 5.1 feature F.2). The selected mechanism's guarantee depends on cut capacity between assessor and target, not on how many statements a node has issued.

Against MeritRank's Personalized PageRank and Personalized Hitting Time (energy propagation, personalized): this is the closest measured competitor, and it is also the entry in this corpus that measures the selected family's own MaxFlow variant losing. On MeritRank's own feedback graph and repeated-Sybil-attack model, Personalized Hitting Time reached the lowest attacker's gain of the three algorithms tested, and MeritRank's MaxFlow variant reached the highest, while costing more to compute (`NASRULIN-BRAINS-22`). That measurement targets a different quantity than the one this selection is built for: MeritRank's "attacker's gain" is a ratio applied to a continuously compounding, per-epoch reward score across 153 repeated attack rounds in a tokenomics setting, not a single admit-or-refuse decision about one stranger. Bazaar's and SumUp's measured guarantee is a bound on total extractable value or vote count per interaction, evaluated as a threshold decision (`POST-NSDI-11`, `TRAN-NSDI-09`), and Advogato's guarantee is a proven bound on attacker resources for exactly a one-shot accept/reject decision (`LEVIEN-USS-98`). No entry in this corpus runs SumUp, Bazaar, or Advogato's construction under MeritRank's repeated-epoch, compounding-reward attack model, or runs MeritRank's PHT algorithm under Bazaar's or SumUp's threshold-decision model, so which family costs less for the task this component performs — deciding how much to trust one stranger, once, at the moment of interaction — is not settled by a shared experiment. The selection is made for that threshold-decision task, the one the component's own definition states, and MeritRank's result is the strongest evidence against extending this same selection to a compounding-reward use elsewhere in the architecture.

Against the Beta reputation system (bilateral outcome counting, unweighted): rejected because the mechanism, by its own worked example, provides no mechanism against collusion — its combination operator treats every unit of feedback as equally trustworthy once received (`ISMAIL-BLED-02`), so two colluding identities that transact with each other repeatedly accumulate the same weight as two strangers with a genuine history; the source's own eBay example states "two of the fraudsters actually had good Feedback Forum ratings, developed through rating each other favourably." The paper states directly it has "not tried to address the problem of immunity against agents changing identities" (`ISMAIL-BLED-02`). The selected mechanism's credit-conservation property (`MISLOVE-NSDI-08`) is a structural answer to exactly the collusion case Beta states it cannot handle.

Against PeerTrust and TrustGuard (bilateral outcome counting, credibility-weighted): the recursive, trust-value-weighted form (TVM) reaches 100% RMS trust-computation error — "complete misclassification of good vs. malicious peers" — once malicious peers exceed 50%, and is "extremely sensitive" to collusion even at small malicious fractions (`XIONG-TKDE-04`, `SRIVATSA-WWW-05`). The similarity-weighted form (PSM) survives the same collusion condition (`SRIVATSA-WWW-05`), but requires the assessor to already share a nonempty set of prior transactions with each feedback source to compute that similarity — if two peers' transaction histories never overlap, PSM has no basis to compute a similarity-based credibility for one from the other (`XIONG-TKDE-04`) — which is precisely the direct-experience requirement a stranger has not yet supplied. Neither paper measures or claims a defense against self-rating through controlled identities beyond citing whitewashing countermeasures as future work (`XIONG-TKDE-04`); the selected mechanism's bound on self-rating (`TRAN-NSDI-09`, `LEVIEN-USS-98`) has no counterpart in this family for a first encounter with a stranger.

Against Advogato's own construction, unaccelerated and boolean-only, as a stopping point within the selected family: not rejected as a mechanism, but not adopted as the complete selection. Advogato's proof gives the tightest known bound (`LEVIEN-USS-98`) but returns only a boolean accept/reject for a fixed flow target of 1, not a graded value a participant can weight a decision by, and the paper itself ends without validating the metric on any deployed or prototype certificate infrastructure, stating "only practical experience with a prototype system can determine whether this tradeoff is worthwhile" (`LEVIEN-USS-98`). Bazaar, SumUp, and Ostra extend the identical construction to a continuous, per-interaction capacity value with measured production-scale performance (an 8,874,521-item eBay feedback crawl, a 446,181-node YouTube trust network: `POST-NSDI-11`, `MISLOVE-NSDI-08`) and add feedback-driven link elimination and credit decay that Advogato's static construction does not specify; Canal supplies the tractable-cost result needed at that scale (`VISWANATH-EUROSYS-12`). Advogato's proof is cited above as the reason the extended family's bound is not an artifact of any one paper's construction, not as a competing selection.

### What this selection requires from the rest of the system

- A trust-linkage layer (an identity or social-graph component elsewhere in this architecture) supplying edges that cost something real — time, money, social capital, or another scarce resource — to create and maintain; the bound collapses to nothing if this layer allows free edge creation, exactly the gap Ostra's own authors flag for the YouTube graph they had to substitute (`MISLOVE-NSDI-08`).
- Either a party able to compute over the full linkage graph on the assessor's behalf (Bazaar's design, `POST-NSDI-11`), a decentralized route-discovery layer (Ostra §7's Bloom-filter-plus-landmark sketch, `MISLOVE-NSDI-08`), or a Canal-style precomputed landmark index rebuilt continuously in the background (`VISWANATH-EUROSYS-12`) — some component must expose enough of the graph for a flow or approximate-flow computation to run from the assessor's own position.
- An atomic hold/release protocol at the point of interaction: capacity along the flow path is reserved before the interaction proceeds and resolved — released or permanently debited — once an outcome signal or a bounded timeout arrives; the component consuming this reputation value (messaging, marketplace, or voting) must supply that outcome classification (`POST-NSDI-11`, `MISLOVE-NSDI-08`, `TRAN-NSDI-09`).
- A new-participant bootstrap: an existing participant extending a starter link at their own real risk, or an escrow/deposit mechanism creating a link of that deposited value; without one of these paths from the identity/onboarding component, every new participant starts at zero flow to everyone (`POST-NSDI-11`).
- Rational-actor incentive alignment for truthful feedback: the reasoning that a participant reports outcomes honestly depends on that participant's own links being at stake (`POST-NSDI-11`), which composes with the edge-cost requirement above — a participant with no remaining stake in its own linkage position has no measured incentive to report truthfully.
- No privacy tier offered elsewhere in this architecture may hide a participant's linkage graph from whichever party executes the flow computation; the evidence record for Bazaar notes explicitly that this guarantee composes poorly with any anonymity or partial-visibility tier that hides participants' linkage graphs from a shared computation point, since the flow computation cannot run over information the computing party does not hold (`POST-NSDI-11`) — this is a composition conflict to resolve explicitly against whatever privacy tiers this synthesis selects, not an open question to leave unresolved.
- If Canal's landmark acceleration is used: a link-level locking mechanism so concurrent path-stitching does not double-consume one link's capacity, and enough memory on whichever machine builds landmark universes to hold the full graph plus every cached universe — measured at almost 20GB for a 234-million-link graph on a single machine, with a distributed, cluster-based version left unevaluated by its own authors (`VISWANATH-EUROSYS-12`).

### What it costs and where it fails

Exact max-flow (push-relabel) costs 0.352 seconds on a 1.4-million-link graph and rises to 220 seconds on a 234-million-link graph, per single query on one machine (`VISWANATH-EUROSYS-12`) — too slow for an online, per-interaction decision at the upper end of that range. Bazaar's own multi-graph optimization, unaccelerated, brings average per-category query time to 1.18–6.29 seconds and needs a minimum 6-core server to keep pace with its trace's measured peak daily auction volume in the busiest category (`POST-NSDI-11`). Canal's landmark approximation reduces this to a median under 1 millisecond for a 1-credit query across five graphs up to 234 million links, and to 0.1–0.2 milliseconds (a 785×–2,329× speedup) once integrated into Bazaar's own eBay trace, at 94.2%–99%+ agreement with the exact computation (`VISWANATH-EUROSYS-12`) — the residual disagreement is entirely false negatives (wrongly refusing a stranger the exact computation would have accepted), never a false positive, so the approximation trades a small, bounded rate of wrongly-refused strangers for tractable cost, never trades away the underlying fraud or Sybil bound.

The bound is only as strong as the minimum-cut weight between assessor and stranger: a legitimate stranger connected to the honest region through one thin link is starved of trust regardless of the honest population's total connectivity elsewhere, a risk Ostra's own min-cut analysis found falls as a participant's degree rises but does not eliminate for low-degree participants (`MISLOVE-NSDI-08`). A compromised long-history account can still be drained of value up to its own accumulated bound — bounded, not prevented (`POST-NSDI-11`). And, as established in the Selection comparisons above, this bound is measured to be the worst-performing option among three personalized alternatives, in a setting where the same underlying reputation value must compound continuously across many repeated attack rounds rather than support one threshold decision (`NASRULIN-BRAINS-22`) — a condition that does not hold for the single-stranger assessment task this component is built for, but is a documented failure mode for any future component that reuses this same mechanism for a compounding score.

### What the corpus does not settle

1. No entry measures this family's fully peer-executed, decentralized variant end-to-end. Ostra's own decentralized design (Bloom-filter and landmark route discovery, each node holding only local per-link state) is validated only by a preliminary Bloom-filter-size and landmark-coverage measurement, not an end-to-end deployment (`MISLOVE-NSDI-08`). Canal's landmark-index acceleration is itself a single-machine, centrally-computed background process (`VISWANATH-EUROSYS-12`); no entry measures a Canal-style landmark index built and queried without a party that holds the whole graph.
2. No entry measures the cut-capacity bound this selection relies on against an adversary who selectively targets which honest participants to attach Sybil links to, the way `VISWANATH-SIGCOMM-10` measured for SumUp's use as a Sybil classifier (where targeted attachment drove classification accuracy below random). Bazaar's guarantee is a different quantity — a bounded monetary or vote amount, not a binary label — so whether targeted attachment degrades the cut-capacity bound the same way it degrades classification accuracy is unmeasured in this corpus.
3. No entry measures how the slander defense (damage bounded by the attacker's own accumulated real transaction volume with the specific victim) behaves when many separate attackers pool their individually-accumulated links against one small-degree target; Bazaar's own text flags this attack qualitatively without a swept experiment (`POST-NSDI-11`).
4. Every tunable parameter cited above (Ostra's L, U, and decay rate d; Bazaar's multi-graph base k and feedback timeout T; Canal's landmark-universe count and level) is evaluated only at whatever value each paper's own trace happened to need, not derived from first principles. A builder needs to re-measure these against the target deployment's own linkage-formation rate and interaction volume rather than reuse the values cited here.
5. No entry directly compares Bazaar/SumUp/Ostra-style max-flow against MeritRank's Personalized Hitting Time on the same graph and the same attack model. The two measured comparisons available (SumUp vs. SybilLimit, `TRAN-NSDI-09`; MeritRank's three algorithms against each other, `NASRULIN-BRAINS-22`) use different graphs, different attack models (static attack-edge injection vs. repeated per-epoch Sybil injection), and different outcome metrics (bogus-vote count vs. a continuously compounding reputation-gain ratio), so a single shared experiment settling which family costs less for a threshold accept/reject decision specifically does not exist in this corpus.
6. No entry measures whether the fast-mixing or bounded-modularity assumption that degrades classification-style Sybil defenses (`VISWANATH-SIGCOMM-10`: accuracy falls toward random, and below random under targeted attachment, as network modularity rises) has any analogous effect on a pure cut-capacity bound of the kind Bazaar and Ostra compute, since that bound is an algebraic property of max-flow rather than a classifier's accuracy against ground truth, and no paper in this corpus tests it against the modularity sweep `VISWANATH-SIGCOMM-10` ran for classification-style methods.
