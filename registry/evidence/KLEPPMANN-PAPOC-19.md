## [KLEPPMANN-PAPOC-19] Interleaving Anomalies in Collaborative Text Editors
**Citation:** Martin Kleppmann, Victor B. F. Gomes, Dominic P. Mulligan, Alastair R. Beresford. "Interleaving Anomalies in Collaborative Text Editors." Workshop on Principles and Practice of Consistency for Distributed Data (PaPoC), co-located with EuroSys, 2019. DOI 10.1145/3301419.3323972.
**Retrieved:** full text via https://martin.kleppmann.com/papers/interleaving-papoc19.pdf
**Source URL:** https://doi.org/10.1145/3301419.3323972 ; https://martin.kleppmann.com/papers/interleaving-papoc19.pdf
**Domain:** D

### What it does
This paper states the precise condition under which several published collaborative-text-editing algorithms garble concurrent insertions into an unreadable character-by-character jumble, and gives a fix for one of those algorithms. The full anomaly occurs when two users concurrently insert text sequences at the same position in a document (for example, one user typing " Alice" and another typing " Charlie" both immediately after "Hello"): a merging algorithm exhibiting the anomaly can interleave the two sequences arbitrarily, character by character, rather than keeping each user's insertion as one unbroken run. Logoot and LSEQ (two published text-editing CRDTs — Conflict-free Replicated Data Types, structures whose concurrent updates merge deterministically without coordination) exhibit the full anomaly because both assign each inserted character a position identifier drawn from a dense ordered set (conceptually a rational number between the identifiers of its left and right neighbors; concretely a path through a tree with the same effect), and when two users insert into the same gap without knowledge of each other's insertion, each spreads its own characters' identifiers across that gap independently, so the merged order interleaves the two runs arbitrarily. RGA (Replicated Growable Array, a different text-editing CRDT) does not exhibit the full anomaly — the paper cites its own prior mechanized Isabelle/HOL proof of this — because RGA anchors each inserted character to the single character immediately preceding it at insertion time rather than to a dense-identifier gap, so a sequentially typed run of characters (each anchored to the one before it) is never split apart by a concurrent insertion elsewhere. RGA does exhibit a lesser variant: if two runs of characters inserted by the same user, at different times, are both anchored to the same preceding character (which happens when a user inserts once, moves the cursor back to the same anchor point, and inserts again), and a third user's concurrent insertion is also anchored to that same character, all insertions sharing an anchor are ordered only by a timestamp comparison, so the third user's whole run can land between the first user's two runs — three merge outcomes become possible instead of the intended one, though no single run's internal character order is ever broken. The paper adds a clause to Attiya et al.'s Astrong specification of collaborative text editing (clause 1(d): for any two sets of concurrent insertions occupying the same document interval, either every element of one set precedes every element of the other in the merged result, or vice versa — never a mix) that rules out the full interleaving anomaly, which the original Astrong specification permits. The paper's fix for RGA's lesser anomaly extends each insertion operation's data from a triple (character, timestamp, reference-character-timestamp) to a 4-tuple that adds e — the set of timestamps of every other insertion sharing the same reference character at the moment this insertion was performed — then orders two insertions sharing a reference character by comparing the minimal timestamp in the "difference" of their two e-sets (the earliest timestamp at which the two insertions' causal histories diverged, rather than each insertion's own single timestamp), which the paper states groups every operation from one continuous editing session together, ahead of or behind every operation from a different, concurrent session.

### Measured results
This paper is a specification and mechanism paper reporting no benchmark, latency, or throughput figures — its evidentiary content is a demonstrated empirical observation and a set of formally stated conditions, not a quantified performance result. It reports one qualitative empirical observation, without a trial count, input size, or measured rate: the authors "performed tests with open source implementations of Logoot and LSEQ... and observed this interleaving anomaly occurring in practice," and separately released the underlying research data as a public dataset (DOI 10.17863/CAM.37617); because this observation carries no stated experimental conditions (no count of test runs, no input text length, no environment), it does not meet this schema's bar for a recordable measured figure and is reported here only as an attributed qualitative claim, not as data.

### Parameters
None — the paper defines no tunable numeric parameter. The one structural quantity it introduces is the per-insertion timestamp-set e used in the RGA fix, whose size the paper states is expected to be small in practice ("there are normally not many operations with the same reference character, regardless of the length of the document"), offered as an unmeasured expectation, not a derived or measured bound.

### Stated limitations
The claim that RGA satisfies the paper's own strengthened specification (Astrong plus clause 1(d)) once the 4-tuple fix is applied is stated explicitly as a conjecture, not a proof: "we conjecture that applying this construction to RGA results in a CRDT without interleaving... A formal proof of this conjecture is left for future work." The fix increases memory and network bandwidth used by the algorithm because of the added per-operation timestamp set e; the paper gives no measured overhead figure for this increase, only the unmeasured expectation noted above. The paper states, but does not prove, that Treedoc and WOOT (two other published text-editing CRDTs) do not suffer from either the full or the lesser interleaving anomaly — this is stated as an unproven conjecture ("we conjecture that Treedoc and WOOT do not suffer from either anomaly, but we leave a rigorous proof of this claim for future work"), so neither algorithm should be treated as verified interleaving-free on this paper's authority. The lesser RGA anomaly requires a specific, uncommon editing pattern (inserting a document, or part of one, in an order other than strict left-to-right) to manifest at all; the paper's own worst-case example — typing an entire document from back to front, causing every character to anchor to the document head and be ordered only by timestamp, permitting arbitrary character-level interleaving — is stated to be "unlikely to occur in realistic editing scenarios," while the paper still argues it is a case formal consistency models must account for.

### Requirements it places on the rest of the system
Ruling out the full interleaving anomaly under the paper's revised specification (clause 1(d)) requires the merge algorithm to preserve, for every pair of concurrently inserted sequences occupying the same gap, a total group ordering between the two sequences as wholes — an algorithm that assigns identifiers to individual characters independently of which other characters were inserted in the same user action does not have the information needed to satisfy this clause, since nothing in a single character's identifier records which run it belongs to. The RGA fix requires every insertion operation to carry, in addition to its own timestamp and its reference character's timestamp, the full set of timestamps of every other insertion that shared the same reference character at the moment this insertion was made — this is additional state that must be transmitted and stored per operation, not derivable after the fact from the document's final character sequence alone, so a wire format or storage layout designed only around the original RGA triple cannot be retrofitted with this fix without a schema change. The fix's total ordering of concurrent insertions sharing a reference character depends on comparing timestamps for set membership (t1 in e2, or the minimal element of a set difference), which requires a total order over timestamps to be well-defined system-wide — the paper notes Lamport timestamps have already replaced Roh et al.'s original custom S4Vector datatype in subsequent RGA presentations, and this paper's fix is stated in terms of that same timestamp abstraction, so any timestamp scheme used must supply a total order, not merely a partial causal order.

### Contradicts
None found as an internal contradiction. This paper functions as a shorter, standalone restatement of a result also presented at greater length in KLEPPMANN-AFP-18 (OpSets) by the same authors: the full interleaving anomaly, Logoot and LSEQ's susceptibility to it, RGA's freedom from the full anomaly, and the revised Astrong specification (Theorem 1-3 material in the OpSets paper) are the same underlying findings, with this paper adding the previously unpublished lesser RGA anomaly and its conjectured fix, which OpSets (AFP-18) does not contain. A claim commonly attributed to RGA — that it fully solves the interleaving problem CRDTs face — is contradicted by this paper's own finding: RGA avoids the full anomaly but is shown here to still permit the lesser anomaly under non-sequential insertion patterns.
