## [SINGH-INFOCOM-06] Eclipse Attacks on Overlay Networks: Threats and Defenses
**Citation:** Atul Singh, Tsuen-Wan Johnny Ngan, Peter Druschel, Dan S. Wallach. "Eclipse Attacks on Overlay Networks: Threats and Defenses." IEEE INFOCOM, 2006. DOI 10.1109/INFOCOM.2006.231.
**Retrieved:** full text via http://rowstron.azurewebsites.net/MS/eclipse.pdf
**Source URL:** http://rowstron.azurewebsites.net/MS/eclipse.pdf
**Domain:** A

### What it does
An eclipse attack surrounds one correct node with colluding malicious nodes so that every, or nearly every, message the victim sends or receives passes through an attacker. A modest fraction of malicious nodes can eclipse a much larger number of correct nodes by supplying biased neighbor referrals during ordinary overlay membership maintenance, because correct nodes propagate whatever neighbor information they receive without verifying it.

The paper's defense bounds each node's in-degree (the number of other nodes referring to it as a neighbor) and out-degree (the size of its own neighbor set) to a value close to the overlay's expected per-node degree, without depending on a centralized service to track degree. It proves that if the out-degree and in-degree of every node are bounded to the overlay's expected neighbor-set size (bound multiplier t=1), the expected fraction of malicious entries in a correct node's neighbor set is bounded by f/(1-f), where f is the fraction of malicious nodes in the overlay.

Degree bounds are enforced by distributed auditing rather than a trusted authority: each node x maintains a backpointer set, the list of every node currently listing x as a neighbor. Periodically, x anonymously challenges each of its own neighbors z by requesting z's backpointer set through a randomly selected intermediate node, called an anonymizer, so that z cannot tell which node is auditing it and cannot selectively suppress its response to that specific auditor. If z's returned backpointer count exceeds the in-degree bound, or z's response omits x from that backpointer set, x treats z as suspicious. The anonymizer must itself be unpredictable to z and cannot be trivially spoofed; the paper analyzes three anonymizer-selection techniques and derives, for an overlay with malicious fraction f, the minimum anonymizer-set size n such that the probability at least half the anonymizer set is malicious falls below a target threshold — at f=0.2, only 1% of anonymizer sets of size 16 have at least half their members malicious. The scheme assumes each participating node carries a certificate binding its node identifier to a public key (defeating identifier forgery, though not addressing Sybil identity creation itself) and that the overlay supports a constrained-routing-table (CRT) secure-routing primitive as a fallback path when the primary proximity-neighbor-selection (PNS) routing table fails.

### Parameters
- Overlay: MSPastry with routing base b=4, leaf-set size ℓ=16.
- Malicious node fraction f: 0.2 (20%) unless stated otherwise.
- Malicious out-degree per routing-table row: 16 (attacker-optimal — the paper states its own simulations show a larger out-degree causes quicker detection and reduces attack impact).
- In-degree/out-degree bound (correct nodes): 16 per routing-table row and backpointer-set row, swept 16/32/48/64/unlimited in the idealized experiment.
- Anonymizer-set size n: 24, chosen so the expected number of anonymizer sets with at least half malicious members is below 1 at f=0.2 (needing at least 12 of 24 correct challenge responses to pass an audit iteration).
- Audit interval: once every 2 minutes per neighbor (halved to once per minute in the high-churn sensitivity test), each audit timed at a random instant within the interval.
- Churn rates tested: 0%, 5%, 10%, 15% per hour, corresponding to average node lifetimes of indefinite, 20, 10, and 7 hours respectively; the paper notes these rates exceed the 37.7-hour average session time Bolosky et al. measured in a corporate environment but are much lower than rates reported for some file-sharing networks.
- Network topology models: GT-ITM transit-stub, 5,050 routers; King-tool-measured real Internet latencies among up to 10,000 hosts.
- Network sizes tested: 1,000/1,740/2,000/5,000/10,000/20,000 nodes, depending on experiment.

### Stated limitations
The defense detects malicious nodes independently at each auditing node and has no mechanism for one correct node to produce a verifiable proof of misbehavior that other correct nodes could act on; the paper states this would require complex cryptographic operations or Byzantine agreement and could interact badly with auditing false positives, so it is not attempted. The mechanism is not directly applicable to overlays that deliberately use asymmetric node degree for performance, such as KaZaA superpeers, because the defense's signal is precisely a degree deviation from the overlay average; the paper states securing such heterogeneous overlays is an open research problem requiring different solutions. Auditing in unstructured overlays needs a separate mechanism to securely select anonymizer sets, which the paper does not build; it sketches maintaining an additional structured overlay purely for anonymizer discovery as one option. Localized eclipse attacks — an adversary concentrating on surrounding a small set of victims rather than the whole network — are not detected by degree bounding, because a localized attacker need not exceed the average degree; the paper states this requires the colluding nodes to have low network latency to the victims specifically (since row-zero eligibility under PNS depends on measured proximity) and states defending against it is an open research problem. The defense assumes the overlay already supports a certified node identifier binding to a public key and a constrained-routing-table secure-routing fallback; it does not itself solve Sybil-identity creation. The target operating regime is stated explicitly as low-to-moderately-high churn — at 15% churn/hour the top-row malicious fraction does not drop below about 30% even after auditing runs, because newly joined malicious nodes have not yet accumulated enough audit history to be caught.

### Requirements it places on the rest of the system
Every node needs a certificate binding its node identifier to a public key before the defense can be deployed; the paper does not supply or evaluate an identity-issuance mechanism, only assumes one exists. The overlay needs a working constrained-routing-table (CRT) secure-routing primitive as a fallback path used whenever primary PNS-based routing fails; the measured overhead figures (about 0.2 msg/node/sec for CRT maintenance) are additive on top of this defense's own auditing cost, and the delay-comparison figures assume this two-tier routing structure is in place. The auditing protocol requires each node to maintain a backpointer set (the list of nodes that currently list it as a neighbor) and to answer anonymized challenges for that set, so any change to how neighbor relations are recorded or discovered elsewhere in the system must preserve this bidirectional bookkeeping. The anonymizer-selection mechanism requires the overlay to supply a way to pick a random relay node whose identity is unpredictable to the node being audited before the challenge is issued; the paper's own analysis (Section IV-C) makes the anonymizer-set-size choice a function of the malicious-node fraction f, so a system deploying this defense needs an independent estimate of f to size that set correctly. The defense needs a nonzero churn-tolerant time window (the paper's simulation requires roughly an hour of node lifetime for 24 audit challenges to accumulate meaningful data) — a system with node lifetimes shorter than this will not collect enough audit rounds to detect an over-degree node before it can complete its attack window, which the paper flags as requiring a correspondingly higher audit rate and proportionally higher overhead.

### Contradicts
None found — no other entry in this corpus reports a conflicting eclipse-attack or degree-bounding figure under matching conditions. The paper itself contradicts the value judgment (attributable to Hildrum and Kubiatowicz, and re-tested here) that proximity neighbor selection alone is a sufficient eclipse defense: measured under real Internet (King) latencies rather than the synthetic GT-ITM topology, PNS's defensive effectiveness is stated to be "significantly reduced," and the paper concludes a PNS-only defense "will not be effective in the real Internet."
