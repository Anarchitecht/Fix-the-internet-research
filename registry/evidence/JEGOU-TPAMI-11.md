## [JEGOU-TPAMI-11] Product Quantization for Nearest Neighbor Search
**Citation:** Herve Jegou, Matthijs Douze, Cordelia Schmid. "Product Quantization for Nearest Neighbor Search." IEEE Transactions on Pattern Analysis and Machine Intelligence 33(1), 2011. DOI 10.1109/TPAMI.2010.57.
**Retrieved:** full text via https://www.irisa.fr/texmex/people/jegou/papers/jegou_searching_with_quantization.pdf
**Source URL:** https://www.irisa.fr/texmex/people/jegou/papers/jegou_searching_with_quantization.pdf
**Domain:** B

### What it does
Product quantization (PQ) compresses each high-dimensional vector in a database to a short binary code while still supporting an accurate estimate of the Euclidean distance between any query vector and any compressed database vector, so approximate nearest-neighbor (ANN) search can run over datasets whose full vectors would not fit in memory. A quantizer maps a vector to the nearest of a fixed set of reproduction points (centroids), called a codebook; a codebook of size k built by ordinary k-means on D-dimensional vectors requires storing and searching k D-dimensional centroids, and reaching a code length of 64 bits (k = 2^64 centroids) makes both the centroid storage and the k-means training infeasible outright — more floating-point values than exist in available computer memory, by the paper's own description.

Product quantization avoids this by splitting each D-dimensional vector into m disjoint subvectors of dimension D/m and quantizing each subvector independently with its own small k-means codebook of k* centroids. The combined codebook is the Cartesian product of the m subcodebooks, giving k = (k*)^m effective centroids while storing and training only m separate codebooks of k* centroids each — a memory and training cost of m times k* times (D/m) values instead of k times D. A vector's code is the concatenation of its m subquantizer indices, each ceil(log2 k*) bits, for a total code length of m times log2(k*) bits.

Distance to a query is estimated two ways. Symmetric distance computation (SDC) quantizes both the query and the database vector, then estimates their distance as the distance between their two codes (each subvector's inter-centroid distance precomputed once and looked up). Asymmetric distance computation (ADC) leaves the query unquantized and estimates the distance between the raw query and the database vector's code, computing, for each subquantizer, the distance from the corresponding query subvector to every one of that subquantizer's k* centroids (precomputed once per query), then summing the appropriate m looked-up values for each database code. ADC removes the query's own quantization error from the estimate and is more accurate than SDC at equal code length, at equal computational cost, so the paper recommends never quantizing the query.

To avoid comparing a query against every database vector (an exhaustive scan, which does not scale to billions of vectors), the paper adds a non-exhaustive search structure: IVFADC (inverted file with asymmetric distance computation). A separate, coarser k-means quantizer (the coarse quantizer, k' centroids) partitions the database into k' inverted lists; each database vector is stored in the list for its nearest coarse centroid, encoded not as itself but as its residual (the vector minus its coarse centroid), further compressed by a product quantizer learned on residual vectors. A query is assigned to its w nearest coarse centroids (multiple assignment, to recover neighbors that fall just across a Voronoi cell boundary from the query but were quantized into an adjacent cell), and only the w corresponding inverted lists are scanned with ADC-style distance estimation against the residual codes. Multiple assignment is applied to the query only, never to stored database vectors, to avoid inflating storage.

Datasets: SIFT — 128-dimensional local descriptors, 100,000-vector learning set (Flickr images), 1,000,000-vector database and 10,000 query vectors (INRIA Holidays images). ### Parameters
- Number of subquantizers m: swept over {1, 2, 4, 8, 16}.
- Centroids per subquantizer k*: swept over {2^4, 2^6, 2^8, 2^10, 2^12} (16 to 4096); k*=256 with m=8 (64-bit codes) is used as the default "reasonable choice" for most later experiments, stated by the authors as a practical tradeoff between codebook memory (k* x D floating-point values) and quantization accuracy.
- Coarse quantizer centroid count k' (IVFADC): typically ranges from 1,000 to 1,000,000 for SIFT descriptors; swept at {1024, 8192} for the main parameter study, 20,000 for the image-search comparison.
- Multiple-assignment width w (number of coarse cells the query is compared against): swept over {1, 8, 64}.
- Learning-set size: 100,000 vectors for both SIFT and GIST.
- Product quantizer training: standard k-means (Lloyd's algorithm), which the authors note finds only a local optimum, not a guaranteed global one.

### Stated limitations
An unstructured (naive) product quantizer splits a vector into subvectors by consecutive component order; the authors show this is suboptimal for both SIFT and GIST descriptors, which have internal structure (grouped orientation-histogram bins), and that using a "structured" grouping that respects this internal structure improves recall@100 substantially for GIST (0.338 to 0.652 in one configuration) and modestly changes it for SIFT — meaning the plain product-quantizer construction described in Section II is not directly optimal for structured descriptor types without this additional grouping step, which the authors state must be chosen using prior knowledge of the descriptor's internal structure; they note an automatic component-grouping method (a co-clustering algorithm) could remove this dependency but do not implement or evaluate one. IVFADC assumes a single product quantizer, trained once on residual vectors pooled across every coarse Voronoi cell, is accurate for every cell; the authors state this is probably less accurate than training a separate product quantizer per coarse cell, but reject that alternative as memory-intractable (it would require k' times D times k* floating-point values, one full product-quantizer codebook per coarse cell). The paper explicitly restricts its scope to the Euclidean distance; the two Hamming-embedding baselines it compares against (spectral hashing, restricted Boltzmann machines) can be learned for arbitrary distance measures, a generality this method does not offer. For very large datasets, exhaustive PQ search (ADC/SDC without an inverted file) remains prohibitive; the non-exhaustive IVFADC variant is required, and even then a database vector not assigned to one of the query's w visited coarse cells is permanently unreachable by that query regardless of code length — increasing code length cannot compensate for w being too small. When benchmarked against FLANN, the comparison holds all vectors in RAM for FLANN's re-ranking stage, which the authors state "seriously limits the scale on which re-ranking can be used" — the reported IVFADC-vs-FLANN comparison is therefore not run at the paper's own largest (2-billion-vector) scale. The paper reports results only for K=1 nearest neighbor for its main recall curves, stating it observed the K=1 conclusions remain valid for K>1 but does not include K>1 measurements in the paper.

### Requirements it places on the rest of the system
- IVFADC requires two separate k-means-trained codebooks in place before any indexing occurs: a coarse quantizer (k' centroids) and a product quantizer trained specifically on the residual vectors that result from the coarse quantizer's assignment — the product quantizer cannot be trained independently of the coarse quantizer's output distribution.
- The coarse quantizer's centroid count k' and the multiple-assignment width w must be chosen jointly: the paper's own results show recall depends on both together, not on either independently, and the fraction of the database scanned per query scales roughly as w/k' — a system component fixing a latency or bandwidth budget must fix this ratio, not either parameter alone.
- The residual-encoding step assumes the energy of a coarse-quantization residual is small relative to the vector's own energy, i.e., that the coarse quantizer's assignment is reasonably accurate; if a downstream vector distribution changes such that coarse assignment becomes poor, the product-quantizer-on-residual encoding degrades without being retrained.
- The inverted-file index requires assigning and storing a vector or image identifier alongside each residual code, with identifier field width chosen to fit the number of distinct items in the corpus (8-32 bits stated); a system layer that needs to update or delete an indexed vector must manage this identifier mapping and inverted-list membership itself, since the paper does not describe any deletion or update mechanism.
- The ADC/IVFADC estimator requires the ability to precompute, per query, the distance from each query subvector to every centroid of the corresponding subquantizer, and to precompute the residual between the query and each of the w assigned coarse centroids, before scanning any inverted list — this precomputation cost is independent of database size but scales with m x k* (product quantizer) and with the coarse-quantizer dimensionality.
- Achieving the paper's claimed memory efficiency requires accepting the accuracy loss relative to keeping full uncompressed vectors in memory (as FLANN's re-ranking stage does); a system that requires FLANN-style exact re-ranking against full vectors cannot also claim IVFADC's memory-footprint advantage at large scale, since the two properties trade off directly in the paper's own comparison.
