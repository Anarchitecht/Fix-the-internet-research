## [KAMVAR-WWW-03] The Eigentrust Algorithm for Reputation Management in P2P Networks

**Citation:** Sepandar D. Kamvar, Mario T. Schlosser, Hector Garcia-Molina. "The Eigentrust Algorithm for Reputation Management in P2P Networks." ACM WWW, 2003. DOI 10.1145/775152.775242.
**Retrieved:** full text
**Source URL:** https://nlp.stanford.edu/pubs/eigentrust.pdf
**Domain:** F

### What it does
EigenTrust assigns every peer in a peer-to-peer file-sharing network a single global trust value derived from the network's entire transaction history, then biases file-download source selection toward high-trust peers to reduce downloads of inauthentic files. Each peer i keeps a local trust value for peer j equal to the peer's own count of satisfactory transactions with j minus its count of unsatisfactory transactions. These local values are normalized per row so each peer's outgoing trust sums to 1, producing a row-stochastic matrix C. A peer forms a wider opinion by asking its acquaintances for their opinions weighted by its trust in them; iterating this process (multiplying by C-transpose repeatedly) converges to a vector independent of the peer that started it. That converged vector is the left principal eigenvector of C, and its entries are the global trust values. Convergence is guaranteed only if C is irreducible and aperiodic; the paper enforces this by mixing a constant fraction a of the probability mass at every iteration into a fixed distribution p over a small set of pre-trusted peers designated at network creation, which also accelerates convergence and defeats malicious collectives that would otherwise trap the iteration in a closed cluster. Global trust values are computed without central storage: each peer computes its own value from values reported by peers who have interacted with it, using O(1) local state per peer under limited average interaction. In the secure variant, a peer's trust value is instead computed by M separate score-manager peers located by hashing the peer's identifier into M coordinate spaces of a distributed hash table (the paper names CAN or Chord); a majority vote across the M managers' reported values overrides individual malicious managers who report false results, and a peer cannot learn or influence its own score because it cannot choose its own coordinate in the DHT.

### Parameters
- Local trust value s_ij: satisfactory transaction count minus unsatisfactory transaction count between peer i and peer j
- Normalized local trust c_ij: max(s_ij, 0) divided by the sum over j of max(s_ij, 0); falls back to the pre-trusted distribution p_j when peer i has no positive experience with anyone
- Mixing constant a (fraction of probability mass injected into pre-trusted distribution p each iteration): used in Algorithm 2/3, value not given as a single fixed number in the main text — described as "some constant less than 1"
- Pre-trusted peer count in simulations: 3 (out of a network of 60-63 total peers across experiments)
- Probability that a peer with global trust value 0 (a newcomer/unknown peer) is still selected as a download source: 10%
- Number of score managers M per peer (secure variant): parameterized, not fixed to one value in the paper
- Network topology: power-law graph modeled on measured Gnutella structure
- Content distribution: Zipf distribution over 20 content categories, per-peer file counts and category interest drawn from a prior measurement study of real P2P networks
- Simulation settings (Table 1): 60 good peers, 42 malicious peers (base setting, varied per experiment), 3 pre-trusted peers, 2 initial neighbors for good peers, 10 initial neighbors for malicious and pre-trusted peers, query TTL 7, 30 simulation cycles of 50 query cycles each, results averaged over 5 experiment runs
- Good peer inauthentic-file-return rate baseline: 5% (models honest labeling/sharing mistakes)

### Stated limitations
The paper states the scheme is not secured "in the traditional sense": the secure score-management protocol only makes the probability small that a peer can misreport a score undetected, and refers the full argument to a separate technical report rather than proving it in this paper. Choosing which peers to designate as pre-trusted is stated to be "an interesting research area" left outside the paper's scope; the algorithm's guarantee of convergence and collective-breaking depends on no pre-trusted peer belonging to a malicious collective, a condition the paper does not show how to verify. Under the Sybil attack threat model (an adversary creating unbounded new identities, discarding each after one bad transaction), the paper states this exploits the 10% traffic share reserved for peers with no track record, and states the attack is countered only by adding an entry cost to new identities (e.g., a computational puzzle or CAPTCHA), a mechanism outside EigenTrust itself. Under a low-rate virus-distribution threat model, the paper states directly that EigenTrust does not eliminate the infected files it lets through, and adds that no reputation system existing at the time claims to fully eliminate corrupt files. The paper states that if a single malicious collective exceeds 40% of the network, that collective can influence global trust value assignment during computation under the majority-vote secure scheme, though the paper's own inauthentic-download experiments assume trust values are computed correctly and do not model this case.

### Requirements it places on the rest of the system
EigenTrust requires a pre-existing, small, out-of-band-designated set of pre-trusted peers whose trustworthiness is assumed rather than derived from the algorithm itself; the paper suggests network designers or founders fill this role but gives no verification procedure. It requires a functioning distributed hash table (CAN or Chord are named) to locate each peer's score managers by hashing its unique identifier, and depends on that DHT's own churn-handling (state handoff on departure, data replication) to keep score-manager assignments available; EigenTrust supplies no independent mechanism for this. It requires every peer to observe and locally record its own per-transaction outcomes (satisfactory or not) with every peer it has downloaded from, since local trust values are the raw input the whole aggregation is built from. It requires an entry-cost mechanism from elsewhere in the system (a computational puzzle or CAPTCHA) to bound Sybil identity creation, since the paper states this is outside what EigenTrust itself provides. The global trust computation assumes limited average peer-to-peer interaction density to keep the per-iteration computation and message count low; the paper notes that a network of unusually active peers requires artificially capping how many local trust values each peer reports to preserve this.

### Contradicts
None found within this corpus as of this batch. Note for later composition checking: this paper's local trust values are derived purely from file-authenticity outcomes of direct transactions and its threat models (A through F) do not include an adversary who selectively targets which honest peers to connect to (targeted attachment), which VISWANATH-SIGCOMM-10 and ALVISI-SP-13 show is the more damaging attack model for social-graph-based Sybil defenses; EigenTrust is not itself a social-graph defense (it aggregates transaction-history trust, not a social graph), so this is a domain distinction, not a contradiction.
