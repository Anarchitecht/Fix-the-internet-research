## [ALWEN-EUROSP-17] Towards Practical Attacks on Argon2i and Balloon Hashing
**Citation:** Joël Alwen, Jeremiah Blocki. "Towards Practical Attacks on Argon2i and Balloon Hashing." IEEE European Symposium on Security and Privacy (EuroS&P), 2017. DOI 10.1109/EuroSP.2017.47.
**Retrieved:** full text via https://eprint.iacr.org/2016/759.pdf
**Source URL:** https://eprint.iacr.org/2016/759.pdf
**Domain:** I

### What it does
The paper reduces the memory an attacker needs to evaluate a data-independent memory-hard function (iMHF) — a key-stretching function, used to slow brute-force password guessing, whose memory-access pattern does not depend on the secret input and so resists timing side-channel attacks — well below the memory the honest algorithm uses, for Argon2i-A (the Password Hashing Competition winner), Argon2i-B (the version proposed to the Internet Research Task Force as a password-hashing standard), and Balloon Hashing. An iMHF's evaluation corresponds to pebbling a directed acyclic graph (DAG) in which each node is a memory block and each edge is a data dependency: computing a node's label requires holding its parents' labels in memory. The attack, extending Alwen and Blocki's CRYPTO 2016 construction, computes a small depth-reducing set S of graph nodes such that deleting S from the DAG leaves only short paths; an attacker recomputes the values in S on demand instead of storing them, trading extra computation for a large memory reduction, at attack quality (the ratio of the honest algorithm's cost to the attack's amortized cost, where a ratio above 1 counts as a working attack) that grows with the number of memory blocks. The paper's own contribution is threefold: extending the theoretical attack to Argon2i-B (not previously analyzed), for which it proves attack quality Θ(N^0.2) by constructing a depth-reducing set of size Θ(N^(4/5)) that leaves a residual graph of depth N^(3/5) (N being the total number of memory-block computations, τ passes times σ table size); introducing heuristics — a smaller depth-reducing set construction and an "XOR compression" trick — that improve the attack's concrete efficiency even when the attacker's on-chip memory bandwidth is bounded; and simulating the attack on randomly sampled instances of all three algorithms to measure memory consumption for practical parameter ranges (up to 16-24 GB) and for varying limits on attacker parallelism. Cost is measured as energy complexity (an estimate of the physical energy an attack hardware implementation would consume), which the paper states tightly approximates area-time complexity for the class of attacks considered.

### Parameters
- Memory parameter σ (table size) and timing parameter τ (pass count): swept over n=στ ∈ {2^17, 2^18, ..., 2^24} and τ ∈ {1, 3, 4, 6, 10, 20} for Argon2i-B and BH; τ ∈ {1, 3, 4} for Argon2i-A.
- Compression-function output/label size B: 1024 bytes for Argon2i (Blake2b-based); 512 bytes for Balloon Hashing (except a 1344-byte variant using SHA3, not the one plotted).
- Attacker parallelism p, explicitly bounded in one experiment set: {25, 50, 100, 200, 500, 750, 1000} at fixed M=1GB; {25, 50, 100, 200, 500, 1000} in the fixed-runtime (n=2^24) variant.
- Assumed memory bandwidth per attacker compute core: 1.5 GB/s, taken as a reference point derived from an implemented Argon2i-B measurement of 5.8 GB/s on 4 cores.
- iXOR indegree: 21 (1 sequential parent plus 20 random parents), matching the original BH-Double-Buffer construction's indegree.
- Multi-lane example parameters: τ=4, σ=2^17, p=4 lanes (n=2^19).
- Number of random graph samples per data point: 10, with reported variation confined to the 2nd-3rd significant digit of measured attack cost.

### Stated limitations
The authors state their understanding of Argon2i-A and Argon2i-B security remains incomplete after this work, and list as open questions whether the attack on Argon2i-B can be further improved and whether a matching lower bound on Argon2i-B's energy complexity can be proved. They state the multi-lane attack result is not fully optimized: they conjecture attack quality on multi-lane Argon2i-A and Argon2i-B can be improved further with additional parameter and heuristic tuning, and explicitly leave this as future research rather than a result they establish. The paper notes it focuses its main simulation results on the single-lane variant of each iMHF because, combined with the "trivial" (independent-instance) approach to parallelism, single-lane constructions are more resistant to this attack than the Argon2i design's cross-lane parent-selection rule — meaning the headline attack-quality numbers understate the effect against the deployed multi-lane configuration. The authors state that prior observers (the Argon2 authors and others) had argued the original Alwen-Blocki attack does not threaten real-world Argon2 security because of large constants hidden in the asymptotic bounds and because a literal hardware implementation would need memory bandwidth beyond then-available technology; the current paper's stated purpose is to test, not assume, those objections, and it reports the concrete simulated numbers rather than asserting the asymptotic result alone.

### Requirements it places on the rest of the system
A system choosing Argon2i-B (or another data-independent MHF) as a password-hashing or key-stretching primitive must select the pass count τ knowing that quality-2 or better memory-reduction attacks exist against low pass counts at practical memory sizes (e.g., τ=6 at 1GB), so the choice of τ trades directly against user-perceived latency: the paper states that increasing τ multiplies running time by τ, and that human users have limited tolerance for authentication delay (on the order of 1-2 seconds cited as the tolerance window in the source text). Any parameter-selection procedure for this class of MHF needs an explicit joint choice of memory σ and passes τ; the paper states the IRTF proposal's own selection procedure (fix memory first from available hardware, then pick the maximum τ affordable in the time budget) tends to produce τ=1 in memory-rich or impatience-constrained deployments, which the measured results show is the parameter region most vulnerable to this attack. A deployment relying on the multi-lane parallel Argon2i construction for throughput must account for the measured finding that cross-lane parent selection reduces attack resistance relative to running independent single-lane instances in parallel; choosing single-lane Argon2i and parallelizing across independent instances instead preserves the stronger resistance this paper measures. Any claim that a hardening technique (such as XOR-and-high-indegree) increases attacker cost needs re-verification under this paper's optimized attack, because the XOR-compression heuristic introduced here is shown to substantially reduce the naive cost increase that technique otherwise imposes.

### Contradicts
The paper contradicts the informal industry consensus, attributed in its own text to the Argon2 designers (Biryukov, Dinu, Khovratovich) and to Khovratovich and Aumasson, that the original Alwen-Blocki (CRYPTO 2016) attack "does not present a threat to the real world security of Argon2-B (or BH)" because of large asymptotic constants and infeasible hardware bandwidth requirements; this paper's simulated results show the attack reduces cost by a factor of 2 against Argon2i-B at 1 GB memory and τ=6 passes, within the IRTF proposal's own recommended parameter space, and states the IRTF proposal's security analysis had omitted this attack from consideration. No contradiction with another paper in this corpus was found (BIRYUKOV-EUROSP-16, the Argon2 paper itself, is the object of this critique rather than an independent measurement disagreement — see BIRYUKOV-EUROSP-16's entry for the corresponding attribution).
