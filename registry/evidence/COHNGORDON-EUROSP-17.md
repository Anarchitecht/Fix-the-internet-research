## [COHNGORDON-EUROSP-17] A Formal Security Analysis of the Signal Messaging Protocol
**Citation:** Katriel Cohn-Gordon, Cas Cremers, Benjamin Dowling, Luke Garratt, Douglas Stebila. "A Formal Security Analysis of the Signal Messaging Protocol." IEEE European Symposium on Security and Privacy (EuroS&P), 2017; extended version, Journal of Cryptology, 2020. DOI: 10.1007/S00145-020-09360-1 / 10.1109/EUROSP.2017.27.
**Retrieved:** full text via https://eprint.iacr.org/2016/1013.pdf (extended version, dated July 2019, superseding the EuroS&P 2017 proceedings paper)
**Source URL:** https://eprint.iacr.org/2016/1013.pdf
**Domain:** H

### What it does
The paper gives the first formal cryptographic security proof of the Signal protocol's core: the X3DH (Extended Triple Diffie-Hellman) initial key exchange composed with the Double Ratchet, the mechanism by which two Signal parties derive and continually refresh a sequence of shared symmetric keys, one per message stage, without both parties needing to be online at the same time. The paper builds a security model as a multi-stage Authenticated Key Exchange (AKE) protocol, in which a session progresses through a tree of stages rather than a linear sequence (a party may branch into a new asymmetric-ratchet stage while a symmetric-ratchet chain continues elsewhere in the same session), and proves (Theorem 1) that no efficient adversary can distinguish a genuine Signal message-encryption key from random, under the Gap Diffie-Hellman (GDH) assumption and modeling every key-derivation function used as a random oracle. The proof is structured as a sequence of cryptographic games, handling each of Signal's six distinct message-key types separately (named triple, triple+DHE, asym-ir, asym-ri, sym-ir, sym-ri, corresponding to the initial handshake variants and the two asymmetric-ratchet substages and the two symmetric-ratchet directions).

Mechanically, Signal derives its initial shared secret (the "triple" or "triple+DHE" handshake) from three or four Diffie-Hellman (DH) computations between a set of long-term, medium-term, and one-time public keys the two parties exchange via a prekey server that only stores and relays data, performing no computation of its own. After the initial handshake, keys evolve through two ratchet mechanisms. Symmetric ratcheting derives each new message key by applying a Key Derivation Function (KDF) to the current chain key alone, without incorporating any new randomness — cheap, but unable to recover once a chain key is exposed. Asymmetric ratcheting periodically injects a fresh DH shared secret (computed from a newly generated ratchet key pair and the peer's most recent ratchet public key) into the root key, in two substages the paper labels asym-ri and asym-ir; this is the step that gives the protocol forward secrecy against a compromise of stored chain-key state and, if the compromised party subsequently performs an update without adversarial interference, restores security to later stages (a form of Post-Compromise Security, PCS, per the paper's own earlier definition cited from Cohn-Gordon, Cremers, Garratt).

### Measured results
None — this is a formal-methods paper. Its result is a security proof (Theorem 1), not an empirical measurement, benchmark, or implementation study. The one quantitative figure the paper itself derives and states explicitly is the non-tightness factor of its own security reduction: the proof loses a multiplicative factor of at least (n_P² · n_S) relating the adversary's advantage against Signal to its advantage against the underlying Gap Diffie-Hellman problem, where n_P is the number of parties and n_S is the number of sessions per party in the security experiment. The paper states this factor arises because the reduction must guess in advance which specific session the adversary will target as its "Test session," among polynomially many candidate sessions, and that no known technique produces a tight reduction for a protocol with Signal's structure. The paper states directly that instantiating Signal with key sizes large enough to make this loose reduction's guarantee numerically meaningful would need computational cost incompatible with parameter sizes Signal deployments actually use on mobile devices, so the proof is offered as a qualitative soundness indicator and a structural starting point for tighter future proofs, not as a basis for a concrete numeric security-level recommendation.

**Formally identified attack surviving the proof's own excluded-attack analysis:** the paper's vertex-cover analysis of the initial handshake (its Figure 3) proves that an adversary who learns exactly Bob's signed prekey (prekB) and Alice's ephemeral key (ekA) — one specific, non-trivial two-key compromise pattern out of all possible compromise combinations — can compute the session key. Because Signal's initial handshake includes no DH edge directly binding Alice's identity key to Bob's identity key, and because Alice's ephemeral key is not itself authenticated, an adversary who has obtained prekB can generate its own ekA and successfully impersonate Alice to Bob; the paper identifies this by name as the Key Compromise Impersonation (KCI) attack, and states it is not excluded by their model, remaining possible even against the strengthened "triple+DHE" variant of the handshake.

### Parameters
Not applicable in the sense of a tested experimental range — the paper reports one formal model with one proof, not a swept parameter study. The values load-bearing for the model itself: six distinct stage types are modeled separately (triple, triple+DHE, asym-ir, asym-ri, sym-ir, sym-ri); the reduction's stated non-tightness factor is (n_P² · n_S), where n_P is the adversary-controlled bound on party count and n_S the bound on sessions per party, both symbolic bounds in the security experiment (Figure 8 in the paper) rather than concrete deployment numbers.

### Stated limitations
The paper devotes a full section (Section 6) to explicit scope exclusions, distinct from open future work. It does not analyze non-Signal library components present in the open-source reference implementation but not used by Signal itself (for example, header encryption used by Pond, and support for online key exchange bypassing the prekey server). It assumes honest distribution of long-term and medium-term public keys and does not analyze Signal's out-of-band fingerprint verification channel, the mechanism intended to reduce trust in the prekey server. It does not prove security of Signal's reuse of the same identity key for both Curve25519 Diffie-Hellman agreement and Ed25519 signing of medium-term prekeys — the paper conjectures a proof is possible by analogy to prior work proving security of a similar dual-use scheme, but instead sidesteps the question by omitting prekey signatures from the model and enforcing prekey authentication directly in the security game, which the paper states means the model does not capture the attack class in which an adversary corrupts an identity key and then inserts a maliciously signed prekey. It does not model the storage of out-of-order message keys (needed to decrypt messages that arrive out of sequence), which the paper notes reduces forward security in practice by extending how long a compromised key stays sensitive. It does not model Signal's simultaneous-session-initiation tie-breaking mechanism. It excludes group-messaging security properties, cross-device message sharing, voice/video call security, 0-round-trip efficiency modes, privacy, and deniability from its scope entirely, stating each is a distinct property Signal may or may not provide but that this analysis does not examine; it explicitly cites Rösler, Mainka, and Schwenk's separate study of group-chat implementation vulnerabilities as the two-party/group distinction this paper does not cross. It does not consider side-channel attacks or the security properties of specific primitive implementations (for example, a particular elliptic-curve implementation), assuming instead that each primitive meets its standard idealized security property. The paper states an unresolved gap for a widely deployed application variant: WhatsApp's re-transmission mechanism resends a message under a peer's new identity key whenever that key appears to change, which the paper states means an adversary controlling identity-key registration can disconnect a party and substitute a new key so a sender's client automatically re-sends the message to the adversary — a concrete, named vulnerability in an application-layer deployment choice, not in the Signal cryptographic core this paper proves secure. The paper states as future-strengthening advice (already communicated to Signal's developers, per the acknowledgments) that Signal's security against a fully predictable random-number generator could be improved at negligible cost using a NAXOS-style construction or by mixing in a static-static DH shared secret.

### Requirements it places on the rest of the system
Signal's asynchronous operation requires a prekey distribution server that stores and relays prekeys and messages but performs no cryptographic computation of its own — the paper's proof depends on this server being untrusted for message secrecy (any active-adversary manipulation of prekey delivery is within the modeled threat model) but implicitly relies elsewhere on that server, or an out-of-band channel the paper does not itself analyze, to distribute long-term and medium-term public keys honestly. Post-compromise recovery (a party regaining security after a state compromise) requires that party to complete at least one subsequent asymmetric-ratchet update without further adversarial interference — the paper's proof structure ties PCS strictly to the asymmetric, DH-based ratchet stages, not the symmetric ratchet, so any system relying on Signal's PCS property must ensure asymmetric ratchet updates continue to occur, not just symmetric chain advancement. Binding a derived key to both parties' identities requires an application-layer step outside the Signal core the paper analyzes: the paper's own UKS (Unknown Key Share) discussion states the core protocol's derived keys do not depend on peer identities, so any system needing protection against unknown-key-share confusion (a session key shared with an unintended party being mistaken for one shared with the intended party) must independently bind identity information — for example, a phone number — into its own initial message exchange, a requirement the Signal core itself does not discharge. A system requiring resistance to key-compromise impersonation must treat this as unresolved by Signal's core proof: the paper's own vertex-cover analysis leaves open a specific two-key compromise pattern (a responder's signed prekey together with an initiator's unauthenticated ephemeral key) under which impersonation succeeds, so any higher-level component assuming Signal sessions cannot be impersonated under partial key compromise is assuming a property this proof does not establish.

### Contradicts
None found within this corpus regarding the paper's own proven claims. The paper's own analysis narrows a claim commonly attributed to Signal — that it is broadly secure against key compromise — by formally demonstrating a specific residual Key Compromise Impersonation attack (compromise of a responder's signed prekey plus an unauthenticated initiator ephemeral key) that the model does not exclude even under the strengthened "triple+DHE" handshake variant; this qualifies rather than reverses the paper's headline result that Signal's core is a secure multi-stage AKE protocol under GDH and the random-oracle model. It corroborates, rather than contradicts, COHNGORDON-CSF-16's finding that the TextSecure deployment of the ratchet mechanism failed to achieve PCS in practice (a multi-device implementation issue), by independently identifying, through the Frosch et al. citation, the same Unknown Key Share attack against TextSecure v3 as a distinct, non-overlapping authentication weakness this paper's own model also does not by itself prevent.
