## [ATTIYA-PODC-16] Specification and Complexity of Collaborative Text Editing
**Citation:** Hagit Attiya, Sebastian Burckhardt, Alexey Gotsman, Adam Morrison, Hongseok Yang, Marek Zawirski. "Specification and Complexity of Collaborative Text Editing." ACM Symposium on Principles of Distributed Computing (PODC), 2016. DOI 10.1145/2933057.2933090.
**Retrieved:** full text via https://www.cs.technion.ac.il/~hagit/publications/podc16.pdf
**Source URL:** https://doi.org/10.1145/2933057.2933090
**Domain:** D

### What it does
The paper gives a formal correctness definition for a replicated list object — the abstraction underlying collaborative text editing, where each list element represents one inserted unit such as a character or line — and proves a worst-case lower bound on the memory any correct implementation must retain. Two specifications are defined over abstract executions consisting of insert, delete, and read operations and a visibility relation between them. The strong list specification requires a single global, transitive, irreflexive, total list order over all inserted elements such that every read returns exactly the elements visible to it and not yet deleted, in an order consistent with that one global order; this rules out an element deleted earlier resurfacing in a different relative order once its neighbors change. The weak list specification relaxes this: the list order is required to be acyclic only among the specific elements a given read returns, so orderings that involve an already-deleted element may form cycles without violating the specification, permitting more implementation behaviors (for example, two different reads observing "ab" and "ba" for the same pair of characters once an interleaving element between them has been deleted). Both specifications imply eventual consistency for protocols that additionally guarantee eventual visibility (every operation eventually becomes visible to all but finitely many future events). The paper reformulates the RGA (Replicated Growable Array) protocol using a timestamped-insertion (TI) tree — a tree data structure that never removes or modifies nodes, only adds them, so that convergence follows directly from set union being associative and commutative regardless of message-delivery order — and proves RGA implements the strong list specification. The paper's central negative result targets "push-based protocols," a formally defined class requiring that every insertion generates an outbound message immediately, every first-observed deletion of an element generates an outbound message immediately, and every operation observes every operation that happened-before it (Definition 13); this class is shown to contain both operation-based protocols (messages carry a description of the operation) and state-based protocols (messages carry full state), and to contain deployed eventually-consistent write-propagating protocols generally, under the assumption that sending a message does not itself change the sender's list state.

### Measured results
This is a formal-methods paper with no implemented system and no empirical benchmark; its results are theorems with proofs, not measurements from a run. The reported quantities are asymptotic bounds, each tied to a stated protocol class and a stated number of replicas:

| Result | Conditions |
|---|---|
| Metadata overhead of any push-based protocol satisfying the weak or strong list specification is Ω(D) | D = number of deletions in the execution; requires n ≥ 3 replicas; holds under causal atomic broadcast (proved via an information-theoretic encoding argument constructing 2^d distinct single-replica states from d-bit strings, for d = ⌊(D-2)/2⌋, forcing at least one state to require d bits) |
| Metadata overhead of RGA over an execution is O(D lg k) | D = number of deletions, k = number of operations in the execution; RGA is proved to satisfy the strong list specification (Theorem 1) |
| The Ω(D) lower bound extends to push-based client/server protocols, applying to the client's metadata overhead | n ≥ 3 replicas; proved by showing a broadcast protocol can simulate a client/server protocol via state machine replication (Proposition 10), then applying the D ≥ 4 lower-bound execution to the simulating protocol (Corollary 11) |

Metadata overhead is formally defined (Definition 11) as the ratio, at a given replica state, of the bit-size of internal (user-unobservable) metadata to the bit-size of the user-observable list contents at that state; the worst-case metadata overhead of a protocol is the largest such ratio over any replica state in any execution in the considered class.

### Parameters
- The lower bound (Theorem 5) requires n ≥ 3 replicas and D ≥ 4 deletions; below D = 4 no bound is stated.
- The lower-bound construction uses d = ⌊(D-2)/2⌋ as the encoded bit-string length, giving Ω(D) via 2^d distinct forced replica states.
- RGA's upper bound is stated as O(D lg k) with no numeric constant given; the paper states the gap between this O(D lg k) upper bound and the Ω(D) lower bound is left open.
- The broadcast model assumed is causal atomic broadcast: causal ordering, no duplicate delivery, and consistent global delivery order across replicas; the paper states its lower bound is strengthened, not weakened, by assuming this idealized broadcast "for free," since a weaker underlying network would only add further metadata cost to implement broadcast.

### Stated limitations
The lower bound applies only to the defined class of push-based protocols; the paper states that relaxing this restriction (protocols that do not send a message immediately upon every insertion or first deletion) is left for future work, so the bound does not, as proved, cover consensus-mediated or batching protocols outside that class. The gap between the Ω(D) lower bound and RGA's proved O(D lg k) upper bound is stated as unresolved — the paper does not claim RGA is asymptotically optimal, only that it is close. The weak list specification's applicability to the Jupiter protocol is stated as a conjecture ("we conjecture that Jupiter satisfies the weak specification"), not a proof. The paper states its specifications model only a flat list object and do not cover richer collaborative-editing systems such as shared structured documents (the paper cites XML editing as an example); it states the lower bound would still apply to such systems but that additional features might induce additional complexity beyond what is analyzed. The client/server extension (Corollary 11) is derived by simulation from the broadcast-model result rather than analyzed as a separate protocol class with its own network assumptions, and the paper states exploring client/server systems more directly is future work, noting only that some deployed client/server systems do not implement the strong specification and that this result suggests that relaxation does not, by itself, give those systems a complexity advantage over strong-specification protocols.

### Requirements it places on the rest of the system
Any protocol this lower bound governs must supply causal broadcast at minimum — the paper's model requires that if send(m) happens-before send(m′), no replica receives m′ before m — and the paper's results are proved to hold even under the strictly stronger causal atomic broadcast (adding no-duplicate-delivery and a single consistent global delivery order across all replicas), so a system that only provides causal broadcast inherits the same Ω(D) floor without needing atomic broadcast. A push-based protocol, by the paper's Definition 13, must generate an outbound message immediately after every insertion and after every deletion that is the first observed deletion of its element; a design that defers or batches these outbound messages exits the class this lower bound is proved for, and the paper does not state what bound, if any, applies outside it. RGA's proof of the strong list specification depends on its state being representable as a strictly-growing set of tree nodes (never modified or removed once added) combined under set union, which is associative and commutative independent of delivery order; a component wishing to reuse RGA's convergence guarantee must preserve this append-only structural property and must not garbage-collect or mutate tree nodes outside the mechanism the paper analyzes. The client/server simulation result (Proposition 10) requires the underlying transport to satisfy causal atomic broadcast among the simulating replicas for the simulation to correctly reproduce the client/server protocol's executions.

### Contradicts
None found within this corpus. The paper's own related-work section states that Treedoc and Logoot (cited comparison protocols) have worst-case metadata overhead linear in the number of deletions, consistent with — not contradicting — this paper's Ω(D) lower bound, and states that operational-transformation protocols storing a full update log have metadata overhead at least linear in the number of updates for the same reason.
