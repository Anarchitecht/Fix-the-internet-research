## [GREGORIADIS-ARXIV-25] SwarmSearch: Decentralized Search Engine with Self-Funding Economy

**Citation:** Marcel Gregoriadis, Rowdy M Chotkan, Petru Neague, Johan Pouwelse. "SwarmSearch: Decentralized Search Engine with Self-Funding Economy." arXiv:2505.07452, 2025.
**Retrieved:** full text via https://arxiv.org/abs/2505.07452
**Source URL:** https://arxiv.org/abs/2505.07452
**Domain:** B

### What it does
The paper funds a decentralized web-scale search system through voluntary donations rather than query fees, and separately resists both training-data poisoning and Sybil manipulation of the donation-allocation mechanism. Every participating node runs three components. First, retrieval: each node fine-tunes a local encoder-decoder transformer model (built on De-DSI, a prior decentralized generative-retrieval design) that maps a query directly to document identifiers via beam search; a querying user sends a query to multiple agents, each returns its own beam of (docid, logit-score) pairs, the querying user runs its own model too, all beams are softmax-normalized and merged by summing scores for identical docids, and the top-k merged docids proceed to ranking. Second, ranking: each node runs DART, a lightweight local learning-to-rank model mapping query-document feature vectors to a relevance score, trained offline so ranking adds no network latency. Third, feedback: a user's click on a result is treated as a positive relevance label for that document and an implicit negative label for every other result shown; click logs are exchanged with other peers as training data. Because peers can inject fabricated click logs to increase their apparent value, each node applies Data Shapley -- a game-theoretic method that estimates a dataset's marginal contribution to a model's held-out performance by comparing model quality with and without that dataset, approximated via Monte Carlo sampling of dataset subsets -- to value each shared dataset against the receiving user's own historical clicks as ground truth, and discards datasets whose estimated marginal contribution is not positive. Financially, users may donate Bitcoin or stablecoins at will; a donor allocates funds using MeritRank, a personalized reputation algorithm run over a locally maintained feedback graph (weighted by observed retrieval accuracy, ranking accuracy, and shared-data value), combined with weighted random sampling without replacement over that graph so that low-reputation nodes retain a non-zero chance of receiving a donation.

### Parameters
- Retrieval model: T5-base, 220 million parameters, fine-tuned per corpus size (100 / 1,000 / 5,000 documents)
- Beam search size: 5 or 10 docids returned per agent per query (paper states "e.g." for these values, not fixed)
- Neighbor count for data-sharing experiment: 10 randomly sampled users per test user, stated as chosen because "preliminary experiments revealed converged performance with this number"
- Minimum clicklogs per user for inclusion: 3
- Personal dataset split ratio: 1:1:1 train:validation:test, chosen to maximize the number of users meeting the minimum-data threshold
- Data Shapley: Monte Carlo approximation, permutation sample size = 100
- Adversarial share n: swept over all integers 0-10 out of 10 shared datasets (label-flipping poisoning attack)
- MeritRank donation weighting: W_j = (R_j + epsilon)^alpha; epsilon prevents zero probability for low-ranked nodes; alpha controls sharpness of merit preference; alpha and epsilon swept across the five Sybil-resilience scenarios (values given above)
- Sybil-simulation network size: 1,000 user nodes; Sybil fraction swept 0-100%
- BM25 candidate-document window: size 10, centered on the position of the clicked document in a BM25-ranked list, used to reconstruct non-clicked candidates missing from the AOL dataset (following Guo et al.'s methodology)

### Stated limitations
The paper states single-model top-1 retrieval accuracy degrades as corpus size grows from 100 to 5,000 documents, and explicitly frames this as tolerable rather than solved: the correct document "may still appear in a top-5 or top-10 beam search" even when it falls out of the top-1 position, deferring correction to the downstream ranking stage rather than fixing retrieval itself. The Shapley-value defense is stated to itself degrade under extreme adversarial share (MRR drops below local-only performance at 90% poisoned datasets), attributed to Monte Carlo approximation error in the Shapley estimate, which the paper states "could be reduced by employing larger sample sizes or more efficient algorithms" -- an unevaluated fix. The paper states that eliminating stochastic inclusion of low-reputation nodes (epsilon=0) sharply reduces Sybil donation capture but "implies reduced robustness to newcomers," an explicit tradeoff the paper does not resolve. Under aggressive reward-skew weighting (alpha=1.5) the paper states the system "becomes vulnerable" once Sybil nodes escape the lowest reputation tier by inflating utility scores within isolated Sybil clusters. The training/test split for the retrieval-accuracy experiment retains duplicate query-docid pairs across train and test sets, which the paper states is "atypical when evaluating the quality of machine learning models," justified only as an attempt to capture realistic repeated-query usage patterns, not validated against a duplicate-free split. Future work is stated as scalability and privacy-preserving techniques, both unaddressed in this paper; deployment inside the Tribler peer-to-peer file-sharing client is stated as in progress, not complete.

### Requirements it places on the rest of the system
Every retrieving node must locally hold a trained generative-retrieval model (De-DSI-style) whose output vocabulary spans candidate document identifiers, and a merge step requires numerically comparable per-agent beam scores (achieved here via per-agent softmax normalization before summing across agents) -- an agent returning scores on an incompatible scale corrupts the merge. Data Shapley valuation requires each receiving user to already hold a local ground-truth signal (their own historical clicks) against which an incoming dataset's marginal contribution is measured; a node with too little click history cannot value incoming data and the paper's own experiment excludes users below 3 clicklogs for this reason. MeritRank's donation allocation requires each node to maintain a persistent local feedback graph recording observed retrieval accuracy, ranking accuracy, and data-sharing value for every peer it has interacted with; a donor with no feedback history for a peer cannot include that peer in its weighted sampling pool (the sampling set S is explicitly restricted to nodes with non-zero reputation in the donor's local view). The Bitcoin/stablecoin donation mechanism requires an underlying payment rail capable of executing the donor's chosen transfers to the sampled recipient set; the paper does not specify settlement mechanics beyond citing MeritRank for the allocation weights.

### Contradicts
The claim "robust under 50% adversarial nodes" (as the paper's own abstract states it) applies specifically to Data-Shapley-filtered ranking-data poisoning resistance, holding MRR flat only up to that share; it does not describe the donation mechanism's Sybil resistance, which the paper's own Figure 4 shows varies continuously with Sybil share and with mechanism configuration (alpha, epsilon) rather than holding a hard threshold. Applying the 50% figure to the financial/donation layer, rather than to the ranking-data poisoning defense specifically, is not supported by the paper's text. No other corpus entry directly disagrees with this paper's measurements as of this batch.
