## [COHNGORDON-CCS-18] On Ends-to-Ends Encryption: Asynchronous Group Messaging with Strong Security Guarantees
**Citation:** Katriel Cohn-Gordon, Cas Cremers, Luke Garratt, Jon Millican, Kevin Milner. "On Ends-to-Ends Encryption: Asynchronous Group Messaging with Strong Security Guarantees." ACM SIGSAC Conference on Computer and Communications Security (CCS), 2018. Pages 1802-1819. DOI: 10.1145/3243734.3243747.
**Retrieved:** full text via https://eprint.iacr.org/2017/666.pdf (version 2.3, March 2020 — the paper's own posted revision)
**Source URL:** https://eprint.iacr.org/2017/666.pdf
**Domain:** H

### What it does
Asynchronous Ratcheting Trees (ART) let a group of message-application users derive a shared symmetric group key without requiring any two members to be online at the same time, while giving the group Post-Compromise Security (PCS — from the paper's own earlier definition, the guarantee that a party recovers a secret channel after a key compromise once that party takes a further protocol step, without needing to detect the compromise first). ART builds the group key from a binary tree of Diffie-Hellman (DH) key pairs, one leaf per group member. Each internal node's secret is the DH combination of its two children's secrets (a group element mapped back to an integer via a function the paper calls ι, so the combined value itself becomes usable as a new DH secret at the next level up); the tree root's secret, called the tree key, derives the current stage key by hash-chaining it with the previous stage key, and the stage key is the group's shared symmetric key.

A group creator who is the only party online generates a fresh DH key pair for every other member's leaf directly (using a one-round authenticated key exchange run against each future member's published prekeys, so the creator alone can compute the whole tree even though nobody else has connected yet), then broadcasts every public key in the tree. Any later member computes the tree key by combining their own leaf secret with the public keys along their copath (the sibling nodes on the path from a leaf to the root), needing only O(log n) DH exponentiations for a group of n members. To achieve PCS, a member updates by drawing a fresh leaf secret, recomputing every node secret on the path from that leaf to the root, and broadcasting the updated public keys on that path; any other member combines the broadcast updates with their own copath knowledge to recompute the same new tree key. Because only path nodes change, an update costs the updater O(log n) exponentiations and every other member O(log n) exponentiations to process it, rather than the O(n) a fully re-run group key exchange would need.

### Measured results

**Asymptotic comparison (Table 1), derived, not measured, comparing ART against two deployed designs at group size n, sender/other split for setup and steady-state ("ongoing") operation:**

| Design | Setup exponentiations (sender / other) | Ongoing exponentiations (sender / other) | Ongoing symmetric encryptions (sender / other) | Ongoing bandwidth (sender / other) | PCS |
|---|---|---|---|---|---|
| Sender Keys (WhatsApp, Facebook Messenger group mode) | O(n) / O(n) | 0 / 0 | 1 / 1 | O(1) / O(1) | No |
| Pairwise Signal (Apple iMessage, Signal's own app) | O(n) / O(n) | O(n) / O(1) | n-1 / 1 | O(n) / O(1) | Yes |
| ART (this paper) | O(n) / O(log n) | O(log n) / O(log n) | 1 / 1 | O(log n) / O(log n) | Yes |

**Implementation benchmark:** ART implemented in Java, compared against pairwise Signal-style Double Ratchet channels, both using 32-byte messages (sized to carry an AES-256 key), on a 2016 MacBook Pro (3.3 GHz Intel Core i7, 16 GB RAM), averaged over four runs. Reported directly in text: setup and per-message sending both complete in a few milliseconds for a group of 10, and on the order of one second for a group of 1,000. Bandwidth: ART's per-message outgoing bytes stay below pairwise Signal's at every measured group size from roughly 10 to 1,000 participants (Figure 7a, read from the log-log plot; the paper states no closed-form numeric values beyond the qualitative comparison). Setup wall-clock time: ART is consistently slightly slower than pairwise channels at the same group sizes but follows the same asymptotic growth curve (Figure 7b); the paper attributes ART's higher constant factor to the tree creator's linear (not logarithmic) initiator-side work, versus pairwise's quadratic effort spread evenly across all members.

**Formal verification:** a Tamarin model (unbounded number of parties, protocol instances, and group members) verifies that an agent's initial derived group key stays secret provided no group member the agent believes is present has been compromised; the model check completes in approximately 15 minutes on what the paper describes only as "a modern desktop," without further hardware specification.

### Stated limitations
The paper explicitly places four problems out of scope and names why: sender-specific authentication (proof of which specific group member sent a message under the shared key) is not provided, because ART omits per-sender signature keys by design choice, so any group member can produce a message indistinguishable in origin from any other member's; malicious-insider security for subsets of a group (m < n honest members) is not addressed, deferred to prior GKE work by Abdalla, Chevalier, Manulis, and Pointcheval; executability under concurrent, conflicting key updates (two members updating simultaneously) is not solved — the paper offers two informal mitigations (a short grace window accepting messages under a stale key, or transport-layer rejection of out-of-order updates) but states a complete solution is an open research question; transcript agreement (all members agreeing on the ordered list of sent and received messages) is not covered. A malicious group creator can silently add an undetected eavesdropper to a newly created group, an attack the paper considers out of scope on the grounds that any group member could republish plaintext regardless of protocol design. Asynchronous group creation carries a stated security cost: if the creator is compromised during the initial creation phase before any other member has come online, all resulting stage keys stay insecure until every group member has independently performed at least one key update; the paper documents this explicitly as an increased requirement captured in its formal freshness predicates, not something ART eliminates. The bandwidth comparison found that ART's true byte count over the network can exceed pairwise channels' when broadcast is implemented via server-side fanout, because every recipient receives and processes a full logarithmic-size update rather than the constant-size message pairwise delivery sends per recipient; ART's advantage is lower per-agent sending latency, not lower total network bytes. The Java implementation and Tamarin proof are stated deliverables, but the paper does not benchmark against the Sender Keys design at all, stating this omission directly on the grounds that Sender Keys does not achieve PCS and so is not a comparable security target.

### Requirements it places on the rest of the system
ART requires a one-round authenticated key exchange protocol (used by the group creator to derive each future member's leaf secret from that member's published prekeys) but states no specific structural requirement on that sub-protocol beyond it being a strong one-round Authenticated Key Exchange (AKE). It requires every group member to maintain a persistent local view of the DH tree's public-key structure (its own copath) between sessions, since a member computes the tree key from its own leaf secret combined with copath public keys, not from any message content alone. It requires reliable broadcast of updated public keys to the whole group after every member update — the paper's own stated mitigations for concurrent updates (a grace-period buffer, or transport-layer rejection of stale updates) require either a relaxation of key-freshness guarantees or an ordering-enforcing transport layer, meaning the choice of transport directly trades off availability against key-lifetime exposure. It assumes an untrusted server may only reorder or drop messages, never forge signed or MAC-authenticated update messages, since ART authenticates the initial group-setup message with a digital signature and every subsequent update with a MAC. It does not authenticate individual senders within an update (no per-sender signature key), so any system layering identity attribution or accountable messaging on top of ART must supply that separately; the paper flags this explicitly as future extension territory (Section 8), not a built-in property. It assumes DH-group hardness (the paper's PRF-ODH assumption) as its sole computational hardness basis and offers no post-quantum variant.
