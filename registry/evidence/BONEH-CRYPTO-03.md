## [BONEH-CRYPTO-03] Aggregate and Verifiably Encrypted Signatures from Bilinear Maps
**Citation:** Dan Boneh, Craig Gentry, Ben Lynn, Hovav Shacham. "Aggregate and Verifiably Encrypted Signatures from Bilinear Maps." EUROCRYPT, 2003. DOI 10.1007/3-540-39200-9_26.
**Retrieved:** full text via https://crypto.stanford.edu/~dabo/pubs/papers/aggreg.pdf
**Source URL:** https://doi.org/10.1007/3-540-39200-9_26
**Domain:** E

### What it does
An aggregate signature scheme compresses n signatures, on n distinct messages, from n distinct signers, into one signature the same size as a single signature, so a verifier holding all n public keys and all n messages can check every signature at once from that one compressed value. This differs from a multi-signature, which combines signatures on one shared message from many signers; aggregate signatures instead combine signatures on distinct messages, which the certificate-chain and Secure BGP (SBGP, a routing protocol in which each router signs its segment of a path) applications the paper targets require.

The construction uses two cyclic groups G1 and G2 of the same prime order, an efficiently computable isomorphism from G2 to G1, and an efficiently computable bilinear pairing e: G1 x G2 -> GT. A user's private key is a random scalar x in Zp; the public key is v = g2^x in G2. To sign message M, the signer computes h = H(M) (a full-domain hash into G1, modeled as a random oracle) and outputs the signature s = h^x, an element of G1. Verification checks e(s, g2) = e(h, v). Any party — not necessarily a signer or a trusted party — can aggregate a set of individual signatures {s_1,...,s_k} on distinct messages {M_1,...,M_k} by computing s = product of the s_i, an element of G1 the same size as one signature. Aggregate verification recomputes h_i = H(M_i) for each message and accepts if e(s, g2) equals the product over i of e(h_i, v_i); the bilinear map's multiplicative property makes this equation hold exactly when every individual signature was valid. Aggregation is incremental: an aggregate of two signatures can later be combined with a third.

A rogue-key attack is possible in this scheme: an attacker who has seen a target's public key v_A can publish a public key v_B = v'_B / v_A for a key pair (x'_B, v'_B) it does actually hold, after which H(M)^(x'_B) verifies as an aggregate signature on M by both the target and the attacker, without the target ever having signed M. The paper's defense is to require every message in an aggregate to be distinct — enforced at verification by rejecting any aggregate whose message list contains a repeat — rather than requiring signers to prove knowledge of their private key, and this restriction alone suffices for the paper's security proof.

The paper additionally builds two derived constructions from the same aggregate scheme. A verifiably encrypted signature lets Alice give Bob an encryption, under a third party's public key, of her signature on a message, together with a proof the encryption is valid, so Bob is convinced Alice signed but cannot read the signature itself until the third party (the adjudicator) later decrypts it; the construction relies on an assumption that individual signatures cannot be extracted from a k-element aggregate signature by anyone without the adjudicator's private key. A ring signature lets any one member of a group of n public keys produce a signature that verifies against the whole group without disclosing which member signed; the paper's version modifies the base signing equation (using h^(1/x) instead of h^x) and lets anyone convert an ordinary modified signature into a ring signature over an arbitrary superset of users, without needing the original signer's participation.

### Measured results
The paper is a construction and security-proof paper; it reports no implementation timing or throughput measurement. Its quantitative content is the security reduction's concrete parameters. Theorem 3.2 states the bilinear aggregate signature scheme is (t, q_H, q_S, N, epsilon)-secure against existential forgery in the aggregate chosen-key model, for all t and epsilon satisfying epsilon >= e*(q_S + N)*epsilon' and t <= t' - c_G1*(q_H + 2*q_S + N + 4) - (N + 1), given the underlying group pair (G1, G2) is (t', epsilon')-hard for the co-Diffie-Hellman problem. Here q_H is the number of hash-oracle queries, q_S the number of signing-oracle queries, N the maximum number of users in the forged aggregate, and c_G1 the time to perform one multiplication or inversion in G1. No concrete numeric values for these parameters are given; the paper states only the algebraic reduction.

### Parameters
- Group pair (G1, G2): prime order p, with an efficiently computable isomorphism from G2 to G1 and a bilinear pairing e: G1 x G2 -> GT; no concrete curve or key size is fixed by the scheme, unlike BONEH-ASIACRYPT-18's worked BLS381 example.
- N: maximum number of signers in a single forged aggregate, appears directly in the security-loss term of Theorem 3.2.
- q_H, q_S: hash-query and signing-query bounds given to the adversary in the security game; enter the reduction's running-time and advantage bounds algebraically.
- Distinct-message constraint: aggregate verification requires all messages M_1,...,M_k in one aggregate to be pairwise distinct; the paper states this can always be satisfied by prepending each signer's public key to the message before hashing, without changing signature or message length.
- k: aggregate extraction assumption (used for verifiably encrypted signatures) is stated for k >= 2, with some extensions in Section 4.5 relying on the assumption for k > 2.

### Stated limitations
The distinct-message restriction is required for the security proof and is not optional; an aggregate over repeated messages is rejected by AggregateVerify regardless of validity. The verifiably encrypted signature construction is stated to make the resulting contract-signing protocol not abuse-free, in the sense of a cited fair-exchange definition — meaning one party can gain an advantage by aborting the protocol partway through. The paper states it does not know how to build efficient aggregate signatures from general gap Diffie-Hellman groups (groups where the decisional Diffie-Hellman problem is easy but computational Diffie-Hellman is hard); the extra structure of a bilinear map, not just gap-group membership, is required. The ring signature construction's anonymity set is limited to the specific groups the signer or a later anonymizer chooses to include; the paper notes any signature can be further anonymized by adding users but assigns no bound on ring size.

### Requirements it places on the rest of the system
Every signature that will be aggregated must be over a message value produced by feeding the message through the shared full-domain hash function H into G1; a signer or protocol that hashes messages differently cannot participate in the same aggregate. The aggregator needs no private key and can be an untrusted third party, but it must have received every individual signature to be included and must have available every corresponding public key and message for whoever later verifies the aggregate; verification is not possible from the aggregate signature alone. The system must enforce message distinctness across every aggregate it accepts — either by protocol design (as in the certificate-chain and SBGP applications, where messages are naturally distinct) or by prepending each signer's public key to its message before signing. The verifiably encrypted signature construction requires an adjudicator entity holding a separate key pair, trusted to decrypt on request and assumed not to collude with either party in a way that defeats the opacity property; nothing in the scheme itself enforces that trust.

### References worth retrieving
- Micali, Ohta, Reyzin, "Accountable-subgroup multisignatures," extended abstract, ACM CCS 2001 — foundational (defines the multisignature security model this paper's aggregate chosen-key model is built to extend beyond a single shared message).
- Boldyreva, "Threshold signature, multisignature and blind signature schemes based on the gap-Diffie-Hellman-group signature scheme," PKC 2003 — competing (shows general gap Diffie-Hellman groups suffice for multisignatures; this paper argues the same groups are insufficient for efficient aggregate signatures, which is the contrast this paper's introduction draws explicitly).
- Boneh, Franklin, "Identity-based encryption from the Weil pairing," CRYPTO 2001 / SIAM J. Computing 2003 — foundational (the paper notes a message-signature pair in its co-GDH scheme has the same form as an identity-private-key pair in this IBE scheme).
- Rivest, Shamir, Tauman, (ring signatures using RSA and Rabin) — foundational (defines ring signatures and signer-ambiguity, the property this paper's Section 5 construction reproduces with bilinear maps).
- Zhang, Kim, (bilinear ring signature in an identity-based setting) — competing (an earlier bilinear-map ring signature construction the paper distinguishes its own construction from).
- Micali, Rivest, (open problem on cutting intermediate links from a certificate chain) — foundational (the paper states its certificate-chain compression application is related to this open problem, though it does not fully solve it: a verifier still needs to know all intermediate links).
