## [EPPSTEIN-SIGCOMM-11] What's the Difference? Efficient Set Reconciliation without Prior Context

**Citation:** David Eppstein, Michael T. Goodrich, Frank Uyeda, George Varghese. "What's the Difference? Efficient Set Reconciliation without Prior Context." ACM SIGCOMM, 2011. DOI 10.1145/2018436.2018462.
**Retrieved:** full text via https://www.ics.uci.edu/~eppstein/pubs/EppGooUye-SIGCOMM-11.pdf
**Source URL:** https://dl.acm.org/doi/pdf/10.1145/2018436.2018462
**Domain:** D

### What it does
The Difference Digest lets two hosts, each holding a set of keys, compute both one-sided set differences (the keys each holds that the other lacks) in a single round of communication, with communication cost proportional to the size of the symmetric difference rather than to the size of either set, and without either host knowing the difference size beforehand. It achieves this with two components: an Invertible Bloom Filter (IBF) that encodes a set into a small table supporting cell-by-cell subtraction between two IBFs, and a Strata Estimator that predicts the difference size before encoding so the sender can size the IBF correctly. An IBF is a table of n = alpha*d cells (alpha >= 1, d an estimate of the difference size), each cell holding three fields: idSum (the exclusive-or, XOR, of every element ID hashed into that cell), hashSum (the XOR of a second, independent hash of each such element ID, used as a checksum), and count (the number of elements hashed into that cell). Encoding an element hashes it to hash_count distinct cell indices and XORs its ID into idSum, XORs its checksum hash into hashSum, and increments count at each of those cells. Subtracting one IBF from another is done cell-by-cell: idSum values are XORed together, hashSum values are XORed together, and count values are subtracted (which can go negative). Because a common element hashes to the same cells in both IBFs, XORing its ID into idSum twice cancels it, so after subtraction, a cell contains information only about elements in the symmetric difference. A cell is "pure" when it holds exactly one such element: count equals +1 or -1, and the paper shows the hashSum field is needed to confirm purity because a count of 1 alone can be produced by a coincidental combination of multiple elements. Decoding repeatedly finds a pure cell, reads off the encoded element ID from idSum, removes that element from every cell it hashes to (by further cell-by-cell subtraction), and repeats until no pure cells remain; if all elements of the difference are recovered this way, decoding succeeds, otherwise decoding fails and the two hosts must retry with a larger IBF. The Strata Estimator builds a hierarchy of independently sampled, fixed-size IBFs (one "stratum" per hierarchy level), each stratum sampling a geometrically shrinking, hash-selected subset of the universe of possible keys, so that summing the decoded difference counts across strata gives an estimate of the total difference size using space proportional to the logarithm of the key universe size. A Hybrid Estimator variant augments the least-selective strata with a single Min-wise sketch (a set-similarity estimator built from k random permutation-minimum hash values) in the same space budget, to improve accuracy for large differences without sacrificing the Strata Estimator's accuracy for small ones. The KeyDiff service implements this as a generic Linux service over TCP with three calls: add a key, delete a key, and diff against a named remote host, and it maintains several precomputed IBFs of different fixed sizes in parallel, updated incrementally as keys are added or removed, so the correctly sized IBF can be selected once the difference-size estimate is known rather than built during the diff call itself.

### Measured results
Every dataset was generated as pairs of sets containing keys from a universe of all 32-bit values (12 bytes allocated per IBF cell: 4 bytes each for idSum, hashSum, and count); the first set SA was chosen randomly without replacement, the second set SB copied a random subset of SA, and each reported point was computed from 100 file pairs (an experiment counted as successful only if the entire set difference was recovered), except where a table states otherwise.

### Parameters
- Universe size U: all 32-bit values in the evaluation (u = 2^32); IBF cell fields sized 4 bytes each for idSum, hashSum, count (12 bytes/cell total).
- hash_count (number of cells each element hashes into): tested 2 through 6; paper recommends 3 for estimated differences above 200, 4 for smaller estimated differences, based on the measured decode-success and overhead results above.
- IBF sizing factor alpha (cells allocated per unit of estimated difference d): rule of thumb given is to size the phase-2 IBF at twice the phase-1 estimate ("twice the estimate found in the first phase") to cover both estimator under-estimation and decoding overhead.
- Strata Estimator cells per stratum: 80 cells per stratum used in the reported configuration, chosen because overhead reaches diminishing returns beyond 80 cells (Figure 8).
- Number of strata: floor(log2(d_max)) where d_max is the largest anticipated difference; 16 strata used for a d_max of 100K in the Strata-vs-Min-wise comparison; 7 strata plus 2,160 Min-wise hashes used in the Hybrid Estimator configured for a d_max around 2,000 (floor(log2(2000)) = 10, reduced to 7 to reallocate space to Min-wise).
- Scaling/correction factor applied to the raw estimator output to keep 99% of estimates at or above the true difference: 1.39 for the pure Strata Estimator at 80 cells/stratum; 1.45 for the Hybrid Estimator; a further scale of 1.25 to 2.3 applied in the second phase per the paper's configuration guideline.

### Stated limitations
The IBF decoding procedure can fail outright: the paper states decoding succeeds only "with high probability," and Figure 5/6/7 quantify failure directly — for example no IBF completely decodes at deltas of 45-50 with only 50 cells, and deltas below 200 require at least 50% space overhead over the difference size to reach 99% decode success. The Strata Estimator and IBF-based reconciliation as described assume both hosts use the same hash functions and agree on hash_count and cell counts in advance; the paper's model section states the method assumes SA and SB "are stored at two distinct hosts" with no discussion of more than two parties. The paper states no protection against or analysis of an adversarial or non-cooperating peer: the retrieved text contains no discussion of malicious key insertion, hash-function manipulation, or adversarial exploitation of the peeling-decode process (the failure modes GADUREK-SEA-26, elsewhere in this corpus, analyzes directly). CPISync is stated to require either foreknowledge of the difference size or an "interactive approach" at "greater computation and latency costs" when that size is unknown; the paper's own benchmark configured CPISync with foreknowledge, so the reported CPISync latency numbers are a best case. ART (Approximate Reconciliation Trees) is stated to recover only some, not all, of the difference in general, and the paper's own bandwidth comparison against ART used the arbitrary standard of 95% recovery with 99% reliability, calling ART's apparent bandwidth advantage at large deltas "misleading" for that reason. The precomputed-IBF approach that gives low diff-time latency requires maintaining multiple fixed-size IBFs in parallel per key, so every add or delete operation touches all of them; the paper states this adds 3.858 to 31.320 microseconds of latency per key update, depending on how many parallel IBFs are precomputed, as the cost of the fast diff path.

### Requirements it places on the rest of the system
Both hosts must agree in advance on the two hash functions Hc (checksum hash) and Hk (cell-index hash) and on the hash_count parameter, since decoding correctness depends on identical elements hashing to identical cell indices at both ends. The application must supply keys as fixed-size identifiers that fit the idSum XOR field (32-bit keys in the evaluation); the paper does not address variable-length elements in the retrieved text. A system deploying this for online reconciliation needs to maintain the IBF (and, for fast diff latency, multiple precomputed IBFs at different sizes) incrementally as keys are added or removed, since the paper's own measurements show building an IBF at request time from a stored list, rather than maintaining it online, costs seconds of server compute time (3,957.847 ms per response with 1M keys, no precomputation) versus tens of microseconds when precomputed. Because the Strata Estimator needs floor(log2(d_max)) strata sized to the anticipated maximum difference, the system must have some prior estimate of the plausible range of difference sizes to size the estimator; the paper does not describe a mechanism for handling a difference larger than the estimator was provisioned for beyond retrying with a larger structure. Decoding requires the peeling process to find at least one pure cell at each step; a system layering this over adversarial peers would need an external integrity check, since the paper's decode procedure trusts that a count of +-1 combined with a matching checksum indicates a genuine single element.
