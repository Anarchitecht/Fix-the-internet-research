## [GOMES-ARXIV-25] Rateless Bloom Filters: Set Reconciliation for Divergent Replicas with Variable-Sized Elements

**Citation:** Pedro Gomes, Carlos Baquero. "Rateless Bloom Filters: Set Reconciliation for Divergent Replicas with Variable-Sized Elements." arXiv preprint, 2025. arXiv:2510.27614.
**Retrieved:** full text via https://arxiv.org/pdf/2510.27614
**Source URL:** https://arxiv.org/abs/2510.27614
**Domain:** D

### What it does
Hybrid Rateless Set Reconciliation lets two replicas holding sets of variable-sized elements (files, database records, transactions) find their symmetric difference and synchronize, using metadata whose size adapts automatically to the actual number of differing elements, without either replica knowing that number in advance and without needing to know a bound on it. It combines two mechanisms in three phases. First, the Rateless Bloom Filter (RBF): rather than sending one Bloom filter of a fixed, pre-chosen size, the sending replica streams an unbounded sequence of Bloom filter "slices," each slice built with a single hash function (k=1 per slice) and a size m = n/ln(2), where n is the sender's set size (the optimal single-hash-function Bloom filter density). Each element x is placed into slice i by setting the bit at position H(x concatenated with i) mod m, where H is a hash function, so the slice index itself substitutes for needing both replicas to agree on a family of independent hash functions in advance. Each new slice received lets the receiving replica move some of its own elements that fail the membership test on that slice from a "suspected common" set into a confirmed "true negative" set. The receiver applies a cost-based stopping rule adapted from Mullin's Bloom-join termination criterion: once the number of newly confirmed true negatives revealed by the latest slice falls below m / C_elem (where C_elem is the per-element communication cost of the final fixed-size reconciliation phase, i.e. the size of an Invertible Bloom Lookup Table (IBLT) cell times the expected number of cells needed per difference), it signals the sender to stop, because transmitting one more slice would cost more than directly reconciling the remaining suspected elements. Second, after this first, unidirectional pass narrows each replica's set to a small "suspected common" candidate set, the same RBF streaming procedure runs in the opposite direction (Phase 2, Bidirectional Partitioning) so both replicas converge on matching candidate sets. Third (Phase 3), the two replicas compute fixed-size hashes of their remaining suspected-common elements and reconcile those hashes using rateless IBLTs (which stream IBLT symbols until decoding succeeds, needing no prior estimate of the residual difference size, unlike PinSketch or Parity Bitmap Sketch (PBS)); once the IBLT decode identifies which hashes are missing on which side, the replica missing an element requests it by hash and the other replica returns the full variable-sized element, and both replicas union in the received true negatives and resolved false positives to reach a synchronized state.

### Measured results
All experiments ran in a single-machine simulation (no network latency), with communication cost computed from the serialized byte size of inter-replica messages; two replica sets of fixed cardinality 100,000 distinct items each were generated per experiment, symmetric differences controlled to hit target Jaccard similarity values from 0% to 100% in 5% increments (0.5% increments for the high-similarity experiment covering 85%-100%), element sizes drawn uniformly from [5, 80] bytes, each data point averaged over 30 independently generated random trials with reported +-1 standard deviation.

### Parameters
- Bloom filter slice hash count: k=1 per RBF slice (single hash function), following Mullin's Bloom-join design.
- RBF slice size: m = n/ln(2), where n is the sender's local set size at the time of streaming.
- Slice indexing function: bit position H(x || i) mod m for element x and slice index i, avoiding any need to pre-agree on multiple independent hash functions.
- C_elem (per-element cost in the final reconciliation phase): the size of one IBLT cell multiplied by the expected number of IBLT cells per element of remaining difference; the paper uses 1.35 as this expected-cells-per-difference constant, stated as the value the ratio converges to for rateless IBLTs.
- RBF streaming stop condition: stop when the number of newly revealed true negatives from the latest slice is less than m / C_elem.
- IBLT field sizes in the implementation: idSum and hashSum both 64 bits, to keep collision probability low.
- Element size distribution used in experiments: uniform over [5, 80] bytes (stated not to affect metadata cost comparisons, since Bloom filters and fixed-size digest schemes both operate independent of element size).
- Set cardinality per experiment: 100,000 distinct items per replica, fixed across all reported experiments.
- Trials per data point: 30, reported as mean with +-1 standard deviation.
- PBS tuning (as configured for comparison, per the original PBS paper's methodology): tuned for 99% probability of completing within 3 communication rounds, with 5 differences per group on average.

### Stated limitations
The paper states its own approach is "suboptimal for replicas with extremely high similarity (Jaccard index above 85%)," because the initial RBF slices consume bandwidth disproportionate to a small actual difference; the measured worst case shows RBF+RIBLT sending close to 50 KB at d=0 versus a few bytes for the fixed-size-digest baselines. The Bloom filter component of the hybrid protocol carries an inherent risk of false positives, which the paper states is "a core limitation of using Bloom filters for reconciliation" generally, requiring the third-phase IBLT reconciliation step to resolve those false positives rather than guaranteeing correctness from the Bloom filter stage alone. PinSketch's O(d^2) decoding complexity is stated to make it "generally untractable for practical use cases where d is not guaranteed to be small," and the paper's own measurement shows approximately 100 seconds of PinSketch decoding time at d approx. 12,500. The stopping criterion's cost model depends on C_elem, itself derived from the empirical 1.35-cells-per-difference convergence constant for rateless IBLTs, so the correctness of the RBF stopping decision depends on that constant matching the reconciliation protocol actually used in the final phase. The exact crossover point between RBF+RIBLT and PBS in computation time is stated to be hardware- and network-dependent and is not given as a fixed number. Stated future work: an "inverting" variant that starts with rateless IBLT streaming, uses observed cell counts to derive a statistical estimate of the set intersection, and switches to RBFs only if divergence is expected to be large — meaning the current protocol's high-similarity weakness is an acknowledged open problem, not one the paper claims to have solved.

### Requirements it places on the rest of the system
Both replicas must be able to compute the same hash function H and interpret slice index i identically, since correctness of the RBF partitioning depends on both replicas placing the same element into the same bit position for a given slice index. The final reconciliation phase requires fixed-size hashes of the variable-sized elements (not the raw elements) to be reconciled via IBLT, and after decoding identifies missing hashes, an additional request-response round is needed for the replica missing data to ask for the actual variable-sized elements by hash, meaning the protocol's Phase 3 requires an object-retrieval mechanism between replicas keyed by hash, layered on top of set reconciliation itself. The stopping criterion for the RBF stream needs the receiving replica to already know C_elem, the per-element cost of the downstream fixed-size reconciliation protocol, so the specific reconciliation protocol used in the final phase must be fixed and its per-element cost characterized before the RBF phase's stopping rule can be evaluated; the paper picks rateless IBLTs specifically because they, like RBFs, need no advance estimate of the difference size, whereas pairing RBF with PinSketch or PBS would additionally require estimating the residual difference d' after the Bloom filter phases. The protocol assumes unidirectional streaming without waiting for per-slice acknowledgment, trading a bounded amount of wasted-slice communication overhead (extra slices sent during the round-trip delay before a stop signal arrives) for reduced latency; a deployment must tolerate this at-least-once-slightly-more transmission behavior. The design generating fixed C_elem from "1.35 cells per difference" is empirically derived for the specific rateless-IBLT implementation used in this paper's evaluation and is not proven as a general constant independent of implementation.
