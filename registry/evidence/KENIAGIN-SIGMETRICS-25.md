## [KENIAGIN-SIGMETRICS-25] CertainSync: Rateless Set Reconciliation with Certainty
**Citation:** Tomer Keniagin, Eitan Yaakobi, Ori Rottenstreich. "CertainSync: Rateless Set Reconciliation with Certainty." Proceedings of the ACM on Measurement and Analysis of Computing Systems (SIGMETRICS), 2025. DOI 10.1145/3727110.
**Retrieved:** full text via https://arxiv.org/abs/2504.08314
**Source URL:** https://arxiv.org/abs/2504.08314
**Domain:** D

### What it does
CertainSync reconciles two sets held by two participants — recovers their symmetric difference (the elements each side holds that the other does not) — with probability 1 of success and without either side estimating the symmetric difference size beforehand, unlike prior IBLT-based reconciliation schemes (Invertible Bloom Lookup Table — a fixed-size array of cells, each holding a count, an XOR of inserted keys, and an XOR of inserted key hashes, that supports listing back the inserted elements by repeatedly locating a cell holding exactly one element) whose listing step succeeds only with a probability that depends on a size estimate supplied in advance. Participant 1 builds an IBLT over its set using a "d-decodable rateless matrix" — a matrix defining which cells each element maps to, whose leading i-row submatrix is guaranteed to support successful listing whenever the symmetric difference size is at most i, for every i up to d — and transmits the matrix's rows as IBLT cells in order, in rounds. After each round, participant 2 subtracts its own IBLT (built with the same rows) from the received cells and tries to list the resulting symmetric-difference IBLT; if listing does not fully succeed, participant 2 requests more rows rather than guessing a target size, and stops requesting once listing succeeds. The scheme provides three interchangeable rateless matrix constructions differing in decoding-row growth pattern: EGH (initials of Eppstein, Goodrich, and Hirschberg, from a group-testing method built on the Chinese Remainder Theorem), OLS (Orthogonal Latin Square — an n-by-n grid construction used because two such grids can be superimposed with each symbol-pair appearing exactly once), and Extended Hamming (rows built from a parity-check matrix used in error-correcting codes). Because the reconciliation guarantee's communication cost grows with the universe size (the count of all possible elements, not just those held by either side), the paper adds UniverseReduceSync, which first hashes every element into a smaller reduced universe using a per-round salt agreed between participants, runs CertainSync inside that reduced universe, and repeats in further rounds with a smaller residual difference whenever the reduced-universe hashing produced a collision that hid an unresolved pair.

### Parameters
- IBLT cell size in the schemes-comparison experiments (Section 5): 192 bits (three 8-byte fields: counter, xorSum, checkSum), held fixed across all compared schemes for fair comparison.
- IBLT cell size in the Ethereum blockchain experiments (Section 6): CertainSync uses 192-bit cells (8-byte reduced-hash fields); UniverseReduceSync uses 576-bit cells (32-byte original-hash fields), because UniverseReduceSync's xorSum/checkSum carry full 256-bit transaction hashes while CertainSync's carry 64-bit reduced hashes.
- Universe size n: swept 10^3 to 10^7 for the universe-size experiments; fixed at n = 10^6 for the accuracy and scalability experiments; n = 2^256 for raw Ethereum transaction hashes before universe reduction.
- Symmetric difference size |Δ|: swept 1 to 10^4 for scalability experiments; fixed at 3, 100, and 1000 for the three accuracy panels; 700-950 in the live Ethereum trace.
- Collision threshold δ (UniverseReduceSync): tested at δ = 1 and δ = 100; the reduced universe size is derived as n_r = ⌈m(m-1)/(2δ)⌉, where m = |S1| + |S2| upper-bounds the union size.
- Number of trials: 10 independent trials per scheme per configuration in the synthetic (non-blockchain) experiments, averaged.
- Rateless-matrix decodability bound d: EGH is (d+1)-decodable for the tested d; OLS is ⌈√n⌉-decodable; Extended Hamming is fixed at 3-decodable, so its maximum recoverable symmetric difference size |Δ|_max = 3 regardless of n.
- Maximum symmetric difference size supported: EGH — n (unbounded up to universe size); OLS — ⌈√n⌉; Extended Hamming — 3 (stated as the reason Extended Hamming is inapplicable to UniverseReduceSync, whose whole purpose is handling variable, potentially larger differences).

### Stated limitations
The paper states as future work, not solved here: constructions for CertainSync beyond EGH, OLS, and Extended Hamming, drawn from combinatorial or recursive designs; reconciliation of more than two sets at once (multi-party set reconciliation) with the same certainty guarantee; and measurement of total reconciliation time (as opposed to communication-overhead bits) against baseline schemes under real-world conditions including high network churn — the paper explicitly did not measure wall-clock reconciliation time or churn effects. CertainSync OLS and CertainSync EGH each have a construction-specific regime where they are markedly less efficient than Rateless IBLT (OLS for |Δ| far below ⌈√n⌉, EGH for |Δ| above roughly 100-1000 depending on n), so no single CertainSync construction dominates across all symmetric-difference-size ranges — the paper frames this as construction choice depending on expected |Δ| range (Table 2), not as a solved unified scheme. UniverseReduceSync introduces possible hash collisions between elements in the reduced universe, which the basic CertainSync framework does not have, and requires multiple synchronization rounds (unbounded, collision-dependent) instead of CertainSync's exactly one round; the paper labels this trade-off explicitly in Table 3 rather than resolving it. UniverseReduceSync also requires parametrization (the collision threshold δ) and an estimation step for the reduced universe size, which is exactly the class of complexity CertainSync itself was designed to avoid.

### Requirements it places on the rest of the system
Both participants must independently construct their own IBLTs using the identical rateless matrix (same construction type and same row ordering) before any subtraction step is meaningful, since the symmetric-difference IBLT is obtained only by subtracting two IBLTs built under the same element-to-cell mapping. The receiving participant must be able to attempt listing after each round and to signal "send more rows" or "stop" back to the sender — the protocol is inherently interactive (round-based), not a one-shot cell transmission, which requires a return channel from the participant that already holds the full universe (or superset) to the one sending IBLT cells. The paper's core experiments (Section 5) assume a "typical case" where one participant's set is a superset of the other's, simplifying symmetric-difference computation to element removal; Section 6 (the Ethereum experiments) states this simplifying assumption is not used there, indicating the general two-arbitrary-sets case is handled by the framework but was validated in the arbitrary-overlap form only on the blockchain workload, not in the controlled Section 5 experiments. UniverseReduceSync requires both participants to derive the same per-round hash salt from an agreed pseudorandom number generator, so the two sides must already share a synchronized seed or generation protocol before any reduced-universe round runs; without that shared salt, the two sides would hash elements into different reduced universes and no valid difference could be computed. The Fully Sync Verifier step in UniverseReduceSync reads the sign of the IBLT counter in each pure cell to determine which side an element originated from, so the underlying IBLT counter field must be able to go negative (subtraction, not just addition) — a plain non-negative counter representation would not support this verification step.
