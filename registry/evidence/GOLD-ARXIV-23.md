## [GOLD-ARXIV-23] G-Rank: Unsupervised Continuous Learn-to-Rank for Edge Devices in a P2P Network

**Citation:** Andrew Gold, Johan Pouwelse. "G-Rank: Unsupervised Continuous Learn-to-Rank for Edge Devices in a P2P Network." arXiv preprint, 2023. DOI 10.48550/ARXIV.2301.12530.
**Retrieved:** full text via https://arxiv.org/abs/2301.12530
**Source URL:** https://arxiv.org/abs/2301.12530
**Domain:** K

### What it does
G-Rank ranks search results inside a peer-to-peer (P2P, no central server) network without any centrally trained model, using only records each peer already holds locally plus records received by gossip from other peers. Every peer keeps a clicklog: a local, append-only list where each row holds the querying peer's node ID, the query term, the ranked results returned for that query, and the item the peer clicked. When a peer issues a query, it first checks its own clicklog for the term; if the term has not been seen, it falls back to matching the term against local file metadata (title, artist, genre tag). If the term has been seen before, results are ranked by the number of clicks each candidate item has accumulated across all clicklog entries the peer holds (its own and gossiped-in ones), weighted by a per-peer-pair similarity score. Peers discover each other only through gossip: receiving a clicklog update from peer B exposes peer A to every node ID appearing in B's log, so the same message that carries ranking evidence also carries topology information. Gossip is pull-based and solicited: a peer sends a request message to one peer at a time and that peer replies with some or all of its clicklog; nodes cannot refuse an incoming request. New results ranked equal in score are additionally tie-broken so that items whose metadata matches the query term always outrank items that match only through clicklog click history with no metadata match, which is stated to blunt query-bombing (an adversary manufacturing spurious query-click pairs).

The similarity score between peer i and peer j, written S_i(n_j), is computed as (kappa_t + kappa_m^2) / kappa_u, where kappa_t is the count of query terms both peers have in their top-K query sets, kappa_m is the count of results both peers have clicked for shared queries, and kappa_u is the count of the union of clicked results between the two peers; the raw score is then normalized to [0,1] by dividing by the maximum score in the peer's list. Squaring kappa_m makes the score fall away faster than linearly as two peers' click behavior diverges, which the authors intend to speed re-clustering away from a peer whose behavior has started to diverge. An isolation constant F, tested at F=0 and F=1, sets a floor added to every similarity weight before it multiplies a candidate item's click count in the final ranking score R_i(Q) = sum over peers of (click_count_k * (S_i(n_j) + F)); at F=0 a peer with zero similarity to the querying peer contributes nothing, and at F=1 every gossiped-in clicklog entry contributes with equal minimum weight regardless of similarity.

### Measured results
All figures below come from one simulated network of 100 peers, initialized so each peer holds 10% of a 256-release Creative-Commons music catalog (approximately 26 items per peer) drawn from the PandaCD label, indexed by 39 unique genre tags used as the query-term vocabulary. Every experiment (baseline and each adversarial variant) was run twice, once at isolation constant F=0 and once at F=1. Adversarial simulations bootstrap 10 malicious peers (or, in the Epic Sybil case, 75 of the 100 peers) at simulation time step t=2500 (25% through the run) and trigger their attack at t=5000.

| Experiment | Condition | Measured outcome |
|---|---|---|
| Baseline (no adversary) | 100 peers, F=0 and F=1, no attackers | Per-peer distance to the globally optimal ranking (positional edit distance between a peer's local ranking and the ranking by global click count) drops sharply early in the run and approaches near-zero for effectively all peers and query terms. |
| Baseline (no adversary) | Same setup | Median fraction of queries for which the single globally most-clicked item for that term appears in a peer's top-ranked results grows slowly at first, then approaches 100% as gossip accumulates; the Epic Sybil Attack run is the only case in the paper where this fraction does not reach 100% by the end of the simulation. |
| Targeted Sybil Attack | 10 sybil peers, each issues 100 queries on one chosen term at attack time, always clicking the lowest-ranked result, then waits to be gossip-pulled | Rankings measurably deviate from optimality after the attack; peers at F=0 are affected more slowly than at F=1. |
| Clicklog Inflation Attack | 10 malicious peers, 1000 queries each (10x the Targeted Sybil count) at attack time, results chosen at random rather than always-lowest-ranked | Produces faster divergence from optimal rankings than the Targeted Sybil Attack, under otherwise identical peer count and network setup. |
| Epic Sybil Attack | 75 of 100 peers are adversarial (a network supermajority), each performing 100 queries choosing the lowest-ranked item, same bootstrap/attack timing as the Targeted Sybil Attack | Ranking quality degrades faster and further than any other tested condition; is the only condition in which the top-item-inclusion metric fails to reach 100% by simulation end. Post-attack rankings remain more accurate than at simulation start in every adversarial condition tested, including this one. |
| Push vs. Pull gossip | 10 malicious peers running the Targeted Sybil Attack, but malicious peers push unsolicited clicklog messages to up to 2 peers each while benign peers push to at most 1 peer, versus the default pull scheme where a peer requests from exactly 1 peer it chooses | Push-based dissemination produces faster convergence toward optimal rankings before the attack, and correspondingly faster and deeper divergence immediately after the attack, than the pull-based scheme used in the other experiments. |
| Gossip message size | All simulations, message size measured as clicklog data transferred per gossip exchange | Mean gossip message size grows quickly early in the run then its growth rate falls off as peers become mutually aware; message size is stated to rarely exceed 600 kB. Each clicklog row is stated to be approximately 600 bytes. |
| Isolation constant F | F=0 vs. F=1, all adversarial experiments | Setting F=0 (discount peers with zero measured similarity entirely) produces a smaller negative effect on rank-distance from adversarial clicklog entries than F=1 (weight every gossiped entry with at least the floor weight F), but neither setting prevents the network from converging toward a single degraded ranking under the Targeted Sybil or Clicklog Inflation attacks. |

The paper reports no wall-clock or bandwidth-per-second figures beyond the gossip message size above, and explicitly declines to report computation time because it depends on implementation language and each device's hardware.

### Parameters
Network size: 100 simulated peers, fixed across every experiment. Catalog: 256 music releases, 39 unique tag values used as the full query vocabulary. Initial per-peer library: 10% of the catalog (approximately 26 items), assigned uniformly at random. Bootstrap gossip at peer join: a randomly selected existing peer shares a randomly sampled subset of its own clicklog; each new peer starts with up to 44 entries (its own 39 initial query-click pairs plus up to 5 gossiped-in entries). Adversary count: 10 malicious peers in every adversarial experiment except Epic Sybil, which uses 75. Adversary bootstrap time: simulation tick t=2500 (25% through the run). Attack trigger time: t=5000. Targeted Sybil query volume per attacker: 100 queries on one chosen term, always clicking the lowest-ranked result. Clicklog Inflation query volume per attacker: 1000 queries, results chosen at random. Push vs. Pull fan-out: malicious peers push to up to 2 peers, benign peers push to at most 1. Isolation constant F: tested at 0 and 1 (no intermediate values reported). Gossip cadence: a hybrid scheme guaranteeing every peer receives at least one gossip update per simulation tick, combined with a per-peer probability p = 1/|N| of performing a query-then-gossip action at a given tick. Evaluation cadence: one evaluation round every 100 queries. Random noise injection into ranking: 50% of queries have two randomly selected result-list positions swapped, stated as a mechanism to avoid ranking plateaus (not varied as an experimental parameter; held fixed at 50% throughout).

### Stated limitations
The paper states that G-Rank does not correct for query misspellings or typos, though it states this could potentially be integrated. The click model used to generate simulated user behavior is described as simplified: simulated peers select the top-ranked item except when two items tie in score, in which case the lower item ID is chosen as a fixed tiebreaker; the authors cite this as a simplification relative to modeling real click noise. The paper states that a "global optimal ranking" used as the comparison baseline throughout the evaluation is only computable inside the simulation, where a global observer can aggregate all peers' state; the authors state explicitly that in a live deployed network this global optimum is not feasibly observable, so the reported distance-to-optimum figures are simulation-only quantities without a deployed-network analogue. The similarity-clustering mechanism (Section 3D) is stated to be a "fuzzy non-parametric" first version, and the authors state that more explicit self-clustering methods, such as outlier detection by distance from cluster centroids, are left to future work. The paper reports no measurement of computation time or CPU/energy overhead, stating this is highly dependent on implementation language and per-device hardware. The paper tests only two values of the isolation constant F (0 and 1), not a swept range. The dataset (256 releases, 39 tags) and network size (100 peers) are both small relative to a production P2P deployment; the paper draws conclusions from this single scale and does not report a scaling experiment across larger peer counts or catalogs.

### Requirements it places on the rest of the system
Peer discovery in G-Rank is not supplied by any separate mechanism: a peer becomes aware of another peer's existence only by receiving a clicklog gossip message naming that peer's node ID, so the ranking mechanism and the topology-discovery mechanism share one message type and G-Rank cannot be deployed without some initial bootstrap peer supplying a first clicklog sample to a joining node. The pull-based pattern (a peer requests an update from one chosen peer, and that peer must reply) requires an underlying transport that supports one-to-one request/response messaging between peers that already know each other's addresses; it does not specify NAT traversal or peer-address resolution, leaving that to whatever transport layer carries the gossip messages. Every peer's clicklog and click history is transmitted in full or in part to any peer that requests it and is not stated to be access-controlled, encrypted for a specific recipient, or filtered by requester identity in the design tested here; a component supplying peer identity or access control would need to sit below this mechanism, since G-Rank has none of its own beyond the derived similarity score. Ranking quality depends on receiving enough distinct, honest clicklog entries per query term; a term with too few observed click events falls back to unranked or noisy metadata matching, so the mechanism requires either a warm network with substantial query history or an explicit cold-start supplement for the first queries on a new term. The mechanism assumes malicious peers can be pull-gossiped from and cannot be selectively excluded once discovered; any Sybil-resistance or peer-admission control the surrounding system supplies determines how many malicious node IDs can enter a given peer's known-peer list, which directly bounds the volume of poisoned clicklog data the ranking model can be forced to absorb.

### Contradicts
None found within this corpus regarding G-Rank's own reported figures. HEGEDUS-ECMLPKDD-19 (reference [29] in this paper's own bibliography) independently compares gossip-based and federated decentralized training for a different task (matrix-factorization recommendation, not learn-to-rank) and is a useful adjacent data point on gossip-based decentralized learning convergence, but it does not measure G-Rank and no direct figure-for-figure conflict exists between the two papers in this corpus.
