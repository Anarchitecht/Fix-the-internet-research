## [WESOLOWSKI-EUROCRYPT-19] Efficient verifiable delay functions
**Citation:** Benjamin Wesolowski. "Efficient verifiable delay functions." EUROCRYPT, 2019.
**Retrieved:** full text via https://eprint.iacr.org/2018/623.pdf
**Source URL:** https://eprint.iacr.org/2018/623.pdf
**Domain:** I

### What it does
This paper constructs a verifiable delay function (VDF): a function that takes a specified number of sequential steps to evaluate and produces an output any observer can check far faster than that evaluation took. The construction builds a trapdoor VDF first: a version in which a party holding a secret key (the trapdoor) can compute the output quickly, while anyone without the trapdoor needs the full sequential computation. Deriving a plain VDF from it means running the trapdoor-VDF setup in a way that discards or never generates the trapdoor, so nobody, including whoever ran the setup, can compute the output faster than the stated delay. The trapdoor construction works over a group of unknown order G (an RSA group, or the class group of an imaginary quadratic field, chosen because nobody can efficiently compute that group's order without extra secret information). Evaluation on input x for delay parameter t computes y = x^(2^t) mod the group's modulus by t sequential squarings; someone holding the trapdoor (knowledge of the group's order, i.e. Euler's totient for an RSA modulus) can compute the same 2^t-th power directly via modular exponentiation of the exponent reduced modulo the order, skipping the sequential squarings. The proof of correctness is a single group element pi computed as follows: the verifier or, via the Fiat-Shamir transform, a hash function derives a random prime number l from the statement (g, y); the prover computes pi = g^floor(2^t / l); the verifier computes r = 2^t mod l and checks that y equals pi^l times g^r. Producing this proof takes O(t / log t) group operations using a precomputation algorithm the paper gives explicitly (Algorithm 5), rather than the naive O(t) operations of recomputing every intermediate squaring, by grouping the exponent's bits into blocks of size kappa and combining a table of gamma = sqrt(t) precomputed powers. A bandwidth-saving variant transmits (l, pi) instead of (y, pi), since l is far shorter than a group element, and lets the verifier recover y = pi^l * g^(2^t mod l). A separate technique splits the sequential computation into n segments so a second computation thread produces the proof for each earlier segment while the first thread continues evaluating, reducing the residual work needed after evaluation finishes from O(t/log t) to O(t/omega^n) at the cost of a proof that grows to n group elements plus n-1 short primes, where omega is a small constant (the paper's example uses omega = 20). The same construction supports proof aggregation across several VDF evaluations sharing the same base and delay, and a watermarking variant that ties a proof to an evaluator's identity by deriving the challenge prime from a hash that includes that identity, at no extra sequential cost to an honest evaluator holding the intermediate values but at the cost of a full VDF re-evaluation for anyone forging a different identity's watermark.

This is a construction and security-proof paper; its numeric figures are algorithmic complexity bounds and one worked concrete example, not deployed-system or empirical benchmark measurements.

### Parameters
- Delay parameter: t (or Delta), the number of sequential group-squaring steps; example instantiation t = 2^40.
- Security level k: stated typical values 128, 192, or 256 bits; controls the bit-length of the random Fiat-Shamir challenge prime l, sampled from Primes(2^k).
- Precomputation-algorithm tuning parameters for proof generation: block size kappa and table-count gamma, with the paper's suggested choice kappa = log(t)/3 and gamma = sqrt(t), giving about t * 3/log(t) group operations and storage of about sqrt(t) group elements.
- RSA setup example: 2048-bit modulus N, product of two safe primes, group G = (Z/NZ)* / {+-1}.
- Segment count n for the overhead-reduction technique: a tunable integer trading proof length (n group elements plus n-1 primes) against residual post-evaluation work (T/omega^n).

### Stated limitations
The paper states that generating an RSA modulus with a strong guarantee that nobody knows its factorization is hard in practice: sampling a random number large enough to be divisible by two large primes with high probability "severely damages the efficiency of the construction" and increases the opportunity for parallel arithmetic optimization or specialized hardware to speed up an attacker; a secure multiparty RSA key-generation protocol avoids this but requires a third party to trust that the participating parties did not collude to recover the secret factorization. The paper's proposed alternative, the class group of an imaginary quadratic order, avoids the trusted-setup problem but its security rests on a generalized time-lock assumption (Assumption 2) that is not known to reduce to a standard, well-studied hardness assumption; the paper states this explicitly, contrasting it with the RSA setting where the analogous assumption can be reduced toward the difficulty of factoring or the RSA problem, though the paper notes even that RSA-setting reduction is not itself established to a standard problem in the strict security-reduction sense described in the proof section. The paper states that achieving precise real-world timing guarantees "is unlikely to be achievable without resorting to trusted hardware," so applications built on this VDF are described as needing to tolerate the small constant-factor timing slack (about 5% for practical parameters) between guaranteed sequential work and total work, rather than relying on the two being identical. The deniable timed-identification protocol described in Section 8 requires an accurate real-world estimate, in seconds, of the delay parameter needed to prevent a near-optimal adversary from forging a response before that estimate can be converted into a physical distance bound via the speed of light; the paper states obtaining such an accurate real-time estimate is a non-trivial open task related to the general difficulty (discussed in the paper's Section 3.2) of calibrating an abstract sequential-step count against real-world seconds.

### Requirements it places on the rest of the system
The plain (non-trapdoor) VDF requires a public setup procedure that generates a group of unknown order without producing a known trapdoor; the paper states this is most efficiently done using the class group of an imaginary quadratic order rather than an RSA modulus, because RSA-modulus generation with a provably-unknown factorization either damages efficiency (public random sampling) or requires trusting a multiparty computation's participants not to have colluded. The Fiat-Shamir non-interactive variant requires a secure cryptographic hash function H mapping to {0,1}^(2k) and, separately, a hash-to-prime function Hprime used to derive the challenge prime l; the paper's soundness proof is stated in the random oracle model, meaning the security argument requires this hash to behave as an ideal random function, not merely a standard collision-resistant hash. The construction's sequentiality proof for the RSA setup rests on the classic time-lock assumption of Rivest, Shamir, and Wagner: no polynomially bounded algorithm without the factorization of N can compute the delayed exponentiation faster than the stated cost function, an assumption the rest of the system must accept as a computational premise rather than a proven-hard problem. The watermarking extension requires the honest evaluator to retain an intermediate value from its own computation (the second-to-last squaring result) to compute a certificate efficiently; a system that discards intermediate state after producing the final output cannot use the cost-effective watermarking method described. The two-thread overhead-reduction technique requires the evaluator to run two computation threads in parallel with a specific handoff of intermediate values between them; a purely single-threaded evaluator cannot reduce the post-evaluation proof-computation overhead below O(t/log t).

### Contradicts
None found. This paper's related-work section (Section 1.2) explicitly distinguishes its own construction from BONEH-CRYPTO-18's polynomial-GCD-based candidate (stated as needing more-than-polylogarithmic parallelism to run in the target delay, one of "these disadvantages" this paper avoids) and from the bounded-pre-computation exponentiation construction in the same paper (stated as "insecure against an adversary that can run a large (but feasible) pre-computation"), but these are the earlier paper's own stated properties for its weaker constructions, not a factual disagreement between the two papers' measurements.
