### What it does
World issues a per-person credential (World ID) that lets a relying party check a presented proof against a public registry and learn only a single bit — unique-human member of the set, yes or no — without learning which person. The registry membership check runs as follows. At enrollment, a purpose-built infrared camera called the Orb captures iris images inside a trusted execution environment (TEE) on the device, derives a fixed-length code from the iris texture using multi-scale Gabor wavelet filtering and phase quantization of the filter output, and never uploads the raw image for the uniqueness check. The Orb splits that iris code into multiple encrypted fragments before the uniqueness check runs, so no single party holds a decodable code; this fragment scheme is called Anonymized Multi-Party Computation (AMPC). Multiple independent operators each hold one fragment and jointly compute whether the new code's Hamming distance to every previously enrolled code falls below a match threshold, without any party learning the distance values — the joint computation returns only a match/no-match bit. If no match is found, a World ID secret (a random byte string) is generated, its hash is added to a public registry (a Semaphore identity set implemented as an Ethereum smart contract, replicated to other chains through state bridges), and a Proof of Human (PoH) credential is returned to the user's device. To authenticate later, the user's app produces a zero-knowledge proof (zk-SNARK, via Semaphore, using Poseidon hashing over the BN254 scalar field) that it holds a secret whose hash sits in the registry, paired with a nullifier that prevents that same secret from producing multiple valid proofs for the same relying-party action; the relying party checks the proof against the public registry and learns only that the presenter is a unique registered human, not which one.

### Parameters
- False match rate design target: 1×10⁻¹² system-wide (billion-identity scale), requiring 1×10⁻⁶ per-iris FMR.
- False non-match rate design target: below 5×10⁻³.
- Two hardware-burned cryptographic keys per Orb unit: one provisioned into the main system-on-chip during manufacturing, one in a hardware secure element that cannot be exported; the device refuses to operate unless both keys validate and their execution environments are intact.
- Identity-set commitment scheme: Poseidon hash over the BN254 scalar field, used as the hash function whose output populates the Semaphore membership set.
- Zero-knowledge proof system: Semaphore, built on Groth16-verifiable zk-SNARKs, deployable to any chain capable of verifying Groth16 proofs.
- Personal Custody Package (PCP) currently contains: iris and face embeddings, raw iris and face images, and the AMPC fragments — each field individually encrypted (each MPC fragment with the public key of its specific AMPC party), then the whole package encrypted again on the Orb with a user-supplied key before leaving the device.

### Stated limitations
The paper states biometric verification is inherently probabilistic and carries nonzero error rates at any threshold choice; it does not claim a zero-error system. Some severe eye conditions reduce iris-biometric accuracy (common conditions such as cataracts are stated not to matter meaningfully); the paper proposes specialized verification centers using facial biometrics as a fallback but states this extension "would need careful design to preserve the system's integrity" and has not built it. Smartphone and existing consumer iris cameras are stated to lack the imaging resolution, multi-angle capture, and active illumination needed for reliable presentation-attack detection, which the paper gives as the reason a purpose-built device (the Orb) is required rather than a phone. Without an on-device trusted execution environment enforcing that image capture originates from a compliant device, the paper states attackers could spoof both image capture and enrollment requests to create unlimited fraudulent credentials — a control the paper says many smartphones cannot provide because on-device secure enclaves are inconsistently available or accessible only to the phone manufacturer. Uniqueness without a strict one-credential-per-person guarantee is stated to be vulnerable to relay attacks, where a small group of humans repeatedly authenticate on behalf of many automated agents. The paper states that "any hardware system interacting with the physical world requires continual enhancements" and describes third-party audits (Theori, Trail of Bits, Least Authority) and a bug bounty program as ongoing responses, not a closed problem. AMPC's roadmap section states current work is to reduce compute requirements and to add trusted execution environments to the compute nodes, which are not yet in place. World ID 4.0, described as a future protocol upgrade, is stated to introduce a distributed oblivious pseudorandom function (OPRF) network for nullifier computation and enforced one-time-use nullifiers — implying the nullifier scheme described elsewhere in the current text does not yet have these properties.

### Requirements it places on the rest of the system
A relying party that wants to check a PoH credential must be able to verify a Semaphore zk-SNARK proof (Groth16) against a public registry commitment; the paper assumes the verifier can read that on-chain (or state-bridged) commitment. The uniqueness check requires every enrollment to reach at least one live AMPC compute node operated by one of the named independent institutions (Nethermind, University of Erlangen-Nuremberg, UC Berkeley RDI, with KAIST and UTEC stated as joining); no fragment holder alone can complete a match. The one-registry-per-person invariant that the whole scheme depends on assumes iris images are captured only by hardware meeting the paper's stated multispectral, TEE-backed, tamper-monitored specification — a general-purpose camera or phone is stated to be insufficient for the false-match-rate target. The paper assumes each enrolling person has functioning eyes matching the biometric modality; it names no complete alternative-verification path already built for people who cannot use iris capture. The nullifier mechanism assumes relying parties supply an action-scoped context so that the same person's proof produces different nullifiers per context, preventing cross-context linkage — the mechanics of nullifier scoping are referenced but not specified in the excerpted text. The whole registry-membership approach assumes the identity-set commitment (the Merkle-style set of secret hashes) is kept synchronized across every chain a relying party might verify against, through the state-bridge mechanism the paper names but does not detail.

### Contradicts
The paper's own claim that "no biometric data ever leave the user's device" is qualified elsewhere in the same text: the Personal Custody Package, which does leave the Orb (it is sent to the user's device, not retained on the Orb, but the raw iris and face images and iris/face embeddings are the biometric data in question, packaged and encrypted, not withheld from ever being formed off the sensor into a transportable artifact). This is the paper's own internal tension between "processed locally" language and the explicit list of raw images and embeddings inside the PCP; it is not a claim from another source. No other paper in this corpus makes a directly conflicting measurement — this is the only source in the batch on iris-based proof of personhood.
