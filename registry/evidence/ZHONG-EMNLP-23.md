## [ZHONG-EMNLP-23] Poisoning Retrieval Corpora by Injecting Adversarial Passages
**Citation:** Zexuan Zhong, Ziqing Huang, Alexander Wettig, Danqi Chen. "Poisoning Retrieval Corpora by Injecting Adversarial Passages." EMNLP, 2023. DOI 10.18653/V1/2023.EMNLP-MAIN.849.
**Retrieved:** full text via https://arxiv.org/abs/2310.19156
**Source URL:** https://arxiv.org/abs/2310.19156
**Domain:** B

### What it does
The attack causes a dense retriever (a nearest-neighbor search model that maps text to vector embeddings and returns the passages closest to a query's embedding) to return attacker-chosen passages for queries the attacker never observed, by inserting a small number of crafted passages into the retrieval corpus. A dense retriever holds two encoders, one for queries and one for passages, and scores a query-passage pair by the inner product of their embeddings; at inference time it returns the top-k corpus passages by that score. The attacker generates a target passage token-by-token using a discrete gradient-approximation method (HotFlip): starting from a random passage drawn from the corpus, at each of 5,000 optimization steps the attack picks one token position at random, computes the gradient of the query-passage similarity score with respect to that token's embedding, and replaces the token with the vocabulary entry whose embedding has the highest inner product with that gradient (a single matrix-vector multiplication, so the step is cheap). The optimization target is the average similarity to a fixed training set of queries `Q`, so one optimized passage is tuned to fool many queries at once rather than one. To attack a query distribution that is not well served by one passage, the attacker first clusters the training queries by embedding similarity using k-means, then runs the optimization once per cluster, producing one adversarial passage per cluster and enabling parallel generation of a passage set `A` with `|A| ≪ |C|` (corpus size). Once inserted into the corpus, the crafted passages compete with the corpus's own passages for the retriever's top-k slots on any query whose embedding is close to the exploited direction.

### Measured results

All experiments generate adversarial passages against a model's training queries (Natural Questions, NQ, or MS MARCO), insert them into the retrieval corpus, then measure the top-20 attack success rate — the percentage of held-out test queries for which at least one adversarial passage appears in the top-20 retrieved results. Adversarial passages default to 50 tokens, generated with 5,000 HotFlip replacement steps, one GPU per passage.

### Parameters
- Adversarial passage length: default 50 tokens; swept over 10, 20, 50, 100, 250.
- Number of adversarial passages |A|: swept over 1, 10, 50, and up to 500 in one experiment; the paper states most experiments used |A|=50 "due to limited computing resources."
- HotFlip optimization steps per passage: 5,000.
- Query clustering for multi-passage generation: k-means on query embeddings, one adversarial passage generated per cluster.
- Embedding-norm-clipping defense constant α: 1.75 selected as the reported best tradeoff point; the paper states it swept "different values of α" in an appendix table but the retrieved text region here reports only the α=1.75 result.

### Stated limitations
The paper states the attack is computationally expensive: generating one adversarial passage requires running the optimization independently on a single GPU per query group, and lists more efficient multi-passage generation as future work. The paper states its investigation covers only corpus-poisoning attacks (inserting passages) and explicitly excludes other attack surfaces against dense retrievers, naming malicious manipulation of user queries as a different, unstudied avenue. The paper states cross-model transferability is limited: success rate falls below 0.5% between similar models and to zero across different model families, so an attacker without the target model's weights (a black-box setting) cannot rely on transfer from a substitute model. The paper states the embedding-norm-clipping defense may not generalize: it "remains possible that corpus poisoning for targeted query distributions or more sophisticated architectures, e.g., ColBERT's late interaction mechanism, may be harder to detect via vector norm anomalies." The paper states the likelihood-based defense could be defeated: "future work might show that an adversary can overcome this weakness by incorporating natural language priors into the attack," citing Song et al. 2021 as prior evidence that fluent adversarial text is achievable in a related setting.

### Requirements it places on the rest of the system
Requires white-box or gradient access to the retriever's query and passage encoders to run the HotFlip token-replacement step; the paper's method computes gradients of the similarity score with respect to token embeddings, so a fully black-box retrieval service (no gradient access) is not directly attacked by the method as described — this bears on any content-location or search mechanism selected for the target architecture, since retrieval systems built on dense/vector embeddings inherit this exposure whenever their encoders are inspectable or replicable by an attacker. Requires the attacker to hold or approximate a representative training query set `Q`, or the transfer results above (same architecture, different domain) do not apply — the reported cross-domain transfer used the source dataset's own training queries, not the target domain's queries. Requires write access to the corpus that the retriever indexes over, i.e., the ability to insert new passages; a content-addressed or append-only storage layer that lets any party insert unreviewed content into the searched corpus is a precondition the attack exploits directly, and any indexing mechanism selected for this project's search component that accepts unvetted contributions inherits this exposure unless a defense (norm clipping, likelihood filtering) is applied at ingestion. The measured defenses require the ability to compute embeddings or likelihood scores over every corpus passage at ingestion or query time — the norm-clipping defense modifies the retrieval-time scoring function itself, and the likelihood filter requires a separate language model to score every candidate passage before or during indexing.
