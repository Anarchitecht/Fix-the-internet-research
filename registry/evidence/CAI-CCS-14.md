## [CAI-CCS-14] A Systematic Approach to Developing and Evaluating Website Fingerprinting Defenses

**Citation:** Xiang Cai, Rishab Nithyanand, Tao Wang, Rob Johnson, Ian Goldberg. "A Systematic Approach to Developing and Evaluating Website Fingerprinting Defenses." ACM CCS, 2014. DOI 10.1145/2660267.2660362.
**Retrieved:** full text
**Source URL:** https://www.cse.buffalo.edu/~rniyanan/papers/tamaraw.pdf
**Domain:** G

### What it does
The paper defends against website fingerprinting attacks, in which an eavesdropper observing only encrypted traffic timing and packet sizes on a tunnel (SSL, Tor) infers which website a client visited, by presenting Tamaraw, a constant-rate padding defense, together with a methodology for measuring any defense's efficiency against the best possible attacker rather than against one specific classifier. Tamaraw sends traffic in both directions in fixed-size packets at fixed time intervals rho_out and rho_in (separate rates per direction, since outgoing web-request traffic is far less frequent than incoming page-content traffic); packet size is set to 750 bytes rather than the network's maximum transmission unit, chosen because most outgoing packets already fall near that size. Unlike its predecessor BuFLO, which pads total transmission time only up to a fixed cutoff tau (creating a tuning dilemma between coverage and overhead), Tamaraw pads the number of packets sent in each direction up to the next multiple of a padding parameter L, independent of any per-page time cutoff, so that many different web pages collapse to the same padded packet count and become indistinguishable to a classifier that observes only packet counts. The paper's ideal-attacker methodology treats two packet sequences as indistinguishable exactly when a defense makes their observable traces identical, giving an attack-independent upper bound on any classifier's accuracy, and separately proves lower bounds on the bandwidth overhead any defense must incur to reach a given security level under this ideal attacker. It also gives a closed-form method for converting a defense's measured closed-world accuracy (attacker chooses among n known sites) into an open-world true discovery rate (attacker must additionally rule out the entire rest of the internet), avoiding the need to run separate open-world experiments.

### Parameters
- Packet size: 750 bytes for Tamaraw (chosen to cover most outgoing packets without excess padding); MTU (1500 bytes) for BuFLO and for one tested Tamaraw configuration.
- rho_out, rho_in (packet-send interval, seconds/packet, one per direction): swept 0.005 to 0.16 s/packet in the Pareto-frontier search (Appendix Figure 4); chosen operating points rho_out=0.04, rho_in=0.012 (MTU packets) and rho_out=0.02, rho_in=0.006 (750-byte packets, halved to hold the same transmission rate at the smaller packet size). BuFLO's original configuration used rho_out = rho_in = 0.02.
- L (padding parameter, packets): incoming and outgoing packet counts each padded up to the next multiple of L; L=100 used throughout the reported Tamaraw evaluation.
- BuFLO's tau (time cutoff, seconds): tau=9 used in the matched-overhead comparison against Tamaraw (553 vs. 18 partitions at ~130% overhead); BuFLO configurations otherwise taken from Dyer et al.'s prior evaluation.
- K (dummy-packet run length signaling end of traffic): introduced as an implementation parameter for detecting stream end, but the paper's own analysis assumes client and proxy know when to pad rather than fixing a specific K.
- Classifier-distinguishability thresholds for the feature-sensitivity experiments (Section 3): 0.55 and 0.75 accuracy, used to define the minimum generator perturbation magnitude v at which a feature classifier can tell the two classes apart.
- Dataset sizes: 800 sites (Alexa top 800, closed-world security/overhead evaluation, one load per site); 100 sites (Alexa top 100, bandwidth/time overhead tuning and open-world evaluation, 70 loads per site); 400 sequences (bbc.co.uk repeated loads, feature-sensitivity experiments, 200 train / 200 test per class).

### Stated limitations
The paper states its causal packet-ordering constraint (a scheduled dummy packet is sent rather than reordering to send an already-ready real packet of the other direction) is a pessimistic implementation choice made to guarantee correctness, and that a practical implementation permitting reordering when the causal dependency allows it could achieve lower size and time overhead than the measured figures. It states that Tamaraw is not perfectly successful at hiding total transmission size against generators that substantially change that size (G1, G2, unique-packet-length generators), because the padding parameter L bins packet counts into ranges rather than eliminating the size signal entirely. It states its evaluation methodology derives an upper bound on attacker accuracy (via the ideal ambiguity-set attacker) rather than a demonstrated attack, so the reported closed-world epsilon-security values bound what any classifier, however powerful, can achieve, but do not represent a specific fielded attack's measured accuracy. It states the theoretical lower-bound framework in Section 5.1 covers only a specific class of attacker (AS attackers using ambiguity-set partitioning) and that the connection between Tamaraw's actual construction and this optimal-partitioning theory is only partial, since Tamaraw's partitions are fixed independent of the dataset rather than dataset-optimized as the theoretical construction requires.

### Requirements it places on the rest of the system
Tamaraw requires a proxy or client-side component capable of enforcing fixed-rate, fixed-size packet transmission independently in each direction, and requires that component to determine, out of band from the padded stream itself, when the real data transfer for a page has ended (the paper flags this as non-trivial and assumes an oracle for it in its own simulation rather than solving it). The scheme requires the padding parameter L and the two rates rho_out, rho_in to be fixed system-wide constants shared by every client generating traffic under the defense, since Tamaraw's security guarantee (via the ambiguity-set partitioning bound in Section 6.2.1) depends on many different pages colliding onto the same padded packet-count bucket; a per-client or per-session choice of L would fragment the anonymity set the defense provides. The open-world performance conversion (Section 5.2) requires the defender or evaluator to supply a closed-world classifier's accuracy across the full candidate site set plus each site's real-world visit popularity (the paper uses Alexa page-views-per-million) as an input.

### Contradicts
None found within this batch. The paper's own headline framing ("website fingerprinting attacks are a paper tiger," attributed by the paper's introduction to prior critique work by Perry) is explicitly rejected by the paper's own undefended-baseline result (under 50% false discovery rate against the 100 most popular sites with no defense at all), which the paper states directly contradicts that claim.
