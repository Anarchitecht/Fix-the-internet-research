### What it does
PAC'nPost lets a node in an unstructured peer-to-peer network retrieve the short posts ("micro-blogs") of the users it follows, and search all published micro-blogs by keyword, without a central server and without directly contacting the nodes it follows. It builds on the probably approximately correct (PAC) search architecture, in which a node retrieves an item with a target accuracy by querying a fixed number z of random peers, provided the item has already been replicated onto a computable fraction of the network. The framework's problem is to replicate every newly created post onto enough nodes, fast enough, without flooding the network with copies (a mechanism the thesis calls rapid-yet-restrained dissemination) and without a central coordinator, given that microblog creation happens continuously and at a high rate rather than as a single one-off rumor.

Every node in the network periodically (every s seconds) sends a request to z randomly chosen peers, naming the list of user IDs it follows and the identifier of the latest post from each it has already retrieved. Each queried node answers by returning, from its own local storage, the most recent post from every followed user it has stored, plus its own most-recently-published post, plus the current contents of a small local structure called the transfer buffer. The transfer buffer holds a bounded number of recently encountered posts that the node has not yet decided to stop forwarding; a post the node chooses not to place in the buffer is permanently excluded from further forwarding by that node (called "stifling," borrowed from epidemic/gossip terminology). Buffer membership is decided per post with a probability that decays with the post's age, P(select) = e^(−t/β), where t is the post's age in seconds and β is a tunable "dissemination parameter" — a larger β keeps older posts eligible for forwarding longer, increasing both the post's final replication and each node's bandwidth. A post is eligible for buffer selection only during its first sr seconds after publication (a fixed replication window), after which no node will forward it further regardless of buffer decisions already made. When a post is first published, its origin node immediately sends it to z (or, in the bandwidth-optimized variant, a separate initial-seeding count zs) random peers, giving the post a head start on this stifling process before ordinary scheduled queries take over its spread.

Retrieval accuracy, µ, defined as the probability of finding a specific post by querying z random nodes given it has been replicated onto r of n total nodes, follows µ = 1 − (1 − r/n)^z, the same relation underlying the PAC search architecture cited from the thesis's own earlier ICTIR 2011 paper (Asthana, Fu, Cox). This equation determines the replication fraction r/n required for a chosen target accuracy at a chosen query fan-out z, and the thesis inverts it to compute the number of nodes queried needed for a required accuracy, or vice versa. Keyword search reuses the identical query mechanism: a query for a keyword is broadcast to the same z random peers, each of which searches its local micro-blog collection using the BM25 ranking algorithm and returns its own top-k ranked results, which the querying node merges by BM25 score into a single top-k list.

To decouple the replication rate from the query interval s (in the base design the two are coupled because replication happens only via ordinary scheduled queries), the thesis's Chapter 4 variant introduces a separate role, "replicators": at every iteration, a node is admitted into the replicator set with a probability that also decays with the age of its most-recent locally-stored post, e^(−(t−1)/δ) for parameter δ, and each replicator independently forwards its own transfer buffer contents to zr additional random nodes per iteration — mimicking the "eager push" primitive of classical gossip protocols while still using the transfer-buffer stifling mechanism to support many concurrent, independently-aged rumors (one per post) rather than a single global rumor.

Chapter 5 adds a two-step algorithm for detecting a trending keyword — one occurring in posts at an elevated rate — without any node having access to global post-creation statistics. Step one: on each scheduled query, each queried node reports the top-j most frequent keywords (by cumulative count) found in its local keyword-storage sets covering the most recent (s+t) iterations, where t is the number of consecutive iterations a keyword must appear in to count as trending; the querying node sums frequencies across the z responses. Step two: on the following scheduled query, the node asks the same z peers for the specific iteration numbers at which any keyword whose combined frequency exceeds w times the median frequency (w a system parameter) was observed; merging the returned iteration numbers lets the node compute a trending fraction σ — the proportion of the required t consecutive iterations in which the keyword was actually observed — and treat the keyword as trending once σ exceeds a threshold.

### Parameters
Target accuracy µ: fixed at 95% throughout ("the most important decision" the designer makes, per the thesis; a lower target trades directly against replication or query count). Nodes queried per request, z: 25 in the base design (Chapters 3, 5); optimized to 15-16 (n=10,000) or 45-51 (n=100,000) as a function of query interval s in the bandwidth-optimized design (Chapter 4). Query interval, s: 30 seconds (base design, chosen to resemble Twitter's user experience) or 60-120 seconds (bandwidth-optimized design). Replication window, sr: 30 seconds (time a post is allowed to spread before being deemed available for retrieval). Dissemination parameter β: swept from 4.9-15.0 across experiments depending on n and target accuracy; determines exponential post-selection-into-buffer probability e^(−t/β). Maximum transfer buffer size, |T|max: unbounded in initial experiments, then capped at 25 (Chapter 3) or 100 (Chapter 4, decoupled design). Post creation rate, α: 25 posts/iteration (10x an assumed Twitter baseline of 4,600 tweets/sec over 200 million users) as the default; 125 posts/iteration (50x-500x baseline depending on n) tested as a spike condition; also expressed as α=2.5×10^-4 posts/node/iteration for the bandwidth model. Followers per node, f: fixed at 35 uniformly, based on Kwak et al.'s reported 1.47 billion links over 41.7 million Twitter users; later relaxed to a power-law distribution with exponent γ=0.68 (top 1% of nodes hold 20% of all follower edges). Post size, cb: 1,000 bytes (500 UTF-8 characters at 2 bytes/character). Per-contact protocol overhead, ct: 64 bytes (empty TCP/IP packet). Per-followed-peer specifier cost, cn: 8 bytes. Per-node contributed disk: 1 GB, split 90% post storage / 10% index. Churn model: session lengths exponentially distributed with mean 60 seconds under the "heavy churn" test; Poisson-arrival joins balance exponential-exit departures, holding active population roughly constant at 50,000 of 100,000 total. Seeding parameter zs: 25-105 tested (Chapter 4), trading off against β for a fixed target replication. Replicator-selection parameter δ: 0.66 in the reported decoupled-design simulations. Replicator fan-out zr: 7-9 (n=10,000) or 7-8.5 (n=100,000) in the decoupled-design simulations. Trending-keyword parameters: t=10 consecutive iterations to qualify as trending, w=10 (frequency threshold multiplier over median), j=1-3 (number of keyword-frequency pairs returned per query), y=5%-15% (fraction of posts carrying the injected trending keyword in test scenarios).

### Stated limitations
The thesis states PAC'nPost provides no mechanism for a user to delete or recall a published post once it has spread; a "recall/delete mechanism" is listed as future work. It states that the fixed-capacity, first-in-first-out (FIFO) storage area at each node means older posts are eventually evicted and permanently lost from the network once no node retains a copy, and that "an archiving strategy needs to be considered" — no such strategy is designed or evaluated in the thesis. The two-step trending-keyword algorithm is stated to require significant additional bandwidth (up to 37.73% overhead in the tested multi-keyword configuration) when tuned to detect multiple simultaneous trending keywords, which the authors state is future work to reduce. The thesis states BM25 is not an optimal ranking function for very short documents (micro-blog posts sized like SMS messages, ~140 characters) because term-frequency weighting is largely uninformative at that length, and states that query-independent features (publisher popularity, follow-relationship distance) would be a better ranking signal — not implemented or evaluated, only proposed as future work. The thesis states the framework is vulnerable to two forms of content pollution: false-identity disinformation and spam; it states these malicious posts would not appear in a user's followed-post timeline (because that timeline is restricted to accounts the user follows) but could appear in keyword-search results, and states that no defense is implemented — a "system of complaints" is sketched as a possible future direction but explicitly noted to itself require a decentralized reputation mechanism whose complaint-submitter's own reliability must also be assessed, which the thesis states is unsolved and left as future work rather than designed. The trending-keyword mechanism's susceptibility to spam abuse (a spammer inserting the trending keyword into unrelated posts to be retrieved by searches on that keyword) is stated explicitly as a known, unaddressed vulnerability, also deferred to future work. The non-uniform (popularity-weighted) replication scheme is stated to yield only marginal bandwidth savings versus uniform replication, in contrast to distributed web search, because the thesis's own periodic-polling retrieval model requires every node to keep querying for both high- and low-popularity content on every cycle, which the authors state erodes the benefit non-uniform document distribution provides in a more static distributed-search setting. The system-bandwidth calculation for mobile devices (6.64 KB/sec sustained upload+download) is stated by the authors to be "currently not viable for a mobile phone," with the only proposed mitigation being to have a mobile app communicate through a separate always-on desktop node rather than the phone itself directly participating.

### Requirements it places on the rest of the system
PAC'nPost requires an underlying peer-sampling/membership service that supplies each node with a partial, near-uniformly-random view of the network and periodically refreshes that view by exchanging entries with other nodes; the thesis names Cyclon, the overlay management system of Jelasity et al., and Brahms as examples that could supply this, but does not itself implement or evaluate any of them, so the correctness of PAC'nPost's random-peer-selection assumption depends entirely on whichever such service is deployed beneath it. It requires every participating node to follow at least one other peer, because a node that follows nobody never issues the scheduled queries that also carry replication traffic via the transfer buffer; the thesis states that if a newly published post is seeded only to nodes that follow nobody, that post fails to replicate — an explicitly acknowledged (if "very unlikely") failure mode. The keyword-search accuracy measurement depends on a centralized "gold standard" database that mirrors every published post, used only for evaluation, not for production operation — a real deployment has no such oracle and cannot itself measure retrieval or keyword-search accuracy against ground truth. The bandwidth-optimized (decoupled) design and the trending-keyword mechanism both assume the underlying transfer-buffer/stifling mechanism from the base design already functions and is running on every node; the trending-keyword mechanism specifically piggybacks its extra request/response fields onto the already-scheduled query and therefore inherits every precondition (working peer-sampling service, non-empty follow lists, honest response content) that the base retrieval mechanism requires. Retrieval-accuracy measurement throughout assumes queried nodes answer truthfully and completely from their actual local storage; no experiment introduces a node that misreports its stored content, forges a keyword-frequency count, or omits available posts, so none of the measured accuracy or bandwidth figures characterize behavior under such a node.

### Contradicts
None found among the papers in this batch (W1-5). The thesis's own two-page WWW 2012 companion paper (Asthana and Cox, "PAC'nPost: A Framework for a Micro-blogging Social Network in an Unstructured P2P Network") is stated by the registry's own retrieval-justification note to be too short to state the mechanism in implementable detail; this thesis is the correct full-length source for citing PAC'nPost mechanism details and measured figures, and any prior citation of numeric results to the WWW 2012 paper alone should be checked against this thesis instead. The thesis's own claim that existing DHT-based peer-to-peer social networks (PeerSoN, eXO, Cuckoo, My3) "do not address how a keyword search across all published data could be performed" and "assume a tight-knit community of peers" is the thesis authors' characterization of those systems, not a verified fact from this batch — retrieving those papers directly would be needed to confirm or contradict it.
