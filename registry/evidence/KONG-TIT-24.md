## [KONG-TIT-24] Locally Repairable Convertible Codes With Optimal Access Costs
**Citation:** Xiangliang Kong. "Locally Repairable Convertible Codes With Optimal Access Costs." IEEE Transactions on Information Theory, 2024. DOI 10.1109/TIT.2024.3435346.
**Retrieved:** full text via https://arxiv.org/abs/2308.06802
**Source URL:** https://arxiv.org/abs/2308.06802
**Domain:** C

### What it does
A code conversion changes the parameters of already-encoded data — for example, from an [n_I, k_I] code to a differently rated [n_F, k_F] code — without decoding the full original data and re-encoding from scratch, because that default approach requires reading a large number of symbols, transferring them over the network, and re-encoding, degrading system I/O. This paper studies conversion cost specifically for locally repairable codes (LRCs) — an (n, k, r) LRC produces an n-symbol codeword from k information symbols such that any single symbol can be recovered by reading at most r other symbols — in the merge regime, where ζ ≥ 2 initial codewords under an (n_I, k_I) LRC are combined into one final codeword under an (n_F, k_F=ζ·k_I) LRC.

The paper defines access cost as the sum of the read access cost (symbols read from the initial codewords during conversion) and write access cost (new symbols written to produce the final codeword), and separates every symbol touched into three categories: remaining symbols (unchanged, carried over from initial to final codeword), accessed symbols (read from initial codewords), and new symbols (written to the final codeword that were not carried over). The paper's contribution is threefold. First, it constructs a family of MDS (Maximum-Distance-Separable) convertible codes for general (n_I, k; n_F, ζk) parameters using Generalized Reed-Solomon (GRS) codes, built by mapping polynomials of degree at most k−1 into polynomials of degree at most ζk−1 via chosen evaluation points, achieving optimal access cost over a finite field whose size is linear in n_I (as opposed to a field size that grows with the code length raised to a large power). Second, it extends this construction, using an existing "good polynomials" technique for building optimal LRCs, to produce locally repairable convertible codes (LRCCs) with parameters (n_I, k, r; n_F, ζk, r), again over a field of size linear in n_I. Third, it proves a general lower bound on access cost for any convertible code whose final code is an LRC (Theorem IV.4), and shows the LRCCs from its own construction meet that bound exactly (Corollary IV.1, Remark IV.1) — establishing the constructed codes as access-cost-optimal, not merely as one available option.

### Parameters
- ζ ≥ 2: merge factor — number of initial codewords combined into one final codeword, k_F = ζ·k_I
- (n_I, k_I, r_I) and (n_F, k_F, r_F): initial and final LRC parameters; this paper's own construction requires r_I = r_F = r (equal locality on both sides), stated explicitly as a restriction relative to the fully general problem
- l_I = n_I − k_I, l_F = n_F − ζ·k_I: numbers of parity symbols in initial and final codes; the paper's constructions assume l_F ≤ min(l_I, k_I) or l_F = l_I = l < k
- q: field size — the paper's explicit constructions require q linear in n_I (specific bound stated in Corollary III.2), a substantial reduction from field sizes exponential in the code length required by some prior general-parameter constructions
- r: LRC locality parameter, fixed equal between initial and final code in this paper's construction

### Stated limitations
The construction requires the initial code and the final code to have the same locality r; the paper states this explicitly as an open question whether the construction and its optimal-access-cost guarantee can be generalized to LRCCs where the initial and final codes have different localities, even though its lower bound (Theorem IV.4) already covers that general case. The paper restricts its treatment to the merge regime only (combining multiple codewords into one); it states the split regime (one initial codeword divided into multiple final codewords) has equally strong practical motivation and cites a concurrent independent paper (Maturana, Rashmi, ISIT 2023, reference [9]) as "a good start" on that separate open question, not something this paper itself resolves. The paper states it is open how small the field size can be for LRCCs with optimal access cost to exist at all — noting that, unlike MDS codes, optimal LRCs are already known in the literature to admit sub-linear field size relative to code length, and this paper's own construction does not establish or approach that sub-linear regime. The paper's construction and lower bound do not address two other named LRC variants, (r,δ)-locality codes and LRCs with disjoint recovering sets (availability); the paper states conversion problems for those variants are open and of both theoretical and practical interest.

### Requirements it places on the rest of the system
A storage system adopting this code-conversion scheme must be able to select, at conversion time, evaluation points and a finite field of the size stated in Corollary III.2, tied algebraically to the specific (k, r, l_I, l_F, ζ) parameters chosen — the construction is not parameter-agnostic, and a system wanting to convert between arbitrary rate targets must verify the required field-size and divisibility conditions (k(r+1) | (q−1)) hold for its chosen field before applying this construction. The conversion procedure needs the initial and final codes' evaluation points and coding coefficients fixed in advance as part of the code design, meaning a system cannot decide to run a low-access-cost conversion after the fact on codes chosen without this construction in mind; the access-cost lower bound (Theorem IV.4) applies to any linear code choice, but only the paper's specific algebraic construction (Corollary III.2) is shown to meet it. The scheme assumes the storage system can address individual codeword symbols directly (read exactly the "accessed symbols" set and write exactly the "new symbols" set) without touching "remaining symbols," which requires the underlying storage layer to support per-symbol, not per-codeword, read and write access during a conversion operation.

### Contradicts
None found within this batch. The paper positions itself as extending, not contradicting, Maturana and Rashmi's original convertible-code framework (reference [5]) and their concurrent LRCC construction (reference [9], "Locally repairable convertible codes," ISIT 2023) — the paper states its own point of difference explicitly: it targets LRCs with all-symbol locality via an algebraic-coding approach achieving field size linear in code length, whereas the concurrent [9] targets LRCs with information locality via a piggybacking-framework approach, without claiming either result is wrong.
