## [AUVOLAT-SRDS-19] Merkle Search Trees: Efficient State-Based CRDTs in Open Networks
**Citation:** Alex Auvolat, François Taïani. "Merkle Search Trees: Efficient State-Based CRDTs in Open Networks." IEEE International Symposium on Reliable Distributed Systems (SRDS), 2019, pp. 1-10. DOI 10.1109/SRDS.2019.00032.
**Retrieved:** full text via https://hal.science/hal-02303490/document
**Source URL:** https://hal.science/hal-02303490/document
**Domain:** D

### What it does
A Merkle Search Tree (MST) lets two replicas holding large key-value sets or maps find exactly which entries differ by exchanging only the tree nodes on the paths to the differing entries, without either replica needing prior knowledge of the other's state or membership. It builds a balanced ordered search tree deterministically from a set of items so that any two replicas holding the same items always construct the identical tree, letting the standard Merkle-tree technique (hashing each node from its children's hashes, so a single root hash identifies the whole data set and matching subtree hashes prove matching subtree contents) apply directly to comparison and diffing. The construction assigns each item x to a tree layer using a collision-resistant hash function h_B(x) whose output is written in base B: the layer l(x) is the length of the longest all-zero prefix of h_B(x), so on average 1/B of items land at layer 1 or higher, 1/B^2 at layer 2, and so on, giving each layer's nodes an average out-degree of B and an expected tree depth of log_B(n) for n stored items (the probability of exceeding depth log_B(n) + c falls exponentially in c). Layer-0 items are leaves; layer-l items serve as the boundary values separating layer-(l-1) subtrees, so the tree is simultaneously key-ordered (unlike a hash-prefix tree, which destroys key order to stay balanced) and balanced only through hash-derived randomness, not through explicit rebalancing operations. Because assignment is a pure function of an item's hash, inserting the same set of items in any order converges to the same tree and the same root hash; this structural uniqueness also holds at every intermediate node, so comparing two trees can skip any subtree pair whose hashes match. Comparing tree f at one node against tree g at another exchanges O(d log_B(n)) messages, where d = |{x : f(x) ≠ g(x)}| is the number of differing items and n = max(|f|, |g|); each read, insert, or delete costs O(log_B(n)). The paper builds a causally-consistent distributed event store on top of MSTs — a grow-only set of timestamped events — reconciled through a gossip-based push-pull anti-entropy algorithm that periodically compares Merkle root hashes with a randomly sampled peer and descends into mismatching subtrees, requiring no causal-broadcast primitive and no per-node vector-clock bookkeeping.

### Measured results
The simulator is an actor-based Elixir implementation of about 2000 lines, publicly released, simulating a network of 1000 nodes (2000 in one scaling test) with synchronous communication rounds and no node crashes; events are generated with increasing timestamps at randomly chosen nodes. Three anti-entropy methods are compared under the identical gossip-based algorithm and event-dissemination workload: Scuttlebutt (vector-clock-based anti-entropy), MST (this paper's method, fixed at B=16), and MPT (Merkle Prefix Tree, a hash-prefix-tree competitor that discards key order but stays balanced through the same exponentially-decreasing hash-collision property). Entropy is a defined dissemination-consistency metric: the sum, over every message, of the binary entropy of the fraction of nodes that have received that message at a given simulation round; lower values mean more uniform diffusion.

### Parameters
- Branching parameter B fixed at 16 for all MST and MPT experiments ("In our experiments, we fix B = 16").
- Network size: 1000 nodes for the primary experiments; 2000 nodes for the one scaling comparison, where the MPT run did not terminate.
- Event generation rates: 0.1 events per round network-wide (light-load scenario, Table IV/Figures 2 and 4) and 1 event per round network-wide (heavy-load scenario, Table V/Figure 3) — a 10x difference between the two scenarios.
- Scuttlebutt gossip fanout tested at 1, 2, 4; gossip interval tested at 1, 2, 4, 8 rounds.
- MST/MPT anti-entropy fanout fixed at 6; maximum simultaneous merges tested at 1, 2, 3, 4, 6, 8.
- No node joins, leaves, or crashes occurred in any reported simulation; the paper states this explicitly as a scope limit, not a tested condition.

### Stated limitations
The paper states its experimental evaluation was restricted to "a very narrow problem" — a grow-only event store, described as one of the simplest known CRDTs — and to a single, simple gossip-based reconciliation algorithm; it does not evaluate more complex CRDT types (sets supporting deletion, multi-value maps) empirically. For CRDT types that need causality tracking, the paper states its simple per-item construction would store causality metadata alongside every item, generating large quantities of redundant data, and proposes storing that metadata separately as unevaluated future work. No node joins, leaves, or crashes were simulated; the paper states it "conjectures" (its own word) that Scuttlebutt's vector-clock overhead becomes even worse in open networks with churn, since inactive nodes' vector-clock entries accumulate and are exchanged at every round, but this claim about churn is not itself measured in this paper. In the heavy-load scenario, MST does not achieve as low an entropy value as Scuttlebutt at either 1000 or 2000 nodes, meaning Scuttlebutt disseminates more uniformly under high event rates in the tested configurations; the paper's own overall assessment is that MST is efficient specifically under moderate-to-low event rates, not universally. Using MSTs as a secondary index over data distributed via a distributed hash table (DHT) is proposed but explicitly stated as unevaluated: "The feasibility of such an approach when many updates occur at many nodes has not yet been evaluated." The comparison-cost bound O(d log_B(n)) assumes constant-size keys and values in K and V; the paper does not state a bound for variable-size elements.

### Requirements it places on the rest of the system
Every replica must use the same hash function and the same base-B assignment rule to place items into tree layers, and that hash function must be collision-resistant (the paper states the probability of two colliding strings is assumed negligible) and must project uniformly across values of size a power of B, since the layer-depth and balance guarantees derive directly from that uniformity; the paper cites SHA-512 as satisfying both properties in practice. The reconciliation protocol requires an anti-entropy transport capable of exchanging tree nodes identified by hash and does not require, and is stated to specifically avoid needing, a causal broadcast primitive — the paper positions this as the mechanism's advantage over delta-based CRDT approaches that need causal broadcast for correctness. Achieving the paper's O(log_B(n)) depth and O(d log_B(n)) comparison-cost bounds requires the branching parameter B to be fixed network-wide (all experiments here use B=16); the paper describes B as a tunable trade-off between shallower trees (larger B, fewer round-trips, more bytes per node) and smaller messages (smaller B), but gives no derivation of an optimal value. For applications needing causality tracking (deletion-supporting sets, multi-value registers), the paper states the base construction requires an external mechanism to store causality metadata separately from the per-item MST entries, since storing it inline would duplicate metadata across the tree; no such mechanism is specified or evaluated in this paper.

### Contradicts
None found within this corpus at time of writing. AMPARORE-ARXIV-26, elsewhere in this corpus, characterizes this paper's Merkle Search Tree as "imposing a rigid, canonically derived tree representation of the data," contrasted with AMPARORE-ARXIV-26's own range-based reconciliation approach, which operates on logical key ranges rather than a predetermined tree topology — a mechanism-level distinction stated by the later paper, not a numeric disagreement.
