### Resolution of open registry item "QRank"
QRank is not a separate paper. It is the name this paper gives to the difficulty-aware hybrid search scheme it defines and evaluates. "QRank" appears in this paper's own text ("we propose QRank, a difficulty-aware hybrid search") and nowhere else in the corpus as an independent title, author, or venue. The open registry item asking whether QRank exists under another name or should be struck should be closed by pointing to this entry.

### What it does
The scheme decides, per query, whether to answer it by flooding an unstructured overlay or by looking up a distributed hash table (DHT), so as to avoid the cost each strategy incurs when misapplied: flooding wastes bandwidth on queries whose matching items sit on only a few peers (because per-peer bandwidth for retrieving many items concentrated on few holders is wasted broadcasting to peers with no matches), and DHT lookup wastes bandwidth on multi-keyword queries whose keywords are individually common (because a DHT-based lookup requires fetching one posting list per keyword and intersecting them across a wide-area network, and long posting lists for common keywords are costly to transmit and intersect). The paper's stated basis for the mechanism is an observed decoupling: a query can have "many related items" without those items being held by "many peers" — items can be concentrated on a small set of peers who each hold many matching items — and existing hybrid schemes estimate search difficulty purely from item count, not peer count, so they misclassify such queries.

The mechanism assigns each query term t a weight ω_t = apTF_t × IPF_t. Inverse Peer Frequency (IPF_t) = log_e(1 + N/f_(t,p)), where N is the total peer count and f_(t,p) is the number of peers holding at least one item whose title contains t; a term held by many peers gets a low IPF, meaning flooding is more feasible for it. Adjusted term frequency (apTF_t) = 1 + α·log_e(f_t / f_(t,p)), where f_t is the total count of items (not peers) whose titles contain t, α>0 is a tunable scaling parameter, and the ratio f_t/f_(t,p) is the average number of matching items per holding peer — a high ratio means the term exhibits strong per-peer concentration (many items on few peers), which apTF weights upward as "difficult." The paper replaces the standard information-retrieval term-frequency measure (TF_t = 1 + log_e(f_(q,t)), the count of a term's occurrences within one query) because P2P queries average 3.54 terms, and 83% of queries in the paper's own analyzed Gnutella trace contain five or fewer terms, so each term occurs only once per query and f_(q,t) is a constant that carries no discriminative information — necessitating apTF as a replacement, computed instead from the term's per-peer item concentration.

Per-query aggregate difficulty δ_q is the mean term weight over the query's terms; σ_q is the variance of term weights around that mean, quantifying whether the query's terms disagree in difficulty. Rather than hand-set thresholds on (δ_q, σ_q), the scheme trains a Support Vector Machine (SVM, a supervised classifier that finds a maximum-margin separating hyperplane between two labeled classes) on a training set of queries labeled "Flooding" or "DHT," where the label for each training query is whichever strategy scored higher on a linear utility function combining three normalized metrics — recall (fraction of relevant items in the network actually returned), latency (mean time to return a result), and traffic cost (network bandwidth consumed) — each weighted equally at 1/3 in the paper's experiments. At runtime, an unstructured super peer computes (δ_q, σ_q) for an incoming query from globally gathered statistics (N, f_t, f_(t,p)) and classifies it, then either floods the query into the unstructured overlay with a fixed time-to-live (TTL) or looks up each keyword separately in the DHT and intersects the resulting posting lists.

The overlay itself has four node roles: normal peers (connect through a bootstrap peer to an unstructured super peer), unstructured super peers (index and search on behalf of their connected normal peers, run the flooding search and the embedded QRank classifier), structured super peers (a small subset of server-like, long-uptime nodes that jointly form the global DHT — the paper nominates the roughly 10% of peers with average uptime exceeding 80 minutes in its Gnutella-derived trace), and bootstrap peers. Only items with rare keywords are published into the DHT-based global index, to limit index-maintenance overhead. Global statistics (N, f_t, f_(t,p)) needed for the weighting model are collected using a push-synopsis gossip algorithm (a variant of Nath, Gibbons, Seshan, Anderson's synopsis diffusion, combined with duplicate-insensitive probabilistic counting), which the paper states converges the statistic estimate exponentially, reaching all nodes within log(n) gossip rounds for n gossiping nodes. An adaptive extension has a super peer, on receiving a query, poll its neighbor super peers' classification decisions; if they disagree, the decision made by the peer with the longest uptime is tagged onto the query (as Uptime_max) and propagated, so a downstream peer whose own uptime exceeds the tagged value and whose own classifier disagrees can override the in-flight flooding decision and redirect to DHT lookup, coordinating with the originating peer to avoid a duplicate DHT lookup.

### Parameters
- Physical topology: BRITE-generated, AS-Model-based, 100,000 nodes.
- Gnutella overlay traces crawled by the authors: seven topologies of sizes 31,747 / 34,206 / 45,650 / 48,134 / 57,926 / 68,737 / 75,643 nodes, crawled at over 50,000 peers per half hour using a custom Java crawler (40 parallel threads) built on LimeWire's open-source client, combined with a web spider for clients that do not answer crawler pings.
- Flooding TTL: 7 hops, chosen because a cited prior measurement found 95% of Gnutella node pairs are reachable within seven hops.
- Structured super peer selection: the roughly 10% of peers with average uptime exceeding 80 minutes in the Gnutella uptime-distribution trace used.
- DHT: Chord, with lookup latency modeled as (1/2)·log(N) hops.
- Query-timeout: 30 seconds.
- Training set for the SVM classifier: 6,759 examples, each a (δ_q, σ_q, BestSearchType) tuple, drawn from the Gnutella query trace (Zeinalipour-Yazti), each query run with both flooding and DHT strategies to determine ground-truth best label via the utility function; classifier trained with Weka 3; kernels tested include linear, polynomial, and Gaussian; α (the apTF scaling parameter) is varied during classifier tuning, exact swept range not stated numerically in the retrieved text.
- Utility-function metric weights: W_i = 1/3 for each of recall, latency, and traffic cost (equal weighting).
- File-popularity distribution used to synthesize the simulated document collection: log-quadratic, y = 10^(-2.98x^2 - 0.68x - 0.07), x the percentage of unique files ranked in log scale, y the percentage of all files in log scale (from a cited external measurement study).
- Interest-based-locality simulation parameters: δ (fraction of peers following the locality principle) swept 50% to 70%; γ (fraction of documents at such peers sharing a similar title) swept 20% to 60%.
- Each simulation condition run 50 times, with results reported as the average or a representative run.
- Text preprocessing: Porter stemming and stop-word removal applied to all query/document term data.

### Stated limitations
The paper states it found it difficult to model interest-based locality precisely in simulation, and its approach of assigning identical titles to distinct simulated items to approximate partial-title matching is explicitly presented as an approximation ("we believe such a method can simulate the interest-based locality to some extent"), not a validated model. The comparison methodology for the competing GAB scheme is stated to give GAB a favorable, near-upper-bound treatment: rather than using GAB's own published threshold-selection method, the paper computes an empirically near-optimal threshold t for GAB in each simulation run by running every sampled query under both flooding and DHT and averaging the equal-utility crossover points, explicitly to ensure the comparison bounds QRank's improvement rather than overstating it against a weaker GAB baseline. The scheme's realistic classifier-training data collection is only sketched, not executed in this paper: the paper states that for "a real-world system design" a large-scale trace such as the TREC WT100G collection deployed on PlanetLab would be needed to collect training data under real network metrics (end-to-end delay, bandwidth), but this larger deployment is not what was run — the reported evaluation uses the Gnutella-trace-derived simulator instead. The paper's future-work section states it intends to deploy the scheme on open platforms for a real-world system design and to address transfer learning for the SVM classifier across different network conditions — both explicitly unresolved at the time of writing. The adaptive hybrid-search extension (using neighbor super-peer uptime to override an in-flight flooding decision) is described mechanically but the paper does not report a separate quantitative evaluation isolating its contribution from the base QRank scheme's numbers reported above.

### Requirements it places on the rest of the system
The scheme requires a two-tier overlay in which a small subset of nodes (chosen by the system as long-uptime, server-like) forms a DHT and every other peer connects through an unstructured super peer to that DHT; a flat, single-tier unstructured network with no capacity-heterogeneous node subset has no natural candidate for the structured-super-peer role the paper's design depends on. Computing the per-query weight ω_t requires each unstructured super peer to know current global statistics N (total peer count), f_t (total item count per term across the whole network), and f_(t,p) (count of peers holding an item with that term) — these are supplied by a push-synopsis gossip protocol requiring log(n) rounds to converge for n participating nodes, so the classifier's input is always a delayed, gossip-converged estimate rather than an exact count, and the scheme's correctness assumes this global-statistics staleness is small relative to how fast the underlying popularity distribution changes (the paper states global statistics in large-scale P2P networks change slowly, which is why infrequent gossip recomputation is stated to suffice, though this rate-of-change assumption is not independently measured against a live deployment). The SVM classifier requires a labeled training set built by running candidate queries under both flooding and DHT and scoring each by the same three-metric utility function used at evaluation time — deploying the classifier in a network with a substantially different query or document-popularity distribution than the training trace has no guarantee attached in this paper beyond the qualitative claim that the underlying statistics "change slowly." The multi-keyword DHT-lookup fallback assumes the DHT layer supports keyword-level posting-list retrieval and an intersection operation across nodes responsible for different keywords, so a DHT design without per-keyword postings (for example, a pure key-value store with no inverted-index layer) could not serve as this scheme's DHT half without an additional indexing structure.

### Contradicts
None found — no other entry in this corpus reports a conflicting recall, latency, or traffic-cost figure for hybrid unstructured/DHT search under matching conditions. Against the open registry question of whether "QRank" is a separate, unretrieved paper: it is not — this entry is that paper's own definition of QRank, so no separate retrieval is warranted, and the registry item should be struck or resolved to point here rather than left open. This paper's own related-work section (Section 2) states, as a critique of GAB (Zaharia and Keshav), that GAB "has a limited accuracy due to the fact that many titles containing the desired terms does not always mean that many peers can answer the query" — presented here as the authors' own finding, not adopted by this extraction as a value judgment about GAB's general worth.
