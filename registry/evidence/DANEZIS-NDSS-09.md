## [DANEZIS-NDSS-09] SybilInfer: Detecting Sybil Nodes using Social Networks

**Citation:** George Danezis, Prateek Mittal. "SybilInfer: Detecting Sybil Nodes using Social Networks." Network and Distributed System Security Symposium (NDSS), 2009.
**Retrieved:** full text
**Source URL:** https://www.ndss-symposium.org/wp-content/uploads/2017/09/sybilinfer.pdf
**Domain:** F

### What it does
SybilInfer assigns each node in a social graph a probability of being honest rather than a binary accept/reject label, by running Bayesian inference over random walks sampled from the graph. It relies on the fact that a social graph without a Sybil attack mixes fast: a random walk from any honest node converges quickly to the graph's stationary distribution, so a short walk started at an honest node lands with near-uniform probability across the honest region. An attacker connecting a Sybil region to the honest graph through a limited number of attack edges creates a sparse cut, which slows mixing across that cut, so a short walk starting in the honest region lands in the Sybil region less often than the stationary distribution would predict. SybilInfer samples T independent short random walks (traces) from a known honest seed node, then runs a Metropolis-Hastings Markov chain sampler over candidate bipartitions of the graph into an honest set X and its complement, scoring each candidate partition by how well the observed trace endpoints match the partition (nodes in X should receive most trace endpoints if X is truly the honest region). Repeated sampling over many candidate partitions produces, for each node, a marginal probability of falling in the honest region; a node is labeled honest if this marginal probability exceeds 0.5. A threshold parameter alpha, applied to a normalized cut-density statistic E_XX, separates a detected Sybil region from ordinary community structure inside the honest graph, trading detected Sybil identities against false positives.

### Parameters
- alpha (E_XX detection threshold, fraction of E_XX_max = 1/(|X|-1) - 1/|V|): swept 0.65, 0.7, 0.75 in synthetic experiments; fixed at 0.7 for the remainder of the paper (real-world data and comparison sections).
- T (number of independent traces/random walks sampled from the honest seed): stated as a parameter of the algorithm; the marginal-probability computation in the synthetic experiments uses 20 samples, but the paper does not give a single fixed value of T used throughout.
- Honest-labeling threshold on marginal probability: 0.5 (a node is labeled honest if its estimated marginal probability of honesty exceeds 0.5).
- Scale-free network generation: m0 initial clique size not numerically stated; m (new edges per new node) = 5, giving average node degree 10; 1,000 total nodes.
- Compromised-node fraction f: swept from near 0 up to 0.35 (comparison with SybilLimit) and up to 0.2 (synthetic Sybil-insertion experiments).
- LiveJournal dataset: raw snowball sample >100,000 nodes; 3-hop neighborhood ~50,000 nodes; after pruning (remove degree < 3, remove asymmetric edges), ~33,000 nodes (31,603 in the comparison figure).

### Stated limitations
The paper states that a practical threshold E_XX must be introduced because ordinary community structure in a real social graph (interest, locality, or administrative groupings) produces sample cuts that could otherwise be mistaken for a Sybil attack, and that this threshold weakens the theoretical guarantee: an adversary can introduce Sybils into a region without detection as long as the induced E_XX stays under the threshold. It states that on the LiveJournal dataset it cannot establish ground truth for the ~2,000-node bottleneck cut found without an injected attack, so it does not label those nodes honest or dishonest. It states that extending SybilInfer to a fully decentralized one-hop distributed hash table, where nodes know only a bounded neighborhood of size O(c*sqrt(|V|)) rather than the full graph, is left as future work, with only a simplified pairwise introduction protocol sketched. It states that when SybilInfer is applied to a partial subgraph representing a specific online community rather than the full social graph, its output changes from an absolute probability of dishonesty to a probability relative to that community, and that nodes poorly integrated into the selected subgroup may be mislabeled Sybil even though the full graph would classify them honest; it states this mode requires first checking that the subgroup itself is fast-mixing.

### Requirements it places on the rest of the system
SybilInfer requires each verifying node to know at least one honest node a priori (used as the sampling seed) to break the symmetry between the honest and dishonest regions; without a known-honest seed, an attacker mirroring the honest social structure is indistinguishable from the real one. It requires the social graph to be fast-mixing, a property the paper attributes to real social networks by citation rather than proving for any specific deployment target. In its evaluated form it requires a node to know the complete social network topology to run the sampler; the paper states this assumption can be relaxed to sub-graphs for decentralized use, but only sketches, without full specification or evaluation, the protocol needed to do so. Friendship edges feeding the algorithm are assumed to reflect a security-relevant relationship, which the paper states requires users to restrict promiscuous "friend" acceptance behavior observed on existing social platforms, since indiscriminate edge formation degrades the fast-mixing/sparse-cut assumption the whole mechanism depends on.

### Contradicts
The paper's own theoretical framing initially treats the fast-mixing assumption and the sparse-cut assumption as strategy-independent guarantees, but its own evaluation (Figure 4 and Figure 5) shows detection performance is itself a function of adversary strategy (scale-free Sybil sub-topology vs. other placements) and dataset (synthetic vs. LiveJournal produces different accepted-fraction curves at the same compromised fraction f=0.2: 0.37 synthetic vs. 0.32 LiveJournal), which the paper does not reconcile into one bound. No other paper in this batch measures or restates this paper's specific detection figures.
