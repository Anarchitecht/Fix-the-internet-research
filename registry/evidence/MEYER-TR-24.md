## [MEYER-TR-24] Range-Based Set Reconciliation Without Homomorphic Hashing

**Citation:** Aljoscha Meyer, Konstantin Scherer. "Range-Based Set Reconciliation Without Homomorphic Hashing." Technical report, self-published, Technical University Berlin, 2024.
**Retrieved:** full text via https://aljoscha-meyer.de/assets/landing/rbsr_nonhomomorphic.pdf
**Source URL:** https://aljoscha-meyer.de/assets/landing/rbsr_nonhomomorphic.pdf
**Domain:** D

### What it does
Lets two nodes, each holding a set of items over a totally ordered universe, compute the union of their two sets by recursively exchanging fingerprints of contiguous subranges of that ordered universe, without either node needing a non-standard homomorphic hash function. Range-based set reconciliation (RBSR, the parent algorithm from Meyer's own prior SRDS 2023 paper, already in this corpus) works as follows: a node splits its item universe into a subrange, computes a fingerprint (a short cryptographic summary) for the items it holds in that subrange, and sends the fingerprint to its peer. When both peers' fingerprints for a subrange match, that subrange is known fully reconciled without transmitting the underlying items. When fingerprints mismatch, the subrange is split further (optimally into subranges of equal size) and the process recurses; below a configurable size, a node sends the items in the subrange directly instead of continuing to recurse. Both peers actively send fingerprints of their own subranges each round, which the paper contrasts with Merkle Search Tree (MST) reconciliation, where one peer sends and the other only responds — a structural distinction the authors argue produces exactly twice the number of range subdivisions per round in RBSR, halving the number of communication rounds relative to MST reconciliation (an argument from protocol structure, not a measured benchmark in this paper).

The stated computational obstacle addressed: computing a fingerprint for an arbitrary subrange (one that does not align with a subtree boundary of the peer's underlying tree data structure) had, in prior presentations of RBSR, required a homomorphic hash function — one admitting an associative combining function that computes the fingerprint of the union of two disjoint ranges from their individual fingerprints — because ranges generally do not correspond to whole subtrees of the tree. This paper replaces that requirement with an algorithm that computes the fingerprint of any range directly from a Merkle tree (a search tree in which every vertex is labeled with a hash of its own keys and its children's labels) using a "clamping" operation. Clamping a search tree `t` to a range `[x, y)` produces the tree containing only the items of `t` that fall in that range, defined recursively: the empty tree clamps to itself; a subtree entirely outside `[x, y)` clamps to whichever single child subtree could contain in-range items; a subtree with at least one key in range clamps to a new vertex whose first and last children are themselves recursively clamped, and whose interior children and keys are kept unchanged. A representation scheme is called history-independent if its representation function (mapping concrete tree structures to the abstract set they represent) is injective — equal sets always produce structurally identical trees — which is necessary for two nodes holding the same items to compute matching fingerprints. A history-independent scheme is additionally clamping-invariant if clamping two structurally different trees that hold the same items over the same range always yields the identical clamped subtree; the paper proves this property is what guarantees any two nodes compute matching fingerprints for a given range, for any tree in this family, without needing a homomorphic hash.

The core algorithmic contribution is a fingerprint-computation procedure, Algorithm 2, that computes the root label of `clamp(t, x, y)` without materializing the clamped tree. A naive recursive translation of the `clamp` definition (Algorithm 1) visits every vertex of a fully-in-range subtree, giving O(n) running time even for a subtree entirely inside the query range. The optimized version passes two boolean flags (`skipLeast`, `skipGreatest`) that, once the algorithm has descended past the single vertex where both a left- and right-side split can occur, let it read a precomputed subtree label directly instead of recursing further on that side, because every subsequent vertex on that side is now known to be either wholly in range (contributing its already-computed label) or wholly out of range (contributing nothing). This bounds the number of recursive calls to twice the tree height, giving O(log n) time and space with high probability for any tree data structure whose height is logarithmic in n with high probability.

### Measured results
None. The paper presents no implementation, no benchmark, no wall-clock timing, and no message-count experiment. All complexity claims (O(log n), O(n)) are asymptotic derivations from the algorithm's structure, stated and reasoned about directly in the text (Section IV-C), not measured on any dataset, node count, or topology. No table of results appears anywhere in the paper.

### Parameters
None with numeric deployment values are given; the paper is purely algorithmic/structural. Parameters that appear as free choices in the construction: the branching factor `k` for a k-ary tree (defined generically, not fixed to a value); the specific history-independent data structure chosen as the backing tree, which the paper lists as including treaps, skip lists, zip trees, zip-zip trees, B-treaps, B-skip-lists, randomized-block-search-trees, the external-memory history-independent B-tree and skip-list of Bender et al., skip trees, dense skip trees, Merkle Search Trees, prolly trees, and G-trees — the paper states most of these are clamping-invariant but explicitly proves only the treap case in detail and states proofs for the rest are "out of scope" for this paper; and a "sufficiently small subrange" size threshold below which a node sends raw items instead of continuing to recurse, left unspecified as a number.

### Stated limitations
The fingerprint-computation algorithm's O(log n) running time holds "with high probability," conditioned on the backing data structure having logarithmic height with high probability — the paper's own qualifier, not a worst-case guarantee. A malicious data source can construct trees of n items, with high probability, that degenerate toward a single long chain (analogous to the paper's description of MST degeneration), and for such trees the fingerprint computation and reconciliation cost rises to O(n) for that session — the paper states this explicitly as the price of removing the homomorphic-hash requirement: communication complexity, round count, and censorship resistance (a malicious node's inability to make two honest peers believe reconciliation of mismatched sets succeeded) remain unaffected by such degenerate input, but the fingerprint computation itself does not. Homomorphic-hash-based RBSR, by contrast, is stated to be completely immune to malicious input because it permits self-balancing set data structures and free choice of backing structure — the paper's conclusion states explicitly that "neither option is strictly superior to the other" between the homomorphic and non-homomorphic variants, and that weighing the homomorphic-hashing overhead against this degeneration risk is a decision left to whoever deploys the system. Proofs of clamping-invariance are given in full only for treaps; for the thirteen other listed history-independent structures the paper asserts most are clamping-invariant but declines to prove this, citing complexity, and states prolly trees are explicitly not clamping-invariant, because a prolly tree's chunk boundaries are set by a rolling hash function applied to a window of consecutive items, and clamping changes which items fall within that window, changing the resulting chunk boundaries.

### Requirements it places on the rest of the system
The backing tree data structure that both peers use must be history-independent (equal sets always produce structurally identical trees) and clamping-invariant, or the fingerprints two peers compute for the same subrange over the same items will not match even though the peers hold identical data in that range. Both peers must use the same clamping-invariant, history-independent data structure family — the paper does not describe reconciliation between two peers using different, incompatible backing structures. The hash function used to label tree vertices need only be collision-resistant and preimage-resistant (standard properties any conventional hash such as the SHA family provides); no algebraic/homomorphic property is required of it under this scheme, in contrast to the paper's characterization of the original RBSR presentation. The reconciliation protocol requires both peers to actively transmit fingerprints each round (a symmetric protocol), rather than one peer polling the other for label confirmation.

### Contradicts
The paper's own abstract states this technique "effectively render[s] merkle-search-tree reconciliation obsolete" — this is a value judgment the authors state, not a measured result; the paper's own conclusion softens this by noting the homomorphic-hash-based variant of RBSR retains an advantage (immunity to malicious-input degeneration, and freedom to use any self-balancing structure) that the non-homomorphic variant presented here does not have, and that "neither option is strictly superior to the other." A later reader citing this paper for an unqualified "MST reconciliation is obsolete" claim would not be supported by the paper's own conclusion. This paper's claim that Auvolat and Taïani's Merkle Search Tree scheme has worse average-case performance because its tree shape is pseudorandom rather than optimally balanced, and can be driven to O(n) degeneration by a malicious data source producing a set that collapses the tree to a single large array, is presented as reasoning from the MST construction, not as a measurement against a retrieved implementation of MST reconciliation. This corpus does not yet hold Auvolat and Taïani (SRDS 2019) to verify that characterization independently.
