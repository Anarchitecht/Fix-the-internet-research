## [LAS-EPRINT-26] De-SyRIS: A Decentralized Sybil-Resistant Identity System without a Trusted Credential Issuer
**Citation:** Michal Ľaš, Ivan Homoliak, Juraj Mariani. "De-SyRIS: A Decentralized Sybil-Resistant Identity System without a Trusted Credential Issuer." IACR ePrint Archive, 2026.
**Retrieved:** full text via https://eprint.iacr.org/2026/1723
**Source URL:** https://eprint.iacr.org/2026/1723
**Domain:** F

### What it does
De-SyRIS assigns each human a single decentralized identity resistant to mass fake-account creation (Sybil attack) without any party centrally issuing or vouching for that identity. It combines two independent Sybil-resistance signals so that defeating one alone does not defeat the system: facial-biometric uniqueness checking, and zero-knowledge (a cryptographic proof that a statement is true without revealing the data that makes it true) social-graph analysis proving an entity is reachable from an externally reputable entity through a chain of privately-held connections.

Mechanism, registration: a user's device captures a facial scan, signs it with a Coalition for Content Provenance and Authenticity (C2PA) manifest (cryptographically signed metadata proving when, on what device, and by what application media was captured) to counter synthetic images, and sends scan plus manifest to a Trusted Execution Environment (TEE, a hardware-isolated region of a processor that keeps code and data confidential even from the machine's own operating system) running under Oasis ROFL (a stateless verifiable-compute layer producing an on-chain-verifiable attestation for each computed result). Inside the TEE the system verifies the manifest's freshness and originating application, runs liveness checks, extracts a biometric embedding, and matches it against an encrypted embedding database that only TEEs holding valid remote-attestation quotes can query. A first-time match produces "full" registration; a collision with an existing embedding produces "limited" registration, requiring the new account to collect community endorsements — each already-fully-registered user may issue exactly one endorsement — before it is promoted to full status. The signed TEE result is submitted to the Oasis Sapphire confidential smart-contract chain, which records the embedding hash and reputation state.

Mechanism, connection establishment: two users meeting in person photograph each other, sign the photos with C2PA manifests, and submit them to a TEE, which matches each fresh photo against the counterpart's stored embedding and, on success, computes a connection commitment CC_AB = H(min(ID_A,ID_B) || max(ID_A,ID_B)) so the commitment value is identical regardless of which party computed it. A relayer batches these commitments into an on-chain Merkle tree; users may bypass the relayer and submit directly if the relayer censors them.

Mechanism, social-graph verification (avoids ever exposing the graph itself, which the paper's own related-work section flags as the metadata-leakage failure of public-graph systems such as BrightID and Circles): an entity constructs a recursive zero-knowledge proof (ZK Random Walk) by proving its connection to the previous entity in a path and appending its own identity and reputation score, then forwarding the extended proof to the next hop. A valid path must have length O(log n) (n = number of entities in the network) and accumulate enough reputation along the way to include at least one externally-reputable entity. To prove a path has no repeated entity (a cycle) without revealing which entities are on it, each entity inserted into the path is added to a Bloom filter (a fixed-size bit array that support membership queries with possible false positives but never false negatives) carried forward with the proof; path-distinctness between multiple submitted paths is checked by a pairwise bitwise-AND of their Bloom filters — fewer than 2k set bits in the intersection (k = number of hash functions) indicates the paths are very likely fully disjoint. Once an entity has gathered the required O(log n) mutually disjoint paths, it aggregates them into a single ZK Proof of Paths, submitted to the smart contract, which verifies it and grants non-Sybil status plus an increment to the entity's own accumulated (intrinsic) reputation — letting entities who have proved themselves reduce dependence on externally-reputable anchors over time. State (reputation, connections) changes only at fixed epoch boundaries (3-7 days), requiring re-proof each epoch to stay verified.

### Measured results
| Experiment | Conditions | Result |
|---|---|---|
| Social-graph entity-verification simulation | 100 simulated entities, 30 epochs, three synthetic graph topologies (Holme-Kim, Watts-Strogatz, Kleinberg small-world), two trust-distribution modes (spread: reputation drawn from a normal distribution up to a capped maximum, applied to a percentage of entities; seeded: fewer entities set to the maximum reputation) | In the Holme-Kim model, spread mode needs 15%-30% of entities holding external reputation before verification propagates through the network; seeded mode needs 8%-10%. The paper states the Watts-Strogatz and Kleinberg models are "unsuitable due to weak connectivity" for this test, without a numeric propagation figure for them. |
| ZK Random Walk / ZK Proof of Paths circuit performance (proof-of-concept, Plonky2 scheme, "l" = path length) | Single-machine proof-of-concept implementation; the walk implementation used a simple nullifier array, not the Bloom-filter design described in the mechanism section | ZK Random Walk (linear circuit, per-recursion-depth): compile 1.56s, circuit size 8KB + l x 4.2MB, prove time 328.56ms, verify time 4.44ms, proof size 124KB. ZK Random Walk (cyclic, single self-referential circuit): compile 2.39s, size 8.4MB, prove 630.27ms, verify 4.68ms, proof 130KB. ZK Proof of Three Paths: compile 1.25s, size 16.9MB, prove 1.58s, verify 7.19ms, proof 143KB. ZK Proof of Six Paths: compile 2.65s, size 33.8MB, prove 2.82s, verify 12.41ms, proof 149KB. |
| Bloom filter sizing for path-distinctness checking (worked example, not a simulation sweep) | Path length 10, filter size 4096 bits, 3 hash functions | False-positive rate approximately 0.05%; false-negative rate approximately 0.01% |

The paper states explicitly that "a more detailed analysis is needed to evaluate the algorithm's effectiveness in preventing Sybil entities from obtaining verification" — the 100-entity simulation measures verification reachability under an honest population, not resistance to an adversarial one.

### Stated limitations
The system does not natively support key recovery or revocation; the authors propose, as unimplemented future work, routing recovery through trusted peers in the social graph instead of a centralized authority. The social-graph attack-resistance mechanism has no defense against an attacker who acquires k distinct attack edges (connections) into the honest region by using real, highly reputable identities as gateways to legitimize a large Sybil cluster; the paper states this outright as an open weakness, not merely a theoretical one. The system currently has no mechanism to penalize an entity for connecting indiscriminately with unknown (possibly Sybil) entities, which the authors say is "essential" future work. Entities can censor others by refusing to forward path proofs for them; the paper argues this has "statistically negligible impact" given the required multiplicity of paths but does not measure that claim numerically. Facial biometric registration depends on C2PA for anti-forgery, and the authors state that "since support for the C2PA standard in smartphones is not yet very widespread, it can theoretically be omitted," which the authors say reduces the registration-time defense to social-graph analysis alone. Merkle-proof persistence for zero-knowledge verification requires historical roots to remain available on-chain, and managing that root-availability buffer "without introducing centralized relayer dependencies remains a significant smart contract engineering challenge," per the authors. The reputation-threshold-for-a-valid-path setting is currently a fixed value derived from the maximum achievable intrinsic reputation with no external reputation; the authors state dynamic, network-adapting thresholds are future work. Community-endorsement-based correction of biometric false positives is stated by the authors to risk endorsements being "coerced" or otherwise obtained improperly, and the underlying facial-embedding quality and endorsement mechanism are called ongoing priorities, not solved problems.

### Requirements it places on the rest of the system
Requires at least one operational TEE deployment (the paper specifies Oasis ROFL/Sapphire specifically) that can produce a remotely-attestable computation result; the paper's own discussion section states this is a live risk, not a design abstraction — it cites the 2025 SGX WireTap DRAM-bus-interposition attack (Seto et al., CCS 2025) as the reason the Integritee TEE-based project was discontinued, and states "Intel will not patch [it] as it assumes physical security," concluding that "the secure functioning of TEEs in decentralized environments remains an open question." Requires an encrypted, centrally-hosted (though TEE-gated) database of biometric embeddings reachable by every registering or connecting TEE instance — the paper labels this database "a centralized but encrypted repository," which is a centralization point in storage even though access is cryptographically gated. Requires at least a small externally-supplied reputation signal ("external reputation") injected into a minority of the entity population from outside the protocol, since the protocol's own intrinsic-reputation accumulation only functions once an entity has already completed at least one successful path proof — the system cannot bootstrap Sybil resistance from zero externally-supplied trust. Requires an on-chain relayer (or a fallback direct-submission path with degraded unlinkability) to batch connection commitments into the public Merkle tree; a permanently unavailable or fully compromised relayer forces users onto the direct-submission path, which the paper states "sacrifices some unlinkability." Requires that in-person meetings between connecting entities are not systematically fabricated at scale, since the whole social-graph Sybil-resistance claim rests on the assumption that establishing many mutual connections with honest entities is difficult for an attacker; the paper does not measure how difficult, only asserts it.

### Contradicts
None found within this corpus regarding measured figures. On attribution: the target-registry's own description of this paper states its purpose is partly to determine "whether the trusted-execution-environment manufacturer becomes a new trusted party" — the retrieved text answers this only partially: it identifies Intel SGX and Oasis specifically as the deployed hardware/platform trust base and states outright that TEE security "remains an open question" in decentralized settings, but it does not analyze whether Intel or Oasis Labs becomes a systemic single point of trust comparable to World Network's Orb hardware manufacturer (which the paper's own related-work section criticizes on exactly that basis).
