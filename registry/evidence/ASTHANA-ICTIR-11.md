## [ASTHANA-ICTIR-11] On the Feasibility of Unstructured Peer-to-Peer Information Retrieval
**Citation:** H. Asthana, Ruoxun Fu, Ingemar J. Cox. "On the Feasibility of Unstructured Peer-to-Peer Information Retrieval." 3rd International Conference on the Theory of Information Retrieval (ICTIR), 2011. DOI 10.1007/978-3-642-23318-0_13.
**Retrieved:** full text via http://www0.cs.ucl.ac.uk/staff/ingemar/Content/papers/2011/ICTIR2011B.pdf
**Source URL:** http://www0.cs.ucl.ac.uk/staff/ingemar/Content/papers/2011/ICTIR2011B.pdf
**Domain:** B

### What it does
The paper determines how many nodes an unstructured peer-to-peer network must query, and the resulting network traffic, to retrieve documents at a target accuracy, using a probably-approximately-correct (PAC, a formal framework in which a search returns a result that is correct with a bounded probability rather than deterministically) search model. A query is broadcast to z randomly selected nodes out of n total; each node holds an independently random subset of the document collection sized so its capacity, summed across all nodes, gives a total system storage R = m·r, where m is the number of unique documents and r is a document's average replication count. The probability of retrieving one specific document di, given it is replicated onto r nodes, is P(di) = 1 − (1 − r/n)^z. Retrieval accuracy for a query is defined as the overlap between the top-k documents an exhaustive search over the entire collection would return and the top-k documents the z-node PAC search returns, divided by k. The expected accuracy averaged over all queries, weighted by query popularity qj, is derived for three replication strategies: uniform (every document replicated the same number of times, independent of popularity), proportional (a document's replication count set proportional to its query popularity, ri = R·qi), and square-root (replication count proportional to the square root of popularity, ri = R·√qi / Σ√qi — following Cohen and Shenker's derivation of this as the strategy that minimizes expected search size for a fixed total storage budget R). The query-popularity distribution qi is modeled as a power law, qi = (1/c)·i^(−α), with the normalization constant c and exponent α fit from AOL query logs and a commercial search engine's logs, giving α in the range 0.8 to 1.0.

### Parameters
- Network size n: 1,000,000 nodes (justified by comparison to Gnutella, BitTorrent, and the Faroo commercial P2P search system's claimed user count).
- Collection size m: 10,000,000,000 (10 billion) documents (justified by 2011-era estimates that Google indexed ~20 billion documents, Bing and Yahoo ~12 billion).
- Query rate: 1,000 queries/second (compared against an estimated Google rate of 38,000 queries/second across ~150 million users; the paper states 1,000 queries/second corresponds to each of 1,000,000 nodes issuing ~4 queries/hour continuously, called an upper bound on realistic per-node query rate).
- Target expected accuracy: 90%.
- Per-node storage fraction κ = capacity/m: primary case 1/1,000 (0.1%), giving 5-10 GB local disk; a secondary parametric sweep in Figure 3b covers κ from 0 to 0.02 on a log-linear plot of nodes-queried versus κ.
- Power-law query-popularity exponent α: swept 0 to 1.6 in Figure 1 (fixed search size z=1,000) and Figures 2a/2b (search size swept 0-2,500 at fixed α=0.8 and α=1.0); the communication-cost analysis in Section 4 uses α=0.8 and α=1.0 specifically, values the paper states were measured from AOL query logs and a commercial search engine's logs.
- Query message size: 300 bytes (conservative estimate over a measured average of ~60 bytes, to account for TCP/IPv6 protocol overhead).
- Response size: 1 KB per node, for top-10 results only (justified by the stated finding that users rarely look past the top-10 search results).
- Character encoding assumption: 2 bytes/character (UTF-8 average).
- Node bandwidth for crawling: 25% of 200 KB/s average global internet connection speed (Akamai 2010 report), used during idle time.
- Section 2.2 parametric example (used to introduce the replication-strategy equations, not the main feasibility analysis): m=1,000,000 documents, n=10,000 nodes, κ=1,000 documents per node.

### Stated limitations
The square-root replication strategy is explicitly stated not to be the accuracy-maximizing policy, only the strategy that minimizes expected search size for a fixed storage budget under Cohen and Shenker's derivation; the paper states an accuracy-optimal replication policy is left for future work. The communication-cost analysis considers only bandwidth feasibility, not query latency; the paper states latency analysis, including the fact that an unstructured architecture need not wait for every queried peer to respond before showing partial results, "is part of our future research," not addressed in this paper. The paper's PAC framework covers only the search stage of retrieval, explicitly excluding the acquisition (crawling/indexing) stage from its formal accuracy model, though the crawl-time estimate (58 days per iteration) is given as a separate, informal calculation; the paper states this crawl duration "could degrade the freshness of results and decrease the relevance of documents" and proposes, without evaluating, a cloud-computing-assisted crawling scheme (Amazon EC2 servers funded by donations, distributing crawled fragments via BitTorrent) as a possible mitigation. The known-item search model underlying the core probability equation (Section 2) is stated to be adopted from prior work on file retrieval by exact filename match; the paper states general information retrieval is broader because query terms may match document content, not just a filename, making query-to-document matching more ambiguous — the paper's own extension to ranked top-k retrieval (Section 2.3, Equation 10) is presented as the mechanism that generalizes past this limitation, but the paper does not validate this extension against any real query log or document collection, only derives it analytically. All numeric feasibility results are derived from stated hardware, network, and document-size assumptions (200 KB/s average connection speed, 25 KB average document size, 1 KB compressed result size, etc.), not from a live deployment or a simulation using measured churn or real document/query traces.

### Requirements it places on the rest of the system
Achieving the stated accuracy figures requires the query rate assumption (1,000 queries/second across 1,000,000 nodes) to hold; the per-query cost and per-peer bandwidth figures scale directly with both the query rate and the node-query fan-out z, so a system with a different member count or query rate needs the underlying equations (Equations 8-13) re-evaluated with its own n, m, and target accuracy, not the specific numbers reported here. The square-root and proportional replication strategies both require replication rate ri to be set from the query-popularity distribution qi (ri = R·qi for proportional, ri = R·√qi/Σ√qi for square-root) — this requires the system to observe or estimate per-document query popularity before choosing how many copies of a document to place, which the paper does not itself specify a mechanism for collecting. The accuracy model assumes each node's indexed subset and each query's target node subset are drawn independently at random from the full node population; a query-routing layer that biases node selection (by proximity, by prior contact, or by any non-uniform sampling) would invalidate the closed-form accuracy equations as stated. The crawl-time and per-peer-bandwidth figures assume nodes contribute crawling bandwidth during otherwise-idle time (25% of average connection bandwidth) and 5-10 GB of local storage; a system whose participants cannot supply this much idle bandwidth or storage would not achieve the stated crawl completion time or index coverage.

### Contradicts
None found within this paper's own claims. Against the prior-pass error the governing brief documents (a distributed search system's recall figures misattributed elsewhere as "1.2 million documents across 750 peers, 45-130 peers contacted"): this paper's own primary numbers are 10 billion documents across 1,000,000 nodes, with 780 to 2,750 nodes queried (depending on replication strategy and power-law exponent) to reach 90% accuracy, and a per-query communication cost of 1.0 to 3.6 MB — not the 6 MB figure sometimes associated with this line of work in secondary summaries; that 6 MB, 3-billion-document figure belongs to a different paper's stated bound (Li et al., cited here as reference [1], "On the Feasibility of Peer-to-Peer Web Indexing and Search," IPTPS 2003) and is not a number this paper states or derives.
