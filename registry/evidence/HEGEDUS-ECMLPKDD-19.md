## [HEGEDUS-ECMLPKDD-19] Decentralized Recommendation based on Matrix Factorization: A Comparison of Gossip and Federated Learning

**Citation:** István Hegedűs, Gábor Danner, Márk Jelasity. "Decentralized Recommendation based on Matrix Factorization: A Comparison of Gossip and Federated Learning." ECML PKDD Workshops (DMLE 2019), Springer CCIS 1167, 2019. DOI 10.1007/978-3-030-43823-4_27.
**Retrieved:** full text via https://www.inf.u-szeged.hu/~jelasity/cikkek/dmle19.pdf
**Source URL:** https://www.inf.u-szeged.hu/~jelasity/cikkek/dmle19.pdf
**Domain:** K

### What it does
The paper trains a collaborative-filtering recommender without collecting any user's rating data on a server, comparing two decentralized training regimes on the identical task. Both regimes solve rank-k matrix factorization: given a matrix A of known ratings (rows are users, columns are items), find matrices X and Y whose product approximates A, minimizing squared error over only the known entries plus an L2 regularization term and per-user and per-item bias terms. Each user's row of A and the corresponding row of X stay on that user's own device and are never transmitted; only the shared item matrix Y (which carries no single user's data) moves between devices or between a device and a server. In federated learning, a central server holds the current (t, Y, c) state (t is a per-item update-count vector, c is the item bias vector), sends it to every device in parallel each round, each device computes a local gradient update to Y and c using its own row of A and X, sends that gradient back, and the server averages the received per-item updates weighted by how many devices touched each item, then waits a fixed round length before starting the next round. In gossip learning, there is no server: each device holds its own copy of (t, Y, c), periodically selects one other online device (through a peer-sampling service that returns a live peer's address, assumed supplied by a separate membership component), sends its current model to that peer, and the two devices merge their models by averaging each item row weighted by a per-row "age" counter, where the merged age is the maximum of the two ages being merged (chosen over averaging or summing because the authors' preliminary experiments favored it). Both regimes optionally apply subsampling compression: instead of transmitting every item row of Y, a device transmits only rows for items it has rated (up to a cap of s items) plus, if room remains, a random sample of unrated items, cutting the size of a transmitted update to s/n of a full model where n is the total number of items.

### Measured results
All results are from simulation using PeerSim (a discrete-event peer-to-peer simulator), on the MovieLens 100K, 1M, and 10M rating datasets, using rank-5 factorization, learning rate η = 0.01 and regularization λ = 0.1 (both tuned in the churn-free, low-bandwidth, uncompressed condition and held fixed everywhere else), with each user's rating row assigned to one simulated device connected via a fixed random 20-out-degree overlay graph.

Churn-free scenario (every simulated device stays online for the whole run; all nodes have equal upload/download bandwidth, server bandwidth treated as infinite, which favors federated learning since gossip learning has no server): with 1 local training epoch per round, federated learning converges faster than gossip learning at the very start of the run, but that advantage disappears within a few hours of simulated time; on the largest dataset (MovieLens 10M) the two methods reach nearly identical root-mean-square error (RMSE, the test-set prediction error metric) by the end of the run, and gossip learning outperforms federated learning by a stated significant margin specifically on the 10M dataset. With 10 local epochs per round instead of 1, convergence speed improves for both methods without any additional communication, and the same relative pattern (federated's early lead disappearing, the gap narrowing as network size grows) holds. In every churn-free condition tested, the compressed (10% subsampled) variant of each method outperforms its own uncompressed variant.

Churn scenario (device availability driven by a real smartphone trace, 1191 distinct users, from the STUNner app measuring battery, charging status, bandwidth, and NAT type; a device counted online only while charging and connected with at least 1 Mbit/s bandwidth for at least a minute; about 20% of devices online at any given moment; mean online session length 81.368 minutes; a 48-hour simulated period built from 40,658 overlapping 2-day trace segments): at low bandwidth (full-model transfer time fixed at 1728 s regardless of dataset, giving about 100 iterations over 48 hours) and at high bandwidth (172.8 s transfer time, about 1000 iterations over 48 hours), faster communication produces markedly better final RMSE for both methods because convergence speed then outpaces the rate of churn-induced message loss (a message counts as delivered only if both sender and receiver stay online through the transfer). The paper states the same qualitative pattern as the churn-free case holds under churn: compression improves both methods, and gossip learning's relative performance improves as network size grows.

The paper reports RMSE-versus-time curves (Figures 3 and 4) rather than single endpoint numbers; the results above are the paper's own stated qualitative comparisons drawn from those curves, since the source text as extracted here contains the figure captions and accompanying prose but not the numeric RMSE values plotted on each curve.

### Parameters
Matrix factorization rank k = 5. Learning rate η = 0.01. Regularization parameter λ = 0.1. Overlay topology: fixed random 20-out-degree graph, node count equal to the dataset's user count (943 / 6,040 / 69,878). Federated learning round length Δf: the round-trip time, i.e., the sum of upload and download transfer times; only the upstream (device-to-server) transfer is compressed. Gossip learning cycle length Δg: exactly one model transfer time, proportionally smaller when compression is applied. Compression ratio when applied: subsample size s = n/10 (10% of items), applied identically in both frameworks so total network-wide bytes transferred over a fixed time period match between methods. Full-model transfer time: 1728 s (low-bandwidth condition) or 172.8 s (high-bandwidth condition, a 10x speedup), yielding approximately 100 or 1000 iterations respectively over a fixed 48-hour simulated window; this transfer time is stated to be the same across all three MovieLens datasets despite their different full-model byte sizes (0.6/1.5/4.1 Mbit), meaning the effective per-bit bandwidth differs by dataset. Server bandwidth: modeled as infinite. Device bandwidth: uniform and equal for upload and download across all devices, motivated by an assumption of a low, uniform, configured per-application bandwidth cap in a real deployment. Availability threshold in the churn trace: online requires charging plus at least 1 Mbit/s connectivity sustained for at least one minute. Local training epochs per round: tested at 1 and 10 (churn-free scenario only).

### Stated limitations
The authors state they do not include additional privacy-preserving techniques (Bonawitz et al.'s secure aggregation for federated learning, or the secure distributed mini-batch method the authors cite for gossip learning) in this study; the comparison is stated to concern only communication-pattern efficiency, not privacy or security mechanisms. The paper states gossip learning's correctness assumes a membership service exists elsewhere in the system, supplying each device unique identity (potentially including public/private keys tied to network address) and peer sampling (returning addresses of currently live nodes); the paper states this service can be implemented as centralized, as a dynamic decentralized protocol, or as a static network of random neighbors able to handle NAT devices, but does not itself supply or evaluate any of these three options. The paper states its own conclusion is not to be generalized beyond the study: "one should obviously not jump to conclusions based on one empirical study." The authors state the design space for both protocols is large and many communication-efficiency improvements remain unexplored in either paradigm. The paper states modeling communication constraints and costs realistically is "a non-trivial question" that depends on many factors not fully captured by the fixed-bandwidth, fixed-transfer-time model used here.

### Requirements it places on the rest of the system
Gossip learning as evaluated here requires a membership/peer-sampling service to already exist and supply each device with addresses of other currently live devices; the paper is explicit that this is assumed rather than provided by the mechanism under test, and names three possible external implementations (centralized service, dynamic decentralized protocol, or a static NAT-capable random-neighbor overlay) without selecting or evaluating any of them. The per-row age counter used for merge weighting requires every device to track, for each item, how many aggregation rounds that item's row has participated in, and requires the merge operation itself (age := max of the two merged ages) to run identically on every device pair, so any transport carrying gossip messages must deliver the full (row, age) pair atomically per item rather than allowing partial or out-of-order row updates within one message. A message is counted as delivered in the churn model only if both sender and receiver remain online for the full transfer duration; the mechanism's measured convergence rate is therefore contingent on the transfer-time-versus-churn-rate ratio holding in whatever real deployment reuses this design, since the paper's own results show a 10x bandwidth increase (172.8 s vs. 1728 s transfer time) producing markedly better outcomes purely by letting convergence "beat" churn. Both training regimes require the item matrix Y to be treated as safe to transmit un-encrypted between devices or to the server, on the stated ground that Y carries only user-independent item information; a system substituting a different factorization or feature representation would need to re-establish that its own shared matrix carries no user-identifying signal before reusing this transmission design unmodified.

### Contradicts
None found within this corpus. GOLD-ARXIV-23 (G-Rank), which cites this paper directly (its own bibliography entry [29]), evaluates a different decentralized mechanism (unsupervised click-log ranking rather than supervised matrix-factorization recommendation) on a different task, and reports no figure that overlaps with or conflicts with this paper's RMSE convergence results.
