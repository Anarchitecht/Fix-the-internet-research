## [ALWEN-TCC-20] Continuous Group Key Agreement with Active Security
**Citation:** Joël Alwen, Sandro Coretti, Daniel Jost, Marta Mularczyk. "Continuous Group Key Agreement with Active Security." Theory of Cryptography Conference (TCC), 2020. DOI 10.1007/978-3-030-64378-2_10.
**Retrieved:** full text via https://eprint.iacr.org/2020/752.pdf
**Source URL:** https://eprint.iacr.org/2020/752.pdf
**Domain:** H

### What it does
The paper defines the strongest security notion proved to date, at time of publication, for continuous group key agreement (CGKA) — the primitive that lets a long-lived group of parties, each coming online only sporadically and relaying protocol messages through an untrusted server, agree on a continuously refreshed shared secret key — and gives three CGKA constructions meeting different levels of that notion. The definitions are stated as universal composability (UC) functionalities, so proved security holds when the CGKA protocol is used inside a larger system rather than only in isolation. Two prior simplifying assumptions are removed. The "cannot-inject assumption" had assumed the network adversary never forges a protocol message between a party's state compromise and its recovery; removing it means the definitions cover insider attacks, where an adversary uses one party's leaked state to author messages other parties accept. The "no-splitting assumption" had assumed an untrusted delivery service, when multiple parties propose changes concurrently, always picks one proposal and delivers it to everyone; removing it means the definitions cover an adversary that partitions the group into subgroups holding inconsistent, mutually unaware states. "Optimal security" means a produced key is judged insecure only when the protocol's own correctness trivially reveals it to the adversary, not through any modeling shortcut.

Three constructions are given, all built on the TreeKEM/TTKEM ratchet-tree design (each party occupies a leaf, updates a path to the root, and encrypts new secrets to the co-path's resolution) and formally proved to meet these definitions:
- P-Pas, for a passive-but-adaptive network adversary (permits reordering and dropping messages, forbids forged messages): built by replacing plain public-key encryption with hierarchical identity-based encryption (HIBE), so every ratchet-tree node's key is bound to an identity vector that changes with every operation, which prevents an adversary from re-using leaked state across a group split.
- P-Act, for an active-and-adaptive adversary: augments P-Pas with key-updating signatures (KUS), an analogous primitive for authenticating messages, and a hash-based mechanism ensuring any two parties who accept an injected message land in mutually consistent states; the tradeoff is that different honest parties may disagree on whether to accept the same injected message ("non-robust").
- P-Act-Rob, for an active-but-static adversary: replaces the hash mechanism with a non-interactive zero-knowledge proof (NIZK) attached to every message, proving message well-formedness, so that if any one honest party accepts a message, every honest party does ("robust"); the cost is that the proof is given only in the standard model against a static (non-adaptive) adversary, because the NIZK's use of common reference strings is incompatible with the random-oracle proof technique used for P-Pas and P-Act.

### Measured results
No implementation and no empirical measurement. The paper's results are asymptotic communication- and computation-complexity bounds derived by proof, not benchmarked figures — this entry records them as parameters, not measured facts.

### Parameters
- Fair-weather commit-message size: logarithmic in group size n for P-Pas, stated to hold "if the exact sequence of preceding operations" is favorable; the paper states the cost of the next operation ranges from Θ(log(n)) to Θ(n) depending on that sequence, and that under mild assumptions on participant online/offline behavior it stays in the O(log(n)) range. No numeric threshold for what counts as a favorable sequence is given.
- P-Pas computation cost: linear in group size n in the paper's simplified Appendix C description, because a processing party updates identity labels across the whole labeled tree (LT); the paper states this is not inherent and can be reduced to logarithmic in n by storing, per node, only the index at which the node was created (each identity vector is then a suffix of a global commit-history index) — this optimization is described but not separately re-analyzed for its effect on other costs.
- HIBE ciphertext size: if the HIBE scheme used has constant-size ciphertexts (the paper cites Lewko-Waters, TCC 2010, as an example), P-Pas has only constant blow-up over the underlying TTKEM protocol; otherwise message size grows with the number of commits sent without interaction (not with group size).
- HIBE encryption cost: often linear in HIBE identity-vector length, which equals the number of messages sent without interaction; the paper notes this could potentially be pre-processed for some HIBE schemes, trading commit cost for process cost, but does not evaluate this tradeoff.
- Security assumptions per protocol, stated as theorem hypotheses: P-Pas requires HIBE and public-key encryption (PKE) to be IND-CPA secure; P-Act requires HIBE and PKE to be IND-CCA secure and KUS to be existentially unforgeable under chosen-message attack (EUF-CMA secure); P-Act-Rob additionally requires a NIZK proof system and a common reference string.

### Stated limitations
The paper's own conclusion states all three constructions "scale sub-linearly in the number of parties and polynomially in the security parameter," and explicitly labels them "not practically efficient," offered as feasibility results rather than deployable protocols. P-Act-Rob's robustness proof holds only against a static adversary (one that commits to its corruption targets ahead of time), not the adaptive adversary the other two protocols withstand, because the NIZK's common-reference-string model is incompatible with the paper's adaptive-security proof technique. The paper's PKI model is described as "overly idealized": adding a party is assumed to always retrieve a key genuinely owned by that party, and a joining party has no means to verify that its welcome message actually came from the party claiming to send it, or that the group state it is joining is legitimate and fresh rather than fabricated — long-term identity key compromise and its recovery are stated as unaddressed. The active-setting definitions do not model a fully malicious PKI: a corrupted party cannot upload a self-generated public key without first corrupting an already-enrolled party and injecting an add proposal through that party's leaked state, which the paper states falls short of "full insider security" and is left as an open problem. The paper conjectures, but does not prove, that full UC security is impossible in the standard model (without a random oracle) while preserving logarithmic complexity; whether the paper's weaker restricted-environment UC notion is achievable in the standard model is left open. A named unresolved case ("security of detached nodes"): a party who joins a group and immediately removes the only party whose state was ever exposed can end up with a key the paper's own definition does not certify secure, because not all ancestor epochs of the new party's join point can be determined from available information; the paper conjectures that fixing this requires protocols that are inherently size-inefficient, without proof.

### Requirements it places on the rest of the system
Security proofs are conditioned on a public-key infrastructure (PKI) functionality (F_pki) that is assumed idealized: correctly delivering the actual public key of the party requested, with no verification available to a joining party that its own welcome message came from a legitimate sender. Two of the three constructions (P-Pas, P-Act) are proved secure only in the random-oracle model, requiring every hash function in the deployed system to be treated as programmable (for full UC security) or non-programmable (for the weaker, restricted-environment variant) — the choice determines the strength of guarantee obtained. P-Act-Rob additionally requires a trusted setup providing every party a common reference string for its NIZK system. The paper's security definitions assume the environment issues at most one "Create Group" call per session (bounding the CGKA functionality to a single group's honest history tree, with the model's composability claims resting on that restriction) and, for the strongest composable statements, that the environment avoids corruption patterns causing the "commitment problem" — a restriction the paper states affects only composition guarantees, not the core security statement. The paper additionally requires (Section 9) that any group-communication mechanism update the entire group state on every operation, not just pairwise channels between the two directly involved parties, and gives a concrete attack showing pairwise-channel designs (as used by Signal) and key-homomorphic-encryption designs based on ElGamal-style additive keys both fail the paper's optimal-security notion for this reason.
