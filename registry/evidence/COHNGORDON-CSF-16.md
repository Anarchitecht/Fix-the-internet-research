## [COHNGORDON-CSF-16] On Post-Compromise Security
**Citation:** Katriel Cohn-Gordon, Cas Cremers, Luke Garratt. "On Post-Compromise Security." IEEE Computer Security Foundations Symposium (CSF), 2016. DOI: 10.1109/CSF.2016.19.
**Retrieved:** full text via https://eprint.iacr.org/2016/221.pdf (extended version, v1.4, October 2019 — the paper's own posted revision of the CSF 2016 paper)
**Source URL:** https://eprint.iacr.org/2016/221.pdf
**Domain:** H

### What it does
This paper defines Post-Compromise Security (PCS): the guarantee that Alice regains a security guarantee about communication with Bob even though Bob's secrets have already been compromised by an adversary, without Alice needing to detect that the compromise occurred. Before this paper, standard Authenticated Key Exchange (AKE — a protocol by which two parties derive a shared session key and confirm each other's identity) security definitions ruled out any guarantee once a party's long-term key was learned by an adversary, on the informal argument that a party who knows a long-term key can run every computation the true owner could run and so cannot be distinguished from the true owner. The paper's counterargument: this informal impossibility proof does not account for a session that runs after the compromise and generates fresh, uncompromised secret state — if that later session's fresh state is what future authentication relies on, the original long-term-key compromise is no longer sufficient to sustain an impersonation.

The paper distinguishes two compromise strengths. Weak compromise gives the adversary temporary use of long-term-key operations (for example, temporary control of a Hardware Security Module, a device that performs signing without exposing the key itself) without ever learning the key value; total compromise gives the adversary the long-term key value itself. For weak compromise, the paper proves (Theorem 11) that an ordinary signed Diffie-Hellman (DH) challenge-response protocol already achieves PCS: because the adversary never learns the signing key, once the adversary's temporary hardware access ends, the adversary cannot forge new signatures, so a session run after access ends is secure. For total compromise, the paper proves an outright impossibility for protocols with no persistent state (Theorem 14: no stateless protocol is secure in the paper's KE-PCS model), because a stateless protocol's only secret inputs are the compromised long-term key and fresh session randomness, both of which the adversary can supply itself. To achieve PCS under total compromise, the paper defines a generic transformation from any three-message AKE protocol π into a stateful protocol π† that maintains synchronized secret state ("intermediate secrets") between the two parties across sessions and derives each new session key by mixing in that evolving state; it proves that if π is secure in a strong existing AKE model (ΩAKE∩ISM), the transformed π† is secure in a still-stronger model (ΩAKE) that additionally captures PCS. The paper further proves a companion impossibility (Theorem 19): no correct one-round protocol secure in its PCS model can be post-network robust, meaning any one-round PCS protocol is vulnerable to a denial-of-service attack in which a network adversary permanently prevents two parties from ever again establishing matching session keys, because rejecting a forged message under attack necessarily desynchronizes the parties' persistent state. The paper's full transformation (given as a two-round protocol) is built specifically to resist this failure mode, remaining "post-network robust" even after an adversary with temporary network control interferes.

### Measured results
None. This is a formal-methods paper: its results are definitions, security-model constructions, and theorems with proofs (all proofs given in the paper's appendices), not empirical measurements. No implementation, simulation, or benchmark is reported. The two structural (not empirical) results load-bearing for later composition analysis are Theorem 14 (no stateless protocol achieves PCS under total compromise, unconditionally, for any protocol structure) and Theorem 19 (no one-round protocol that achieves PCS under total compromise can also resist network-level denial of service, unconditionally).

### Parameters
Not applicable — no experiment or implementation is reported. The paper's formal models are parameterized by a set of adversary queries Q (create, send, corrupt, randomness, session-key, and others defined in the paper's Table 2) and a freshness predicate F restricting which query sequences count as valid attacks; the exact predicate clauses making up each named model (eCKw, eCKw-PCS, ΩAKE∩ISM, ΩAKE, KE-PCS) are given precisely in the paper's Table 3, and any downstream use of these models must copy that predicate exactly rather than approximate it, because the difference between predicate clauses is what separates a satisfiable model from an unsatisfiable one (Theorem 14 is exactly the statement that the KE-PCS predicate is too permissive for any stateless protocol to satisfy).

### Stated limitations
The paper's first (weak-compromise, HSM-based) construction assumes only a signature interface to the long-term key — the abstract operation "sign with this key" and nothing else — and the authors state explicitly that most real Hardware Security Modules expose a wider operation set (they cite the PKCS#11 standard as an example), so extending the result to a general key-storage interface, including Diffie-Hellman-style key-derivation operations of the form (chosen exponent)^(stored key), is left as future work, described by the authors as needing care because the interaction between such an interface and DH session-key computation is subtle. The paper considers only necessary conditions demonstrated by one concrete protocol (the signed DH challenge-response of their Figure 4); deriving general necessary or sufficient conditions on protocol structure for achieving PCS under weak compromise is left open, with the sole stated partial result that the signature must cover some freshly generated data. The paper does not address zero-round-trip (0-RTT) protocols like Axolotl/Double Ratchet, which send a first message before any round-trip completes; the authors state as an open question how the ratcheting mechanism's necessity for 0-RTT operation interacts with the security goals of PCS. The generic stateful-protocol transformation targets only signature-based, three-message input protocols; the paper does not claim the transformation's applicability to arbitrary starting protocols outside that message-count and authentication-type assumption.

**Case-study limitation findings — protocols the paper shows fail to achieve PCS, with the specific mechanism of failure:**
- OPTLS (a since-superseded signature-free TLS 1.3 handshake proposal, also matching Google's early QUIC design): the server signs a temporary public key together with a validity period, and that pre-signed key then functions as a standing credential — an adversary with only temporary access to the server's signing key can issue a fake pre-signed key that remains valid and usable for impersonation after the adversary's HSM access is revoked, so the protocol does not achieve PCS even though it separately provides forward secrecy through its ephemeral DH exchange, and this failure persists even if the signing key is held in a Trusted Platform Module (TPM).
- TextSecure/Axolotl (the ratcheting predecessor to Signal's Double Ratchet, as deployed in the discontinued TextSecure messaging app): each user device stored a full copy of the user's long-term identity key but ran an independent, unshared Axolotl ratchet chain per device; an adversary who learned a user's long-term identity key could register a new device under that identity, and other users would accept the new device as legitimate purely on the strength of the correct identity key, so an adversary could keep impersonating a user by registering fresh devices even after the user's genuine devices had completed an honest key-refreshing session that should, under PCS, have locked the adversary out. The paper states it remains unclear whether Axolotl's ratcheting in TextSecure provided any security benefit over a plain strong AKE protocol beyond reducing round trips, though a separately cited earlier analysis (Frosch et al., "How Secure is TextSecure?") found an unrelated unknown-key-share attack and did not itself examine post-compromise security.

### Requirements it places on the rest of the system
The paper's core PCS-achieving construction under total compromise requires persistent, synchronized secret state shared between the two communicating parties across sessions ("intermediate secrets"), so any system adopting it must provide durable per-peer storage that survives between sessions, not just within one session; a fully stateless implementation cannot satisfy PCS under total compromise by Theorem 14, unconditionally, regardless of what other mechanism is layered around it. Robust operation under network interference (post-network robustness) requires at least two message rounds, by Theorem 19 — any system requiring both PCS-under-total-compromise and resistance to network-level denial of service cannot use a one-round handshake, and this trade-off cannot be resolved by adding cryptographic strength, only by adding a round. The weak-compromise (HSM) construction requires that the long-term signing key never leave the isolated hardware boundary in any form — the security proof depends specifically on the key being usable only through a black-box sign operation, so any code path or backup procedure that exports the raw key value invalidates the guarantee entirely, converting a weak compromise into a total one. A system using the paper's key-refreshing transformation must ensure state updates are explicitly tied to successful peer authentication; the paper states that a state update performed without authenticating the peer first risks the deletion of a secret value still needed to communicate with the legitimate peer, which is exactly the flaw the paper's own "robustness" definition is built to rule out. Multi-device deployments must share ratchet/session state across a user's devices, not merely share the long-term identity key per device independently — the TextSecure case study demonstrates that per-device long-term-key copies without shared session state reopens the exact impersonation vector PCS is meant to close.

### Contradicts
None found within this corpus. This paper's own case studies contradict a claim commonly associated with TextSecure/Axolotl and its descendant the Double Ratchet — that ratcheting alone delivers post-compromise security — by showing the specific multi-device implementation TextSecure shipped did not achieve PCS despite using a ratchet; the paper is explicit that this is a fact about the specific multi-device architecture deployed, not a claim that ratcheting mechanisms cannot achieve PCS (Signal's later Double Ratchet, evaluated in COHNGORDON-EUROSP-17 in this corpus, is the two-party protocol built to close this gap).
