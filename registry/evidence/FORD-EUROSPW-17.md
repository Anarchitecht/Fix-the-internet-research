## [FORD-EUROSPW-17] Proof-of-Personhood: Redemocratizing Permissionless Cryptocurrencies
**Citation:** Maria Borge, Eleftherios Kokoris-Kogias, Philipp Jovanovic, Linus Gasser, Nicolas Gailly, Bryan Ford. "Proof-of-Personhood: Redemocratizing Permissionless Cryptocurrencies." IEEE European Symposium on Security and Privacy Workshops (EuroS&PW), 2017. DOI 10.1109/EUROSPW.2017.46.
**Retrieved:** full text via https://infoscience.epfl.ch/record/228239
**Source URL:** https://doi.org/10.1109/EUROSPW.2017.46
**Domain:** E

### What it does
Proof-of-personhood (PoP) lets a person prove they control exactly one cryptographic identity token, tied to one physical body, without disclosing who they are — a basis for Sybil resistance (defense against one attacker registering many identities) that does not depend on spending computation (proof-of-work) or capital (proof-of-stake). The paper builds PoP on the pseudonym party (Ford and Strauss, 2008): a real-world, in-person gathering, organized by any set of volunteers acting as organizers, at which every attendee receives exactly one PoP-token by the end of the event.

The security model is an anytrust assumption: attendees trust only that at least one organizer, and at least one of the organizers' independent servers (a conode, jointly forming a collective authority or cothority), is honest and not colluding with the rest — the specific honest party need not be known in advance. Before the party, organizers fix its place, date, start and end times, a barrier time after which no new PoP-tokens are issued, and a token expiration date, publish these in a configuration file, and run dry-run tests without real attendees. Organizers also select an independent group of observers to record video of the event for transparency and later dispute resolution. Each attendee generates a fresh key pair locally, then derives an ephemeral public key specific to this party by hashing the configuration file into an elliptic-curve point H and computing X' = H^x from the attendee's private key x using Ed25519; this ephemeral key, not the attendee's ordinary public key, is what gets bound to the PoP-token, so using the ephemeral key elsewhere does not compromise the attendee's other-service anonymity. At the party, attendees enter during a fixed window (departure remains free at any time for safety); once the barrier time arrives, no further entry is allowed, and organizers form a line where each organizer individually confirms every attendee's personhood, records the attendee's ephemeral public key, and marks the attendee with a physical ink stamp — visual confirmation that prevents an attendee from returning to the front of the line for a second token. After all organizers have confirmed an attendee, the attendee proceeds to a separate room with no path back to re-enter the confirmation line. At the party's end, the conodes collectively sign a party transcript containing a hash of the recorded video and the full list of attendee public keys; each attendee's PoP-token is the triple of their ephemeral public key, their ephemeral private key, and this attendee-public-key list from the transcript.

To authenticate a PoP-token to an online service without revealing which attendee it belongs to, the paper proposes a linkable ring signature scheme (Liu et al., 2004): the token holder signs a challenge message within a service-specific context, producing both a signature and a verification tag; the service checks the signature against the full anonymity set of attendee public keys in the party transcript, then checks whether the resulting tag already exists in its own database. A first use is accepted and its tag stored; a repeat use of the same token against the same service produces the same tag and is rejected, preventing one PoP-token from creating more than one account per service, without ever revealing which attendee's key produced either signature.

PoPCoin is the paper's proposed cryptocurrency application: a minting pool is formed from attendees who authenticate their PoP-token to a set of trusted servers within a stated validation window (the paper's example: one week) after the party. In the simple variant, the system substitutes proof-of-stake's minter-selection step with a random draw over the PoP-token-holding minting pool, using RandHound (a distributed protocol producing scalable, unbiasable, publicly verifiable randomness run by the last N minters against Byzantine adversaries) to pick the next minter every M minutes; a minter caught extending two chains is punished, which the paper states resolves proof-of-stake's nothing-at-stake problem (the incentive to build on every competing chain since doing so costs nothing). A second variant instead extends ByzCoin (a Bitcoin-like cryptocurrency using collective signing, CoSi, to reduce Practical Byzantine Fault Tolerance's message overhead), replacing ByzCoin's proof-of-work-based sliding share window of size W with PoP-token-based membership, so the consensus group of the last W blocks' minters runs RandHound to select the next window member and then continues as ByzCoin's leader-based collective-signing protocol.

### Measured results
The paper describes a design and a real-world deployment vision; it reports no benchmark, simulation, or measured deployment result of its own (no party was run and measured as part of this work). Its only comparison against a competing scheme is qualitative: the paper states the Proof-of-Individuality (PoI) project, which uses virtual video-based pseudonym parties plus Ethereum smart contracts, has three disadvantages relative to this paper's physical-pseudonym-party approach — it needs a separate mechanism to confirm a submitted video is an actual live stream rather than a recording; it depends on Ethereum's security and in turn on Ethereum's proof-of-work foundation, so it cannot alone bootstrap a secure cryptocurrency; and it adds implementation complexity from that Ethereum dependency. No figure accompanies any of these three points; each is a design comparison, not a measurement.

### Parameters
- Party timing parameters: place p, date d, start time t_start, end time t_end, barrier time t_barrier (after which no new tokens are issued), and token expiration date t_exp — every value is fixed per-party by the organizers, with no numeric example given in the paper.
- PoPCoin block interval M: the period, in minutes, after which minters repeat the minting selection process; no concrete value is given, only the variable name.
- ByzCoin sliding window size W: the number of most recent blocks whose minters form the active consensus group; no concrete value is given.
- RandHound participant count N: the last N minters run RandHound to produce the randomness selecting the next minter; no concrete value is given.
- PoPCoin token-authentication validation window: the paper's own illustrative example is one week, explicitly marked as an example ("e.g., one week"), not a derived or measured requirement.

### Stated limitations
The paper states PoPCoin is envisioned to begin as a small local cryptocurrency (comparable to community currencies such as Ithaca Hours, BerkShares, and the Leman), with a pseudonym party held roughly every few months, before any larger-scale federation across independent local groups is attempted; the paper offers no evidence such federation is technically solved, describing it as a future step contingent on the initial local experiment succeeding and gaining traction. Scaling PoP-token issuance to prevent one person from obtaining tokens at two simultaneous parties in different regions is proposed to rely on physical travel infeasibility (the paper's example: traveling from Europe to the US west coast within a few hours), which the paper states depends on the parties' relative timing and geographic separation rather than on any cryptographic guarantee. The paper states the PoI project's video-based virtual pseudonym party does not provide the same security properties as an in-person physical pseudonym party, specifically because confirming a submitted video is a genuine live stream and not a pre-recording is an unsolved requirement for that competing approach; this paper's own physical-party design is presented as avoiding that specific problem by requiring physical co-presence, not as having solved video-liveness verification itself.

### Requirements it places on the rest of the system
Running one pseudonym party requires a set of volunteer organizers, each operating an independent server (conode) that together form a collective authority, and requires at least one organizer and at least one conode among them to be genuinely honest and non-colluding for the anytrust security assumption to hold; the specific honest party need not be identified in advance, but its existence is a precondition the protocol does not itself enforce or detect. The party additionally requires an independently selected group of observers to record video for transparency, and the paper leaves the process of independently selecting both organizers and observers as external to the protocol it specifies. Every attendee must generate their key pair locally, on their own device, before the party, and must derive their party-specific ephemeral public key from the published configuration file using the paper's Ed25519-based hash-to-point construction; a service that authenticates PoP-tokens must obtain and hold the party transcript (published by organizers on trusted servers) to validate a token's origin and expiration date, and must independently maintain its own per-service database of linkable-ring-signature tags to detect a repeated use of the same token. The PoPCoin minting mechanisms require RandHound's distributed randomness generation to be run by a live, cooperating subset of current minters (the last N, or the current window's W minters in the ByzCoin variant) at each selection round, and require a punishment mechanism external to the paper's own description to be enforceable against a minter caught extending two chains, for the stated resolution of the nothing-at-stake problem to hold in practice.

### References worth retrieving
- Ford, Strauss, "An offline foundation for online accountable pseudonyms," Workshop on Social Network Systems, 2008 — foundational (the original pseudonym-party construction this paper's PoP mechanism is built directly on).
- Liu, Wei, Wong, "Linkable spontaneous anonymous group signature for ad hoc groups," ACISP 2004 — foundational (the linkable ring signature scheme this paper's PoP-token authentication mechanism uses to prevent one token from creating multiple accounts per service).
- Kogias, Jovanovic, Gailly, Khoffi, Gasser, Ford, "Enhancing Bitcoin security and performance with strong consistency via collective signing," USENIX Security 2016 — foundational (introduces ByzCoin and CoSi, both directly used by this paper's second PoPCoin construction).
- Proof of individuality project (cited as an online resource, consulted October 2016) — competing (the video-based virtual pseudonym-party alternative to this paper's physical-party design, with three stated disadvantages relative to it).
- Douceur, "The Sybil attack," IPTPS 2002 — foundational (the attack this paper's proof-of-personhood mechanism, and Sybil-resistance mechanisms generally, are designed to resist).
- Nakamoto, "Bitcoin: A peer-to-peer electronic cash system," 2008 — foundational (the proof-of-work "one CPU one vote" minting principle this paper's PoPCoin proposes to replace with a "one PoP-token one vote" principle).
