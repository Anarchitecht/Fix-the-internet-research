## [PATRA-TIT-25] Generalized Regenerating Codes and Node Repair on Graphs

**Citation:** Adway Patra, Alexander Barg. "Generalized Regenerating Codes and Node Repair on Graphs." IEEE Transactions on Information Theory, 2025. DOI 10.1109/TIT.2025.3532625.
**Retrieved:** full text via https://arxiv.org/abs/2405.11714 (arXiv:2405.11714v1, 20 May 2024)
**Source URL:** https://arxiv.org/abs/2405.11714
**Domain:** C

### What it does
A generalized regenerating code (GRC) repairs a failed storage node while accounting for the fact that helper nodes sit at different distances from the failed node on a communication graph, so nodes farther away transmit less data than nodes close by, reducing total transmission cost below what a distance-blind scheme spends. The paper defines an [n, k, d, l, B, M] GRC over a graph G = (V, E): a file of M symbols is stored as l symbols in each of n nodes, any k of the n nodes reconstruct the file, and repair of a failed node contacts d helper nodes and downloads a fixed but not-necessarily-equal quantity beta_i (drawn from a set B of d positive integers) from the i-th helper under a chosen assignment. Because remote helpers' data passes through nearer helpers on the way to the failed node, the paper defines Intermediate Processing (IP): a helper node closer to the failure combines the data it receives from farther helpers with its own contribution before forwarding, rather than simply relaying each helper's data unmodified (which the paper terms Accumulate-and-Forward, AF). The paper proves a cutset bound on the minimum total download for any GRC (Theorem II.1), gives a stacking code construction that meets this bound at the Minimum Storage Regenerating (MSR) point (repair with the least possible per-node storage), proves a further lower bound specific to IP repair (Theorem III.1) and conditions under which the stacking construction is IP-optimal, and extends the model to a limited-power adversary that corrupts the stored contents of up to t helper nodes without controlling their computation, giving a cutset bound with error correction (Theorem VI.3) and a construction concatenating the MSR stacking code with a Gabidulin rank-metric code to correct errors at the failed node during repair.

### Parameters
- B = {beta_i}, i=1..d (per-helper download amounts): free design parameter of a GRC; uniform download is the special case where all beta_i are equal.
- d (repair degree, count of helper nodes contacted): free parameter; the MSR point is defined by l = Delta_{d-k+1}(B), the MBR (Minimum Bandwidth Regenerating) point by l = Delta_d(B) = sum of all beta_i.
- t (adversary power, maximum number of helper nodes with corrupted stored contents): free parameter of the adversarial model; the paper's construction requires N - K >= 2*Omega_t(B) for the concatenated Gabidulin code to correct the resulting errors, where N, K are the outer Gabidulin code's length and dimension.
- Worked example parameters: n=10, k=5, l=15 or 25, beta=5, d=7 (AF) or d=9 (IP construction), t=1 adversarial node, outer code [N=25, K=15, D=11] Gabidulin code with minimum rank distance D=11 correcting up to floor((D-1)/2)=5 rank errors (paper states correction capacity as (N-K)/2 >= Omega_t(B)).

### Stated limitations
The adversary model analyzed is a limited-power adversary that corrupts a helper's stored data but does not control that helper's computation on the data it forwards; the paper states an all-powerful adversary that actively controls a vertex's computation is a harder problem it does not address, citing that model as open in the cited network-coding literature. The error-correcting construction (Section VI-C) supports repair and error correction only for systematic nodes, not for all nodes in the code; the paper's concluding remarks state designing codes that support adversarial repair with optimal overhead for all nodes, not only systematic ones, as future work. Data retrieval by a Data Collector under restricted graph connectivity is analyzed only at the MSR point, where the paper states standard relaying is already optimal because MSR codes are maximum-distance-separable; the paper states retrieval away from the MSR point (for example at the MBR point) is estimable and left largely unaddressed in this paper. Designing an algebraic (non-stacking) construction that lets the same helper node contribute a different download amount across different repair rounds is listed as an open problem the authors state they believe is difficult.

### Requirements it places on the rest of the system
Repair requires the system to know, at the time of repair, the graphical distance from each candidate helper to the failed node, since the download-amount assignment tau: D -> [d] that determines each helper's beta_i is chosen based on that distance; the paper's bounds and constructions assume this distance information is available and correct. Intermediate Processing requires helper nodes along the path from a remote helper to the failed node to perform linear combination of the data they relay, not simple retransmission, so a network layer or protocol that forwards data unmodified (pure relaying) cannot realize the IP repair-bandwidth savings the paper proves, only the Accumulate-and-Forward baseline. The adversarial construction requires helper computation to remain uncorrupted even when stored contents are corrupted (the limited-power adversary model); a system in which a compromised helper can also falsify the linear combination it computes and forwards, rather than only its stored value, falls outside every guarantee this paper proves. Reconstructing the original file from k nodes, and repairing a failed node from d helpers, both require the specific graph-and-code pairing fixed at construction time; the paper's bounds hold for a fixed graph topology, and the paper does not analyze what happens under topology changes during repair.
