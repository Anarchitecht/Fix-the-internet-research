## [ANDONI-ARXIV-26] Efficient Algorithms for Adversarially Robust Approximate Nearest Neighbor Search
**Citation:** Alexandr Andoni, Themistoklis Haris, Esty Kelman, Krzysztof Onak. "Efficient Algorithms for Adversarially Robust Approximate Nearest Neighbor Search." arXiv:2601.00272, 2026. DOI 10.48550/ARXIV.2601.00272.
**Retrieved:** full text via https://arxiv.org/pdf/2601.00272
**Source URL:** https://arxiv.org/abs/2601.00272
**Domain:** B

### What it does
This paper gives algorithms that answer Approximate Nearest Neighbor (ANN) queries correctly with high probability even when an adversary chooses both the searched dataset and every query adaptively, after seeing every prior answer — a threat model under which the paper shows ordinary randomized nearest-neighbor data structures can be forced to fail. The (c,r)-ANN problem (Definition 1.1) is: given a dataset S of n points in a metric space, a radius r, and an approximation factor c, build a data structure that, for a query point q, returns some point within distance c*r of q if any point within distance r of q exists, and otherwise may answer "no such point." Locality-Sensitive Hashing (LSH), the standard oblivious solution, groups points so that nearby points collide in the same hash bucket with higher probability than far points; a prior attack (Kapralov et al., 2024, cited but not reproduced in this corpus) is stated to show that an adaptive adversary needs only a number of queries polynomial in log(n) to learn enough about an LSH structure's internal hash functions to make it fail on a subsequent query.

The paper's adversarial-robustness model (Definition 3.1) is a game: the adversary picks the dataset S; the algorithm preprocesses S using private internal randomness the adversary cannot see; then, over Q rounds, the adversary picks each query using the full history of previous queries and answers, and the algorithm must answer correctly in every round with probability at least 1 - delta over its own randomness, for the run to count as delta-adversarially-robust. The dataset may also be updated (points added or deleted) obliviously, meaning the adversary fixes the update schedule in advance rather than adapting it to the algorithm's answers.

Three constructions are given, all working by preventing the adversary from learning the algorithm's internal randomness rather than by hiding the output (unlike the noise-adding techniques used for numeric estimation problems, which the paper states do not apply to search problems because the output must be an actual dataset point, not a perturbable number):
1. Fairness-based robustness (Theorem 1.2): building on prior work on "fair" ANN algorithms that select a valid answer uniformly at random from the qualifying candidates (Aumuller et al., 2022), the paper proves that any exact fair ANN algorithm is automatically adversarially robust, because uniform random selection is a form of statistical independence across queries that denies the adversary a learnable signal.
2. Search-to-decision via bucketing (Theorem 1.3): the search problem is reduced to a weak decision problem (does a point within r exist? does one within c*r not exist?) that can be solved by an oblivious LSH structure and then made robust with differential-privacy techniques (Hassidim et al., 2022) — maintaining Θ(sqrt(Q)) independent copies of the decision structure and combining their answers privately (via subsampled aggregation, avoiding a private-median step the prior framework needed). The dataset is partitioned into buckets of about sqrt(n) points each, a robust decider is run per bucket to find which bucket holds a qualifying point, and that bucket is then searched exhaustively for the final answer.
3. Concentric-annuli construction (Theorem 1.4): to remove the sqrt(n) floor the bucketing method imposes on query time, the (r, c*r) annulus around a query is split into several smaller concentric sub-annuli, the fair algorithm from construction 1 is run within each sub-annulus, and a counting argument guarantees at least one sub-annulus has low enough point density that the fair algorithm terminates quickly with probability at least 0.9; a differentially private selection step then picks a favorable sub-annulus to run the final (held-out) query on, without revealing which internal randomness the selection is based on to the adversary.

A separate "for-all" family of algorithms (Theorem 1.5 and Appendix D) targets a stronger, different guarantee: with probability at least 0.99, the built data structure answers every possible query correctly (not merely each of Q adaptively chosen queries with per-round failure probability delta), by discretizing the metric space into a covering and running enough independent LSH hash functions that a union bound over all points in the covering succeeds. This is stated to apply only to low-dimensional metric spaces, defined here as the regime d = O(sqrt(Q)), as opposed to the high-dimensional regime d = omega(sqrt(Q)) the fairness/privacy constructions target.

### Measured results
Every figure in this paper is a proved asymptotic bound over an abstract computational model, not an empirical measurement; there is no implementation, dataset, or run reported anywhere in the text. The bounds and the exact model conditions each depends on are:

### Parameters
- n: dataset size (number of points).
- d: dimensionality of the metric space.
- c: the ANN approximation factor (c >= 1); larger c generally drives rho(c), and therefore query-time exponents, toward 0.
- r: the target radius defining a "near" neighbor; c*r is the radius defining the discard threshold.
- Q: the total number of adaptive queries the algorithm must remain robust against; several constructions' space costs scale with sqrt(Q).
- delta: the per-construction failure probability bound (adversarially-robust constructions) or, for the for-all family, the paper fixes a concrete constant success probability of 0.99 rather than a tunable delta.
- rho(c): the LSH quality exponent, metric-space- and construction-dependent; explicit closed form given only for the Hamming hypercube under the best known LSH construction, rho(c) = 1/(2c-1) (cited to Andoni and Razenshteyn, 2015).
- beta (concentric-annuli construction): beta = min_{k in positive integers} max(rho(c^(1/k)), 1/k), a derived quantity from rho and c, not an independently chosen parameter.
- Regime split: high-dimensional d = omega(sqrt(Q)) is where the fairness/decision/annuli constructions (Theorems 1.2-1.4) are the paper's contribution; low-dimensional d = O(sqrt(Q)) is where the for-all constructions (Theorem 1.5, Appendix D) apply instead.

### Stated limitations
Theorem 1.2's query time is stated to depend on the density ratio D between the c*r-ball and r-ball around a query, and the paper states the adversary can construct a dataset where this ratio is large, "severely degrading performance" — this is an explicit, named weakness of the fairness-only construction, not merely an unoptimized bound. Theorem 1.3's query time is stated to always be at least O(sqrt(n)) regardless of how favorable c is, which the paper calls not ideal given that oblivious LSH methods can push the query-time exponent arbitrarily close to 0 by increasing c. The for-all family (Theorem 1.5, Appendix D) is stated to have space complexity that scales by an extra factor of d, "making them intractable for high-dimensional metric spaces," a direct consequence of needing enough independent hash functions to union-bound over every possible query; the paper also states these for-all algorithms "lack the generality of their adaptive counterparts" because each is tailored to a specific metric space rather than working generically. The adversarial-robustness game defined here (Definition 3.1) treats updates to the dataset as oblivious — chosen in advance by the adversary, not adaptively based on the algorithm's answers — and the paper states it is "not concerned with robustness" against adaptively chosen updates, only queries. The conclusion states three explicit open questions the paper does not resolve: whether matching time/space lower bounds exist for robust ANN algorithms, whether the fairness-to-robustness link generalizes to estimation problems beyond search, and — stated directly — that "a practical implementation of our approach and the nuances it presents in a real system are also important avenues to investigate," meaning no implementation or systems-level evaluation exists in this paper.

### Requirements it places on the rest of the system
Every construction requires the algorithm's setup-phase and per-query internal randomness to be genuinely private from the adversary (Definition 3.1 states the adversary "may know the code for A but not the specific instance of R_setup"); a real deployment must therefore supply a source of randomness the querying party (or anyone observing the querying party's queries and answers) cannot predict or reconstruct — the proofs give no robustness guarantee if this randomness leaks through a side channel the model does not account for. The bucketing and concentric-annuli constructions both require access to a differential-privacy composition and amplification toolkit (the Laplace mechanism, privacy amplification by subsampling, and adaptive/parallel composition theorems, all cited to prior differential-privacy literature and used, not re-derived, as noted in Appendix B) — a system adopting this mechanism needs a correct implementation of these DP primitives, since the robustness proof is built on their guarantees holding exactly. The fairness-based construction (Theorem 1.2) requires an existing exact fair ANN algorithm as a subroutine (cited to Aumuller et al., 2022) that returns a uniformly random valid neighbor, not merely the closest one, so a system without such a subroutine cannot use this construction directly. The bucketing and annuli constructions both require maintaining sqrt(Q) or more independent copies of an underlying LSH-based decision structure simultaneously, so a deployment must know (or bound) Q, the number of future adaptive queries it needs to remain robust against, in advance, since the space cost is stated as a function of Q rather than being unboundedly extensible. The for-all algorithms require the metric space to be discretizable into a bounded covering (explicit constructions given only for the Hamming hypercube and l_p spaces), so applying them to an arbitrary or unbounded metric space is out of scope as stated.
