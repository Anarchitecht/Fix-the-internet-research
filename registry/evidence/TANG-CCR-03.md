### What it does
pSearch answers full-text and semantic queries in a peer-to-peer network by placing document representations at network locations chosen so that a query only has to contact nodes near the query's own representation, instead of contacting every node (query broadcast) or maintaining one global inverted index. It runs on eCAN, a hierarchical version of the CAN (Content-Addressable Network) distributed hash table (DHT) that the paper states routes in O(log n) hops and follows paths approximating the underlying Internet topology (this bound and the topology claim are attributed to the eCAN report, Xu and Zhang, HPL-2002-41, and not re-derived inside this paper). CAN organizes a logical address space as a d-dimensional Cartesian space (a d-torus) partitioned into zones, each owned by one or more nodes; an object's key is a point in this space, and the object is stored at the node owning the zone containing that point, so locating an object reduces to routing to the zone containing its key.

Two algorithms are defined, both keying eCAN storage locations off information-retrieval (IR) representations of documents. Peer-to-peer Vector Space Model (pVSM) computes each document's Vector Space Model (VSM) term vector — each vector element weighted by term frequency times inverse document frequency (TF*IDF) — takes the m most heavily weighted terms, hashes each term with a hash function h into a point in the CAN space, and stores (h(term), document-index) pairs at the nodes owning those points. A query hashes each of its own terms the same way, routes to the corresponding nodes, and each contacted node ranks locally using VSM before returning candidates to the querying node, which merges and re-ranks them globally.

Peer-to-peer Latent Semantic Indexing (pLSI) instead computes each document's semantic vector using Latent Semantic Indexing (LSI, a term-document matrix decomposition that maps documents into a lower-dimensional semantic space), and uses that vector directly as coordinates in a CAN space of matching dimensionality (l = k, where l is the LSI space's dimensionality and k is CAN's). A document's (semantic-vector, index) pair is stored via eCAN routing on that key; a query's semantic vector is computed the same way and routed to the corresponding zone, then the query is flooded outward to nodes within a radius r (set by a similarity threshold or a target result count) so that documents whose semantic vectors are close but not identical to the query's are still found. Because LSI semantic vectors are normalized to unit length and therefore lie on the surface of a hypersphere, a naive placement onto CAN coordinates is unbalanced; pLSI first transforms an l-dimensional semantic vector S = (s1, ..., sl) into an (l-1)-dimensional parameter vector using the polar-coordinate transform theta_j = arctan(s_(j+1) / sqrt(sum_{i=1}^{j} s_i^2)) for j = 1, ..., l-1 (the paper's Equation 1), and routes using the parameter vector instead of the raw semantic vector, because points on the unit hypersphere have only l-1 degrees of freedom.

Because LSI's semantic space typically has 100-300 dimensions and nearest-neighbor search degrades in that many dimensions (attributed to Weber, Schek, and Blott, VLDB 1998), pLSI reduces dimensionality with a multi-plane scheme: the lower elements of a parameter vector (which the paper states carry decreasing importance as a consequence of the underlying singular value decomposition, so earlier elements matter more) are partitioned into several low-dimensional subvectors, one per plane, and CAN's own dimensionality is set to that of a single plane. Each subvector is used as the DHT key for routing and flooding on its plane independently; each plane returns its own locally best-matching documents into a combined pre-selection set, which the query's originating node then re-ranks using the full semantic vector.

Node bootstrap for both algorithms is modified from plain CAN: a joining node picks a random document it is about to publish and routes its join request toward that document's own key (term vector position for pVSM, parameter vector position for pLSI) rather than to a uniformly random point. This ties a node's zone location to the content it is about to host, producing three effects the paper attributes to this choice: load balancing (each node ends up storing roughly the same number of index entries, because node density in the space tracks index density), index locality (a node's other published content tends to land in its own or neighboring zones), and query locality (a user's queries tend to be searched in zones near where that user's own content already lives, because a user's queries reflect the user's own interests).

### Measured results

|---|---|---|
| pVSM index-completeness on MEDLINE | Storing a document's index under its 30 most important terms achieves a result "as good as" full VSM: with high probability, at least one query term is among a document's top-30 stored terms whenever VSM itself would have returned that document | MEDLINE corpus, 1,033 documents; no node count, hardware, or run count stated for this specific experiment |

No message-count, bandwidth, or latency figures are given for pVSM; its only stated quantitative property is that the number of nodes it must visit for a query "is bounded by the number of terms in the query, which is usually small," a structural claim rather than a measured count.

### Parameters
- m (pVSM): number of most-heavily-weighted terms under which a document's index is stored; the paper states 30 achieves near-full-VSM recall on the MEDLINE experiment, and separately states m can vary per document (Section 3.4).
- l, k (pLSI): dimensionality of the LSI semantic space (l) and of the CAN Cartesian space (k); the paper sets l = k so the LSI vector can serve directly as CAN coordinates before the polar transform reduces it to l-1.
- LSI semantic-space dimensionality in practice: stated as 100-300 dimensions ("medium dimensionality"), the range that triggers the curse-of-dimensionality problem the multi-plane scheme addresses.
- Number of planes: 4-6, found effective by parameter search on the TREC/pLSI experiment.
- Dimensions (parameter-vector elements) per plane: about 10-12, found effective in the same search.
- Flooding radius r (pLSI): set per query by either a similarity threshold or the number of documents the user wants; no default numeric value is given.
- Per-plane result counts in the worked example: 30, 20, 10 for the first three planes when the user wants the top 15 documents (a fixed illustrative choice, not a derived or swept parameter).

### Stated limitations
The paper states outright that, "due to the space limit," further results and the authors' own suggestions for configuring the system are deferred to a later, separate publication — the evaluation in this paper is explicitly partial by the authors' own statement. Four problems are listed as needing solutions for pLSI (sphere distribution of semantic vectors producing unbalanced load, uneven distribution of semantic vectors on the hypersphere producing hot spots, the curse of dimensionality at 100-300 dimensions, and a global-statistics dependency), and the paper addresses each one but does not claim to have measured the residual hot-spot skew after its fixes are applied. A "global state problem" is stated for both pVSM and pLSI: both need global information (the term dictionary and inverse document frequency values for pVSM; comparable global statistics for pLSI) computed from a representative document sample and merged periodically over a combining tree that approximates the network topology; the paper states it expects this global state to change slowly, "at the rate of weeks or even months," an assumption rather than a measured update rate. Coarse-granularity indexing (clustering many documents at one node into fewer index entries via hierarchical k-means) and relevance feedback (both the conventional query-refinement use and an index-migration use, where a popular document's index is stored under more terms or moved closer to the queries that successfully retrieve it) are both listed under "Advanced Issues" as left for future work, with no evaluation given for either in this paper.

### Requirements it places on the rest of the system
pSearch requires eCAN as its routing substrate specifically, not a generic DHT: the load-balancing, index-locality, and query-locality properties described above all depend on eCAN's bootstrap process being modified so a joining node's position is chosen from a document it is about to publish, which is a change to the DHT's join protocol, not an add-on above an unmodified DHT. Both pVSM and pLSI require every participating node to compute IR representations locally (VSM term vectors with TF*IDF weights, or LSI semantic vectors via singular value decomposition) using a shared global dictionary and shared inverse-document-frequency statistics; producing and maintaining that shared global state requires a combining-tree mechanism sampling documents across the network, which the paper assumes changes slowly enough (weeks to months) that its own staleness is not a documented problem. pLSI's flooding step requires every node within a query's flooding radius r to receive and answer the query, so the radius, not just the destination node, determines message cost per query; the paper gives no formula relating r to node density or query accuracy beyond the empirical 0.4%-1.0%-of-nodes-for-95%-accuracy point in Figure 5. The multi-plane dimensionality reduction requires a document's index to be published independently to a node on every plane (4-6 separate publications per document in the effective configuration found), so storage and publication cost scale with plane count. Nothing in the extracted text states an assumption about participant honesty; the mechanism as described assumes every node that receives a routed or flooded query answers it correctly and returns its true local ranking.
