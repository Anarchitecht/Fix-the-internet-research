Abstract
Approximate nearest neighbor search (ANNS), also known as vector
search, is an important building block for various applications, such
as recommendation systems, biometric authentication, and machine
learning. In this work, we are interested in the private ANNS prob-
lem, where the client wants to learn (and can only learn) the ANNS
results without revealing the query to the server. Previous private
ANNS works either suffer from high communication cost (Chen
et al., USENIX Security 2020) or work under a stronger security
assumption of two non-colluding servers (Servan-Schreiber et al.,
SP 2022). We present Panther, an efficient private ANNS framework
under the single server setting. Panther achieves its high perfor-
mance via several novel co-designs of private information retrieval,
secret-sharing, garbled circuits, and homomorphic encryption. We
made extensive experiments using Panther on four public datasets,
showing that Panther could answer an ANNS query on10million
points in18seconds with284MB of communication. This is more
than7.8×faster and20×more compact than Chen et al..

1 Introduction
The𝑘-nearest neighbors search (𝑘-NNS) is a fundamental prob-
lem in the fields of machine learning, data mining, and pattern
recognition. Given a database of multidimensional points,𝑘-NNS
aims to find the top-𝑘 closest points to a query point.𝑘-NNS has
numerous applications, such as recommendation systems [9, 56],
image recognition [31], biometric authentication [7], and Retrieval-
Augmented Generation (RAG) [23, 32] in large language models. In
the case of large, high-dimensional databases where exact𝑘-NNS
is prohibitively expensive, the problem is often relaxed to approxi-
mate nearest neighbors search (ANNS), which returns points highly
likely to be among the top-𝑘 closest neighbors, rather than guaran-
teeing the exact top-𝑘. Compared to exact𝑘-NNS, there exist several
more efficient algorithms [22, 28, 35, 37–39, 45, 54, 57, 59, 63] for
ANNS.
Normally, ANNS algorithms require knowing the database and
the query point in plaintext to proceed. However, there exist scenar-
ios where both the database server and the query client are reluc-
tant to reveal their sensitive data to each other. Examples include
genome similarity search [4] and fingerprint recognition [16, 24, 34].
To this end, proposing private ANNS services based on secure multi-
party computation (MPC) would be beneficial.
A considerable number of studies have been conducted along this
line. Some of them [4, 51, 53, 67] use a full database distance com-
putation, and thus are only practical for small or low-dimensional
databases. Some works [50] try to increase efficiency at the cost
of extra information leakage. Another popular choice is to build
the system under a multi-server setting [ 13, 48, 52, 60], where

the client’s privacy only holds if the servers do not collude. They
adopt such setting because the complexity of MPC could be greatly
reduced given the additional assumption of non-colluding partici-
pants. However, for clients seeking private ANNS services, systems
relying on such security assumptions may be less trustworthy than
those in a single-server setting.
In USENIX Security 2020, Chen et al. [11] propose the milestone
framework SANNS that scales to a database of 10 million entries in
the single server setting. However, SANNS relies on several secure
computation techniques with high communication overhead, such
as distributed oblivious RAM (DORAM) [17] and garbled circuits
(GC) [61]. As a result, SANNS requires several gigabytes of commu-
nication per query, which is not deployable over realistic network
connections (Section 8.3, [48]).
Designing an efficient single server private ANNS is challenging
due to two main reasons. First, a common approach in ANNS is to
partition the database into clusters, so that top-𝑘 distance compu-
tations are only required on those clusters close to the query point,
rather than the entire database. While reading the content of these
clusters is straightforward in plaintext, it needs to be done oblivi-
ously in MPC, often necessitating costly primitives like DORAM.
Second, computing the top-𝑘 elements in MPC is resource-intensive.
For instance, secret sharing (SS)-based methods [20] can require nu-
merous communication rounds, while GC-based methods, as used
in SANNS, can lead to high communication costs. These challenges
underscore the difficulty of the secure ANNS problem.
1.1 Our Contributions
This work focuses on an efficient pipeline for addressing the pri-
vate ANNS problem in the single server setting. Through a careful
integration of private information retrieval (PIR), secret sharing,
garbled circuits, and homomorphic encryption (HE), we success-
fully designed a systemPanther that is scalable to datasets with tens
of millions of samples, and is much more efficient than previous
works. Our contributions in this work are four-fold:
• We design a novel “shuffle-and-reveal" protocol that enables us
to efficiently address the oblivious read problem in secure ANNS,
leveraging batch PIR instead of the costly DORAM. This approach
reduces the communication cost for this step by97%∼99%.
• We propose several efficient and nontrivial methods for the “PIR
to secret shares" problem, including post-processing PIR results
(which are homomorphic ciphertexts in special format), and op-
erating under the ring𝑍2𝑘 in PIR. These are important building
blocks when one wants to securely evaluate a function on the
PIR results without disclosing the results, and could be of broader
interest.
• We propose a mixed-primitive approach (combining SS and GC)
for top-𝑘 selection, paired with a carefully designed selection
network, reducing the communication cost by85%∼90%.
• We open-source Panther1, a fully implemented framework for se-
cure ANNS. We conducted extensive evaluations on the datasets
SIFT-1M, Deep1B-1M, Deep1B-10M and Amazon, which are com-
monly used benchmarks in the ANNS literature. Results show
that Panther achieves up to7.8× faster than the state-of-the-art

method [11] with the same accuracy, and the communication
cost is reduced by more than one order of magnitude.
2 Related Work
Approximated Nearest Neighbors Search.Approximated near-
est neighbors (ANN) search has broad applications. In the "plaintext
world", many studies aim to enhance search efficiency while main-
taining high accuracy. Including(1) graph-based[22, 37, 38, 45], (2)
tree-based[57], (3) quantization-based [28, 39, 59] and (4) hashing-
based [35, 54, 63]. Most of the algorithms employ the same strategy:
initially, they generate a set of candidate nearest neighbors, fol-
lowed by identifying the actual𝑘 nearest neighbors from within this
candidate set. The difference lies in their ways of generating candi-
date neighbors. Referring to the benchmark [6], the graph-based
algorithm usually performs better. It introduces a more complex
structure to organize the vectors. The complex structure brings a
big challenge for secure computation. The𝑘-means clustering based
algorithm may not be the optimal choice, but it is outperforming
in secure computation.
Secure ANNS under Two Non-colluding Servers.Servan-Schr-
eiber et al. [ 48] propose an efficient private 𝑘-NNs called Preco
in two non-colluding servers. In the two-server setting, it is well-
known that there exist many significantly more efficient protocols.
However, the assumption that two servers hold the same dataset
but do not collude with each other may be impractical in many real-
world scenarios. This protocol utilizes local sensitive hash (LSH)
to calculate the index of the approximated nearest subsets. Then
it used the distributed point function to retrieve a subset with all
the nearest points from all subsets. It can be free of comparison but
need to retrieve from a large number of subsets (i.e.𝑛= 245), which
ensures that each subset has only one point. In the single-server
setting, the cost in the retrieval process will become intolerable. In
addition, this scheme will leak part of the information about the
dataset. Song et al. [52] follow the Preco direction but retain the
comparison operations, which can reduce the number of subsets.
However, the comparison method in their scheme does not consider
network latency. They only show performance under a low-latency
network. What’s more, even using comparison after retrieving
subsets, the number of subsets is still too large (e.g. 𝑛= 225) for
single server setting.
Secure ANNS without Server Privacy.Some studies only fo-
cus on ensuring query privacy, without protecting the privacy of
the database on the server. Henzinger et al. [ 25] propose Tiptoe,
a system that allows clients to search over hundreds of millions
of documents, while revealing no information about their search
query to the search engine’s servers. Asi et al. [5] propose Wally
improving the performance of Tiptoe by relaxing the privacy notion
to differential privacy. This approach allows for the amortization of
server computation and communication costs across multiple client
requests. Both Tiptoe and Wally utilize clustering-based algorithms.
Given that the database is public, it can let the client locally save
and compute a mount of information to improve performance. Zhu
et al. [66] propose a graph-based ANNS scheme called Compass in
the setting where the client owns the database and outsources it to
the server in encrypted form. Zhou et al. [65] propose a graph-based
ANNS scheme called PACMANN in the setting where the database

3.1.4 Batch private information retrieval.Private information re-
trieval (PIR) is a family of protocols that enable a client to query
a server’s database db with a private index 𝑖, ensuring that the
client obtains db[𝑖] without revealing𝑖 to the server. Some works
have designed protocols using probabilistic batch codes (PBC) [2]
to allow a client to query a set of indices (𝐼={𝑖 1,𝑖 2,···,𝑖 𝐿}) simul-
taneously. It can amortize computation costs to greatly improve
efficiency compared to making𝐿separate queries indb.
Angel et al.[2] proposed an efficient PBC construction based on
cuckoo hashing. For a database of size𝑛, ifC makes𝐿 batch queries,
S can use a 3-way cuckoo hashing to encode the database into𝐵=
1.5𝐿 buckets. Each bucket can be viewed as a subset of the database,
with the total number of items across all buckets being 𝑀= 3𝑛.
ThenC sends one query in each bucket and then receives a total of
𝐵 responses. It can recover all results for arbitrary𝐿 queries with a
small failure probability (𝑝=2 −40). Each query on the server only
needs to search within a subset of a database, approximately2𝑛/𝐿
in size. It is important to note that each query traditionally requires
scanning the entire database with size 𝑛. Meanwhile, the client
needs to run𝐵 (>𝐿 ) queries, which might increase communication
overhead. However, in our scenario, getting more responses means
inputting additional points during the final top- 𝑘 computation,
which could potentially enhance the accuracy of the search results.
Despite a larger response size, server privacy could be enhanced
by converting responses to secret sharing, which we will explain
in Section 5.2.
3.2 ANNS based on Clustering
There have been many studies on Approximate Nearest Neigh-
bor Search (ANNS) aimed at improving search efficiency. These
studies can be broadly categorized into three types of approaches:
graph- or tree-based, locality-sensitive hashing (LSH) based, and
clustering-based. In plaintext settings, graph-based methods, such
as Hierarchical Navigable Small World (HNSW) graphs[38], typ-
ically deliver the best performance. However, HNSW is not well
suited for secure computation, due to its heavy reliance on hierar-
chical RAM operations, which cannot be executed in parallel. In
contrast, while clustering-based algorithms exhibit average per-
formance in plaintext settings, we observe that they are highly
efficient in secure computation environment, a finding also noted
inSANNS[11].
A typical workflow of clustering-based ANNS can be briefly
described as follows:
I. Partition the database into clusters based on similarity.
II. Select a subset of clusters whose centroids are closest to the
query point.
III. Retrieve the points belonging to the selected clusters.
IV. Search the top-𝑘 points closest to the query point from the
retrieved points.
The algorithm described above is particularly advantageous for
secure computation because it can significantly reduce the search

4 Technical Overview
4.1 Threat Model
Similarly to prior private ANNS works [4, 11], Panther provides se-
cure two-party computation against astatic semi-honestadversary
A. We consider a computationally bounded adversaryA, which
corrupts either the server or the client at the start of a protocol
execution and honestly follows the protocol specification. Semi-
honest security is suitable for many practical scenarios, such as
when both parties are willing to collaborate but cannot directly
share their data in plaintext due to legal restrictions. We describe
Panther under thehybrid model, where the subroutines are invoca-
tions of corresponding “ideal” functionalities. In this way, as long
as the ideal functionalities are securely instantiated, the full proto-
col reveals no information beyond the hyperparameters (e.g., the
number of clusters or the number of points in clusters) of the ideal
functionalities. This adheres to the sequential modular composition
theorem [10], and is the rule of thumb in designing MPC protocols.
Panther protects the privacy of both the client and the server.
The server learns nothing about the query or the result, while the
client learns nothing about the dataset beyond the ANNS result.
The protocol is designed such that it reveals nothing beyond the
output of the corresponding plaintext ANNS algorithm. While some
studies [29] have explored whether a database can be reconstructed
from ANNS query results, such attacks typically require access to a
large number of queries. In our work, we do not consider leakage
from the query results themselves. This assumption is reasonable,
as the server could charge the client per query, which naturally
limits the query rate and discourages adversarial querying.
4.2 Analysis of Prior Approaches and Insights
A key step in clustering-based ANNS involves retrieving points
belonging to the selected closest clusters (Step III in Section 3.2).
Performing this retrieval in MPC is a nontrivial task, as both the
identifiers of the points to retrieve and the retrieved results (i.e.,
the coordinates of the points) must remain in secret-shared form
to prevent extra leakage. This resembles a special oblivious read
problem. Indeed, SANNS employs the DORAM protocol named
Floram [17] to resolve the challenge.
However, Floram is inherently costly: according to [17], a single
oblivious query on a database of ten thousand entries requires
communication on the order of several megabytes. In the context
of secure ANNS, where we need to retrieve hundreds or thousands
of entries using such queries, such communication costs become
prohibitive.
First failed attempt.A natural idea is to consider whether recent
advancements in DORAM, such as DUORAM [55], could optimize

which is significantly more efficient than DORAM. Nevertheless, we
cannot directly apply PIR because it requires the client to know both
the query indices and query results in clear, while in secure ANNS
we require the query indices and query results to be secret-shared.

4.3 Design ofPanther
Our “shuffle-and-reveal” approach.To address the challenges
of secret-shared indices in batch PIR, we suggest utilizing the
shuffle-and-reveal paradigm, which has been studied in prior stud-
ies [3, 30, 44]3. We letS sample a random permutation to locally
shuffle the database before serving each query. This allows the shuf-
fled indices to be revealed toC, who can use them for subsequent
PIR. The revealed indices are just pseudorandom values and thus

5 Point Retrievals via Batch PIR
In this section, we demonstrate how to efficiently instantiate secure
point retrieval (Step 4-5 in Fig. 1) using PIR, which contributes the
most to our efficiency gains.
5.1 Choosing a Shuffle-friendly PIR Protocol
From a practical perspective, our goal is to ensure that the shuf-
fle operation does not significantly impact performance. Unfor-
tunately, for efficient PIR protocols with preprocessing such as
SimplePIR [26] and PIANO [64], they need a considerable amount
of offline hints stored on the client side, which need to be updated
accordingly with any database change. It is acceptable in their cases
due to the assumption that the database is less frequently updated.
However, in our scenario, we need to reshuffle the entire database
for each query, essentially making the “offline” cost an “online”
cost, completely undermining their performance advantages.
Other batch PIR protocols, such as PIRANA [ 33] and Batch-
PIR [42], demonstrate high efficiency but are not friendly to shuffle
operations, because both protocols encode multiple items into a
single polynomial in a SIMD manner, necessitating a complete re-
encoding of the polynomial if item positions are to be shuffled.
The SIMD encoding in homomorphic encryption could be time-
consuming, so we wish to avoid redoing such encoding process for
each query.
Consequently, an appropriate PIR protocol for our scheme must
facilitate both efficient shuffling and encoding without leaking ad-
ditional database information. Fortunately, there exists a line of
PIR protocols that do not need preprocessing, and allow direct co-
efficient encoding instead of SIMD encoding, such as SealPIR [2],
OnionPIR [41], and Spiral [40]. Although Spiral is recognized as
the state-of-the-art RLWE-based PIR protocol, its advantage lies in
the size of PIR results, which is not the bottleneck of our protocol
since we already have low communication costs. Under our context
of batch PIR, where the size of each bucket is approximately2 11,
we found that the earlier SealPIR protocol performs best. Keeping
our requirements in mind, we present a comprehensive compar-
ison of various PIR protocols in Table 3, and discuss necessary
customizations in the subsequent sections.
Item encoding.We encode the points of each cluster into coeffi-
cients of a single BFV plaintext polynomial. As a result, shuffling
the database is just modifying the index map, and does not require
any polynomial modification. Figure 2 provides a toy example. In
more detail, for each point vector ﬁ𝑝=(𝑝 1,𝑝 2,...,𝑝 𝑑), we encode
each element of the vector into one separate coefficient, while many
PIR protocols consider the data as a string and ignore its own struc-
tures. Separating each element is helpful for additive secret sharing,
as will be shown in Section 5.2. Within a single plaintext, we can
encode𝑚 points with𝑑 dimensions. Because𝑚×𝑑 is large enough
in our scenarios, this encoding method efficiently utilizes available
space. For larger datasets, if there are more points in each cluster,
we can encode them into multiple plaintext polynomials.

7.1 SupportingZ 2𝑘 Plaintext Domain in PIR
Common PIR schemes are based on homomorphic encryption, thus
their plaintext domain naturally works under a prime field. How-

is motivated by the observation that MPC protocols operate more
efficiently in the ring Z2𝑘 than in the prime field Z𝑝 (Table 2, [47]),

8.1 Implementation and Environment
We have fully implemented Panther in C++ using the SecretFlow7
and EMP-toolkit [58] libraries. The SPU library within SecretFlow
was employed to develop the secret-sharing-based comparison and
distance computation protocols. Additionally, we utilized the mpir
part in the SecretFlow PSI library to construct the PIR building block,
and the emp-sh2pc framework8 to implement the top-𝑘 selection
network using garbled circuit protocols. These components were
integrated to create a comprehensive end-to-end implementation,
which we subsequently evaluated in terms of performance. Our
code is available at https://github.com/AntCPLab/OpenPanther.git.
The experiments presented in this paper were conducted on
cloud instances equipped with 64 vCPU, operating at 2.80 GHz and
256 GB of RAM. Both the client and the server are running under
32 threads.
To simulate various network conditions, we adjusted the band-
width using the traffic control utility in Linux. Following theSANNS
network setting, we performed our benchmarks under two network
conditions: a Local Area Network (LAN) with a bandwidth of 4000
Mbps and a 1ms round-trip time (RTT), and a Wide Area Network
(WAN) with a bandwidth of 320 Mbps and a 74ms RTT.

8.5 Accuracy
Since Panther and SANNS have the same underlying plaintext rou-
tine, and share the same set of hyperparameters such as plaintext
bitwidth, number of bins in approximate top-𝑘, and shape of clus-
ters, we expect that the accuracy of Panther will be the same as
SANNS, which is determined by the plaintext clustering algorithm.
SANNS achieves 10-NN accuracy of 0.9 (9 of 10 points are correct
on average, Section 5.3 of [11]).
There are only two points that might lead to accuracy differ-
ence between Panther and SANNS. The first is the possibility of a
one-bit error in the H2A step of distance computation (Section 7.3).
Although the one-bit error occurs in the least significant bit and is
unlikely to affect the accuracy, we want to experimentally show the
results. However, SANNS did not provide enough details to repro-
duce the same experiment result in their paper; most importantly,
we do not have the plaintext clustering algorithm they used. As
a result, we choose the𝑘-means clustering algorithm in [18] and
use Panther with noise flooding instead of H2A (so that there are
no one-bit errors) to simulate SANNS. Table 10 shows its accuracy
comparison with Panther. Results indicate that H2A indeed does
not affect accuracy. Note that even we tried our best to tune the
hyperparameters, either aligned or not aligned to the settings de-
scribed in SANNS, the accuracy is still slightly below 0.9, which may
because the plaintext clustering algorithm in [18] is not optimized
for the ANNS task.
The second difference is that the batch queries in PIR naturally
return additional items due to the cuckoo hash method used. Specif-
ically, Panther returns50%more points in the point retrieval step.
These extra points will be fed into the top-𝑘 step so the size of the
final output does not change. It is likely that feeding more candidate
clusters to the top-𝑘 step could improve accuracy, but the benefi-
cial effect is unpredictable because the additional50%clusters are
picked at random. We choose to stay conservative and do not claim
the accuracy improvements.
9 Conclusion
In this paper, we propose an efficient private ANNS framework
Panther. It can significantly improve performance than the pre-
vious single-server ANNS framework. We design novel protocols
to retrieve points with efficient batch PIR instead of DORAM. We
propose a mixed-primitive top-𝑘 approach with optimized selection
network to enhance the top-𝑘 selection performance. We carefully
design optimized usage of homomorphic encryption. After evaluat-
ing the end-to-end implementation on datasets of different sizes,
Panther is superior to the previous work in both communication
cost and computation cost.
