A Scalable Content-Addressable Network
or “CAN” for short
Ratnasamy, Francis, Handley, Karp, Shenker

Claims
● scalable
– average routing path length: O(dn
1/d
)
– number of neighbors: O(d)
– nodes affected by join / leave: O(d)
● fault-tolerant
– replication
– redundant links
● self-organizing

Initial Design
● d-dimensional Cartesian coordinate space
– on a d-torus
– acts like a hashtable
● objects are (key,value) pairs
– a key of an object is mapped to the a point by a 
uniform hash function
● nodes own zones of the coordinate space
● nodes know their surrounding neighbors
– to support routing, joining, leaving
● nodes are self organizing
– decisions are dynamic and handled locally

Routing
● greedily forward 
messages to the 
neighbor with 
coordinates closest to 
the destination
● average path length is 
(d/4)(n
1/d
) hops 


Construction – Joining the Party
● Bootstrapping
– use special bootstrap nodes to get a partial list of nodes
● Finding a Zone
– choose a random point P
– send join message to P
● Joining the Routing
– learn neighbors from the current node at P
– inform neighbors with a periodic update message

Node Departure – Saying Goodbye
● Leaving Normally
– hand over zone to neighbor
– neigbor updates neighbor table and contents
● Crashing
– detected by neighbors
● lack of periodic update messages
– send takeover message
– take over crashed node's zone

Design Improvements
● Multi-dimensioned coordinate spaces
● Multiple coordinate spaces
● Better routing metrics
● Overloading coordinate zones
● Multiple hash functions
● Topologically-sensitive construction
● More uniform partitioning
● Caching and replication techniques

Multi-dimensioned Coordinate Spaces
● coordinate space not 
restricted by dimension
● increases number of 
neighbors


Multiple Coordinate Spaces
● coordinate spaces 
called “realities”
● nodes given a different 
zone in each reality
● uniform hash function 
remains constant
● contents of hashtable 
replicated at every 
reality
● routing can occur on 
any reality


Multiple Dimensions vs Multiple Realities
● both shorten paths
● adding dimensions 
shortens paths more 
than adding realities
● adding realities offers 
better data availability 
and fault-tolerance
● adding realities adds 
considerably more 
state per node


Better Routing Metrics
● consider RTT when routing messages
● continually measure RTT to each neighbor
● favor lower latency paths


Overloading Coordinate Zones
● peer nodes share the same zone
– up to MAXPEERS
● no additional neighbors
● join does not split zone until peers > MAXPEERS
● poll neighbors for peer with lowest RTT


Multiple Hash Functions
● apply multiple hashes 
on each object
– place at multiple points 
on the coordinate space
● search queries may be 
run in parallel
● search queries may 
instead go to closest 
copy


Topologically-sensitive Construction
● define m landmarks
● each node orders 
landmarks by RTT
● partition the coord 
space into m! equal 
sized portions
● each node joins 
network at point 
corresponding to 
ordering


More Uniform Partitioning
● split the largest 
neighbor zone at join
● assumes volume of 
node indicates storage 
and query load
● not sufficient for true 
load balancing
– hot spots


Caching and Replication Techniques
● maintain a cache of recently accessed keys
– may serve a request instead of forwarding
● request neighbors to replicate a popular key
– neighbors may still – with certain probability – forward 
requests
– copy has a time to live
