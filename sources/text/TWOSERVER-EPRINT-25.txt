in Sublinear Time and Quasilinear Space

Abstract
We build two-server private information retrieval (PIR) that achieves information-theoretic security
and strong double-efficiency guarantees. On a database of𝑛> 106 bits, the servers store a preprocessed
data structure of size1.5
√
log2𝑛⋅𝑛 bits and then answer each PIR query by probing12⋅𝑛0.82 bits in this
data structure. To our knowledge, this is the first information-theoretic PIR with any constant number
of servers that has quasilinear server storage𝑛1+𝑜(1) and polynomially sublinear server time𝑛1−Ω(1).
Our work builds on the PIR-with-preprocessing protocol of Beimel, Ishai, and Malkin (CRYPTO 2000).
The insight driving our improvement is a compact data structure for evaluating a multivariate polynomial
and its derivatives. Our data structure and PIR protocol leverage the fact that Hasse derivatives can
be efficiently computed on-the-fly by taking finite differences between the polynomial’s evaluations.
We further extend our techniques to improve the state-of-the-art in PIR with three or more servers,
building on recent work by Ghoshal, Li, Ma, Dai, and Shi (TCC 2025).
On an 11 GB database with 1-byte records, our two-server PIR encodes the database into a 1 TB data
structure—which is 4,500,000× smaller than that of prior two-server PIR-with-preprocessing schemes,
while maintaining the same communication and time per query. To answer a PIR query, the servers
fetch and send back 4.4 MB from this data structure, requiring 2,560 × fewer memory accesses than
linear-time PIR. The main limitation of our protocol is its large communication complexity, which we
show how to shrink to𝑛0.31⋅ poly(𝜆) using compact linearly homomorphic encryption.

1 Introduction
Every day, users fetch data from online databases and, in the process, reveal sensitive information—e.g.,
the websites they browse, the places they visit, and the friends they talk to—to untrusted servers and
services [Zve13]. Cryptography can eliminate this leakage: withprivate information retrieval (PIR), a user can
fetch a record from a remote database, while hiding which record was fetched from the servers hosting the
database [CGKS95,KO97]. PIR is at the core of systems for private web search [ASA+21,HDCGZ23,ABG+24],
private media consumption [GCM+16, MW22, AAAG23], metadata-private messaging [MOT+11, AS16,
CSM+20, HSW23, TWG24, KRAP25], private auditing [HHCG+23, HPW25, LHCG25, KCG21], private set
intersection [LLMT25], private e-commerce and advertising [Jue01, HOG11, BKMP12, GLM16, SSHD21,
ZMA22], private machine learning [LJX+24], and private storage [DFL+20, MVM25]. In recent years, PIR
has made the leap from theory to real-world deployment in Apple’s private caller-ID lookups [Art] and
Google’s Chromebook device enrollment [Yeo23].
More formally, a PIR protocol runs between a set of servers, who store an𝑛-bit database, and a user, who
holds an index𝑖∈{1,2,…,𝑛}. At the end of the protocol, the user learns the𝑖th bit of the database, while the
servers learn nothing about the index𝑖. Chor, Goldreich, Kushilevitz, and Sudan [CGKS95] showed that PIR
with information-theoretic privacy and𝑜(𝑛) communication is possible, when relying on a non-collusion
assumption between two (or more) servers. Kushilevitz and Ostrovsky [KO97] constructed PIR with𝑜(𝑛)
communication and a single server, by relaxing the privacy guarantee to be computational and relying
on cryptographic hardness. In both settings, the communication complexity of modern PIR is strikingly
small: it is subpolynomial in𝑛 with two servers [DG16,GKS25], or polylogarithmic in𝑛 with cryptographic
assumptions and either two servers [BGI16] or a single server [KO97, CMS99, GR05, Lip05, DGI+19].
However, the privacy guarantees afforded by PIR come at a steep computational cost. While a non-
private array lookup takes𝑂(1) time on a RAM machine, Beimel, Ishai, and Malkin [BIM00] proved that a
PIR-lookup requiresΩ(𝑛) server time, regardless of the number of PIR servers and regardless of whether
the scheme’s privacy is information-theoretic or computational. More precisely, the PIR servers must touch
every bit of the database when answering a query—otherwise, the server(s) would learn that the user is
not reading whichever locations they did not touch. This linear server time is a painful bottleneck on
databases that are many gigabytes in size and queried by millions of users, as in today’s search engines,
content-delivery platforms, and social networks [HDCGZ23, ABG+24, DCG23].
PIR with preprocessing. To circumvent this linear-time lower bound, Beimel, Ishai, and Malkin proposed
the PIR-with-preprocessing model, which lets the servers run a one-time preprocessing step to produce a
data structure that encodes the database [BIM00]. Then, the PIR servers use this data structure to answer
PIR queries from any number of users. 1 If each location in the data structure depends on many (or all)
bits of the database, the linear-server-time lower bound no longer applies: the servers could answer PIR
queries by probing a sublinear number of locations, running in𝑜(𝑛) time. Unlike other PIR models (e.g.,
offline/online PIR, detailed in Section 1.3), the PIR-with-preprocessing model can achieve sublinear server
time even if each user makes a single query. If the database contents change, the servers must update their
data structure, but no additional communication with the users is needed.
Despite decades of study, few techniques to speed up PIR using preprocessing are known, and those
that exist offer limited improvements. All known PIR-with-preprocessing schemes either (1) save only
polylogarithmic factors in server time [WY05, Lip09, Lee25, CIMR25], (2) require a super-constant number
of non-colluding servers (i.e., growing with the database size) [LLF+25,GLM+25], or (3) encode the database
1This model has also been referred to as “unkeyed” doubly efficient PIR [LMW23, LMW25].

in a way that incurs large overheads in server storage. In the last category, on a database of size𝑛∈ ℕ, two
types of schemes exist:
• Information-theoretic schemes, which use a constant number of servers, require server storage𝑛1+Θ(1)
that is polynomially larger than the original database [BIM00, GLM+25]. The smaller the exponent
in this polynomial, the smaller the gains in server time. In concrete terms, with two servers and on
databases that are gigabytes in size, the servers would store a data structure that is 5 to 8 orders of
magnitude larger than the original database (cf. Table 1).
• Computational schemes, which use a single server, offer quasilinear server storage 𝑛1+𝑜(1) and
subpolynomial server time𝑛𝑜(1) [BIPW17, CHR17, LMW23]. However, these asymptotics come with
prohibitive constants and factors of the security parameter: the PIR schemes either use idealized
program obfuscation [BIPW17, CHR17] or directly work with a cryptographic assumption [LMW23]
in a way that, on a 370 MB database, would take 128 million core-years to build the data structure and
3 core-weeks to answer a PIR query, whereas linear-time PIR takes 0.03 core-seconds [OPPW24].
In all cases, PIR schemes with preprocessing have never been shown to run concretely faster than linear-time
PIR, on any practically relevant database size.
This paper takes another step towards speeding up PIR using preprocessing. We introduce the first
information-theoretically private PIR-with-preprocessing scheme with any constant number of servers (in
our case, two) that offers quasilinear server storage𝑛1+𝑜(1) and polynomially sublinear server time𝑛1−Ω(1).
Concretely, on databases that are gigabytes in size, our scheme encodes the database into a data structure
that is four to six orders of magnitude smaller than that of prior information-theoretic, two-server PIR
with preprocessing [BIM00, GLM+25]—while matching their communication cost and their server work per
query. A preliminary implementation shows that our PIR servers can answer queries at higher throughput
than the fastest two-server, linear-time PIR, though our scheme requires more storage and incurs larger
communication costs.

Extending to more servers. In Sections 4 and 5, we extend our techniques to work with three or more
servers. In our schemes, the number of servers is a constant—i.e., it does not grow with the size of the
database—and so our schemes support databases of any size. Our schemes strictly improve on known
PIR-with-preprocessing protocols with a constant number of servers [BIM00, GLM+25]. Much like in the
two-server case, specific parameterizations of our schemes offer quasilinear storage and polynomially
sublinear server time: with𝑠≥2 servers, the time is𝑛𝛼(𝑠) for𝛼(𝑠)=0 .5+1/log 𝑠+𝑜(1/log𝑠). As in prior
work [BIM00, GLM+25], our schemes adapt to the setting where a bounded number of servers may collude.
Concrete efficiency. In Section 6, we give concrete costs of our information-theoretic, two-server PIR with
preprocessing. On an 11 GB database with 1-byte records, our servers encode the database into a 1 TB data
structure—which is 4,500,000× smaller than the encoding produced by prior two-server schemes [BIM00,
GLM+25], while achieving the same communication and time per query.
To answer a PIR query to this 11 GB database, the servers in our scheme fetch and send back 4.4 MB from
their preprocessed data structure. That is, relative to the fastest two-server, linear-time PIR (with square-root
communication) [CGKS95], our scheme blows up the storage by 93× and blows up the communication by
37×, while decreasing the number of memory accesses per query by 2,560×. A preliminary implementation,
running on a large AWS instance, shows that this translates to9× higher server throughput (i.e., queries
answered per second, including network costs).
As mentioned above, the communication in our scheme could be significantly reduced using homomor-
phic encryption, without increasing the number of memory accesses (or the asymptotic server work) per
query. We leave evaluating and optimizing the concrete efficiency of this direction to future work.
Abstract view of our techniques. Finally, we sketch our approach before diving into more detail in
Section 1.2. All prior information-theoretic PIR-with-preprocessing schemes (with a constant number of
servers and with server time𝑛1−Ω(1)) follow a strategy of Beimel, Ishai, and Malkin [BIM00,WY05,GLM+25]:
(1) build an “imbalanced” PIR scheme where the queries are extremely short, namely 𝑐⋅log𝑛 bits for
a constant𝑐, and (2) have each server precompute a lookup table that stores the answer to each of the
2𝑐⋅log𝑛 =𝑛𝑐 possible queries. To answer a PIR query, the servers make one RAM lookup to the corresponding
location in the table; letting𝓁 be the bit length of the servers’ answers in the “imbalanced” PIR, this requires
𝑂(𝑛𝑐⋅𝓁) storage and𝑂(𝓁) time per query.
Our new PIR deviates from this template: we show how to eliminate a large amount of redundancy in
the lookup table produced by prior PIR schemes. We design a new data structure in which, to answer a PIR
query, our servers now probe𝑂(𝓁) query-dependent locations, each of constant bit length (instead of one
location of bit length𝓁). As a result, the PIR servers again answer queries in𝑂(𝓁) time on a RAM machine,
but they hold a much leaner data structure to encode the database. This improves the tradeoff between
storage and time, shown in Fig. 1, and allows forquasilinear storage while running in polynomially-sublinear
time. In addition, in the case of three or more servers, we describe a new family of imbalanced PIR schemes
that improves the final construction.
Our space-efficient data structure has implications beyond PIR with preprocessing. First, it gives new
and improved constructions of information-theoretic homomorphic secret sharing with preprocessing
(Remark 3.6) [ILM21]. Second, Section 3.4 shows that our data structure can be viewed as a new type of
locally decodable code with a relaxed smoothness property, which we call “batch smoothness. ” A batch-
smooth locally decodable code is parameterized by a number of batches 𝑏 ∈ ℕ; decoding the𝑖th location of
a message works by querying𝑏 batches of symbols in the codeword. The smoothness guarantee is that the
marginal distribution of each of these𝑏 batches of symbols is independent of the index𝑖. To our knowledge,
our result gives the first batch-smooth locally decodable code with constant alphabet size, constant number
4

of batches, quasilinear codeword length, and polynomially sublinear number of queries.

1.3 Related Work
Chor, Goldreich, Kushilevitz, and Sudan first defined and constructed private information retrieval [CGKS95].
Since then, a sequence of works improved the communication complexity of PIR in the information-
theoretic [Amb97,CG97,BI01,BIKR02,Yek08,Efr12,DG16,ABL24,GKS25] and computational settings [KO97,
CMS99, Cha04, Lip05, GR05, GI14, BGI15, BGI16, GH19, DGI+19]. At the same time, a second metric emerged
as a point of concern for PIR: the server time per query, which Beimel, Ishai, and Malkin proved must be
linear in the database size 𝑛 [BIM00]. In light of this bound, a line of work sought to make linear-time
PIR as concretely fast as possible [AMBFK16, ACLS18, AYA+21, GH19, MCR21, ALP+21a, MW22, HHCG+23,
DPC23, ZPZS24, LMRSW24, HDCGZ23, MW24, BMW24].
Circumventing the linear-time lower bound. In addition, a number of new PIR models aimed to
circumvent the linear-server-time lower bound altogether. The batch PIR model, introduced by Ishai,
Kushilevitz, Ostrovsky, and Sahai [IKOS04], lets each user read a batch of𝑄 database bits at once. In this
model, the PIR server(s) can run in amortized sublinear time𝑛/𝑄 per query. However, all𝑄 queries must
be made by the same user, at the same time [IKOS04, LG15, AS16, Hen16].
The shuffle PIR model, also introduced by Ishai, Kushilevitz, Ostrovsky, and Sahai [IKOS06, IKLM24],
shows that the PIR server(s) can run in amortized sublinear time if many users interact with the server(s)
at once, anonymously. A limitation of these schemes is that their privacy hinges on the assumption that
sufficiently many honest users make queries at the same time to mask each other’s requests.
The offline/online PIR model, introduced by Patel, Persiano, and Yeo [PPY18] and Corrigan-Gibbs and
Kogan [CGK20], lets each user store private, randomized, and database-dependent state. By having each
user make a sequence of𝑄 adaptively-chosen PIR queries while maintaining this local state, the server(s)
again run in amortized time𝑛/𝑄 per query [PPY18,CGK20,KCG21,SACM21,CGHK22,LP23,ZLTS23,GZS24,
ISW24, RMS24, ZPZS24, DDLO25, HPPY25, WR25]. At the same time, these schemes require every user to
8

make many queries for the amortization to kick in, and they necessitate communication with each user to
update its local state should the database contents change.
Very recent work [LLF+25, CIMR25] proposes a new PIR model where the servers may interact with
each other in a multi-round protocol to answer each query, though the schemes’ privacy still relies on
non-collusion. In this setting, Lazaretti et al. [LLF +25] show that three non-colluding servers can use
distributed oblivious RAM [FOSZ23] to answer PIR queries in𝑛1+𝑜(1) server storage, polylog(𝑛) server time,
andΩ(log𝑛) rounds of server-server interaction per query. In contrast, all other models do not require the
servers to interact to answer each PIR query.
Finally, the PIR with preprocessing model, introduced by Beimel, Ishai, and Malkin [BIM00], lets the
PIR server(s) store additional, database-dependent state. In this model, the server(s) perform a one-time,
client-independent preprocessing of the database to produce a data structure that they use to answer PIR
queries. Sublinear server time is possible even if each PIR user makes only one query. If the database
contents change, the server(s) must update their data structure, but no additional communication with the
stateless PIR users is needed.
PIR with preprocessing. In the information-theoretic setting, with a constant number of non-colluding
servers𝑠≥2, Beimel, Ishai, and Malkin [BIM00] and Ghoshal, Li, Ma, Dai, and Shi [GLM+25] build PIR with
preprocessing with𝑂(𝑛(1+𝜖)/𝑠) server time and poly(𝑛) server storage4 for any𝜖> 0. When the number of
servers𝑠 grows logarithmically in𝑛, Lazzaretti et al. [LLF+25] bring the server time down to𝑛𝑜(1) with
server storage𝑛1+𝑜(1). Ghoshal et al. [GLM+25] generalize this to work with any number of servers𝑠=𝜔(1)
that grows with the database size. In contrast, our schemes work in the constant-server regime; they strictly
improve on those of Beimel et al. [BIM00] and Ghoshal et al. [GLM+25] for any number of servers𝑠≥2.
In the computational-privacy setting, the PIR-with-preprocessing candidates of Boyle, Pass, Ishai, and
Wootters [BIPW17] and Canetti, Holmgren, and Richelson [CHR17] require virtual black-box obfuscation
and new code-based assumptions. Lin, Mook, and Wichs [LMW23] show that single-server PIR-with-
preprocessing is possible under the ring learning-with-errors assumption, achieving𝑛1+𝑜(1) server storage
and𝑛𝑜(1) server time. However, concrete estimates [OPPW24] expect these PIR schemes to be tens of orders
of magnitude slower than their linear-time counterparts. In contrast, Section 6 shows that our two-server
PIR runs an order of magnitude faster than linear-time PIR on gigabyte-size databases.
As in prior work, our results combine with generic re-balancing [CGKS95, GLM+25] to improve their
communication at the expense of storage or computation.
Lower bounds. Finally, Beimel, Ishai, and Malkin [BIM00] prove that, in any PIR-with-preprocessing
scheme with a constant number of servers, if the servers store 𝑏 ≥ 1 extra bits of information beyond
the database, they must answer PIR queries in Ω(𝑛/𝑏) time [BIM00]. Persiano and Yeo strengthen this
bound to show that, in the single-server setting with 𝑏 = Ω(log𝑛) extra bits, the server must run in
Ω(𝑛log𝑛/𝑏) time [PY22]. Our new upper bounds are far from these lower bounds, leaving open the
question of constructing—or ruling out—better information-theoretic PIR with preprocessing.

3 Two-Server PIR with Preprocessing
In this section, we describe a new two-server construction of PIR with preprocessing. We present the PIR
protocol in Fig. 3; its innovation is to perform reconstruction via finite differences.
In particular, compared to the protocols of Beimel, Ishai, and Malkin [BIM00] and Ghoshal, Li, Ma, Dai,
and Shi [GLM+25], our user constructs its PIR queries in the exact same way. However, in our scheme,
each server sends different PIR responses back to the user: rather than replying with the evaluations of the

database polynomial and its derivatives at the given query point, each server replies with the evaluations of
the database polynomial in a Hamming ball around the query point. The user then runs a new reconstruction
routine to recover the database bit read. With this technique, our scheme polynomially shrinks the server
storage compared to prior work, while maintaining the same server time.

3.3 Shrinking the Communication with Homomorphic Encryption
Next, we combine our new information-theoretic PIR scheme with standard cryptographic primitives to
reduce its communication cost.
Background: Homomorphic encryption. An encryption scheme is homomorphic [RAD78, Gen09] if it
supports computations on encrypted data. Linearly homomorphic encryption can compute all polynomial-
size linear functions on encrypted data. Fully homomorphic encryption can compute all polynomial-
size circuits on encrypted data. We follow standard definitions of symmetric-key linearly and fully ho-
momorphic encryption, which require the encryption scheme to be correct, semantically secure, and
strongly compact [Hal17]. We use Halevi’s notion of “multi-hop” homomorphic encryption [Hal17],
which has the property that evaluating a circuit with 𝐶 gates takes time𝐶⋅ poly(𝜆) on security param-
eter 𝜆. Classic linearly and fully homomorphic encryption schemes are strongly compact and multi-
hop [GM84, ElG85, Pai99, DJ01, Gen09, BV11, BGV12, FV12, GSW13].
Composing PIR with homomorphic encryption. To shrink the communication in the PIR scheme
from Fig. 3, we let the user send each server its original PIR query, along with an encryption of its secret
point 𝐩∈ 𝔽𝑚

then runs the user’s reconstruction under the hood of the encryption scheme. With linearly homomorphic
encryption, each server first writes the user’s reconstruction as a degree-two polynomial (in the secret
point 𝐩), which the server partially evaluates. Following an observation by [BIM04, Theorem 4.7], we can
further shrink communication by noticing that the user only needs to read some of the bits of each server’s

5 Many-Server PIR with Preprocessing
In this section, we describe new constructions of PIR with preprocessing for three or more servers. Our
schemes depart from prior work [BIM00, GLM+25] in two ways:
20

1. We observe that Hasse derivatives can be efficiently computed on-the-fly from the truth table of the
database polynomial𝑓DB by taking finite differences. In constrast, prior schemes require the servers
to store the truth table of𝑓DB and of each Hasse derivative [BIM00, GLM+25].
2. We take the individual degree𝑑 of the database polynomial𝑓DB to be a tunable constant larger than
one.
We provide a general, information-theoretic PIR-with-preprocessing framework that abstracts prior work
in Section 5.1. Then, using the two above techniques, we give concrete PIR schemes that instantiate this
framework: in Section 5.2, we present a construction that uses both techniques, tailored towards optimizing

towards optimizing the server time per query.

storage by 93×, our PIR scheme provides a 2,560× decrease in the number of memory accesses per query.
Since these memory accesses are RAM accesses to a large array (as opposed to a linear scan) and since the
communication is larger than in XOR PIR, this translates to9× higher server throughput than XOR PIR.
On a 2 GB database with 1-byte records, encoded into a 1 TB data structure, our servers answer a PIR
query by probing and sending back 0.7 MB from the data structure. That is, by blowing up the storage
by512×, our PIR scheme provides a 2,926× decrease in the number of memory accesses per query, which
translates to10× higher server throughput than XOR PIR.
When the ratio of parameters 𝐷/𝑚 is large (approaching 1/2), the storage overhead in our scheme
shrinks, but the communication overhead grows. Because of this large communication cost, our PIR servers
become bottlenecked by the rate at which they can send PIR answers over the network. As a result, when
the ratio𝐷/𝑚 is sufficiently close to 1/2, our schemes do not show a throughput gain (when including
network costs).
Communication. The main limitation of our PIR scheme is its communication. Our PIR is “imbalanced”: on
database size𝑛, the upload scales asΘ(log𝑛) and is concretely tens of bits, while the download scales as
Θ(𝑛𝜖) for a constant1/2<𝜖< 1 and is concretely megabytes to gigabytes(Table 2). In contrast, XOR PIR is
“balanced” and has communication4√𝑛. Concretely, this is one to three orders of magnitude smaller than
the communication of our scheme.
At the same time, as described in Section 3.3, the communication in our scheme could be dramati-
cally reduced using homomorphic encryption, without increasing the number of memory accesses (or the
asymptotic server work) per query. As shown in Table 2, in some settings, the server throughput of our
scheme without networking is substantially larger than that with networking, indicating that our scheme’s
end-to-end throughput is bottlenecked by networking costs. As a result, decreasing the communication
25

in our schemes could improve the server throughput further yet. We leave implementing and optimiz-
ing these communication-shrinking techniques for future work. In particular, we expect techniques for
speeding up homomorphic encryption in the context of linear-time PIR to be complementary with our
protocols [ALP+21b, MW22, HHCG+23, MW24, BMW24, LHCG25].
7 Conclusion
This paper presents information-theoretic PIR with preprocessing with quasilinear server storage and
polynomially sublinear server time, using two or more servers. We leave open the question of whether it is
possible to construct—or rule out—information-theoretic PIR with preprocessing achieving a better tradeoff
between storage and time. Towards this goal, we pose three concrete questions:
1. Does information-theoretic PIR with preprocessing with a constant number of servers, storage 𝑛1+𝑜(1),
and server time 𝑛1/2−Ω(1) exist? Our results with quasilinear storage achieve server time 𝑛1/2+𝜖
(Corollary D.11). In contrast, with poly(𝑛) storage, protocols with server time𝑛𝜖 are known [BIM00,
GLM+25].
2. Does information-theoretic PIR with preprocessing with a constant number of servers, server storage
poly(𝑛), server time𝑛1−Ω(1), and communication𝑛𝑜(1) exist? Our schemes only achieve these efficiencies
using computational hardness. At the same time, known information-theoretic PIR based on matching
vector codes provides subpolynomial communication [DG16], but not with double efficiency. The
key challenge with preprocessing these schemes is that they encode the database as a polynomial in
𝜔(log𝑛) variables, making it infeasible to store this polynomial’s truth table.
3. Harder yet, does information-theoretic PIR with preprocessing with a constant number of servers, server
storage poly(𝑛), and server time 𝑛𝑜(1) exist?
A related question is to design better data structures for fast evaluation of a multivariate polynomial𝑓
and its derivatives. One promising direction would be to interpolate between the two extremes studied
in this work: on the one hand, precomputing only the truth table of the polynomial𝑓 and computing its
derivatives on-the-fly via finite differences (Section 5.2); on the other hand, precomputing the full truth
table of𝑓 and of all partial derivatives needed (Section 5.3). For instance, it may be beneficial to precompute
only certain evaluations of the polynomial𝑓 and certain derivatives, while evaluating others on-the-fly.

First, we select appropriate data types: we store the preprocessed Table as a densely-packed array of
bytes. We represent each evaluation point in 𝔽𝑚
