controller

Congestion Control and Bandwidth Estimation
• Congestion control can be implemented at the QUIC layer (e.g., GCC, SCReAM, NADA)
• Congestion control for real-time media requires packet receive timestamp extension for QUIC
(draft-ietf-quic-receive-ts)
• The estimated total bandwidth of the QUIC connection will be shared by the application layer protocols
• Pacing at the QUIC layer limits the transmission speed of the connection

Scheduling and Prioritization
• Media encoders can be configured to produce data at the allocated rate
• Data Channels are not necessarily rate based (e.g., a file transmission)
• Prioritizing QUIC streams (or datagrams) that carry media
− ensures that media will be delivered at low latency
− since media is rate limited, it will not consume the whole bandwidth
− Data Channels dynamically yield or consume bandwidth when media over- or undershoots target
Mathis Engelbart (TUM) | QUIC as Multiplexing Layer in WebRTC 7

Conclusion

timestamp extension
• Multiplexing can solve unfairness issue between RTP and Data Channels
